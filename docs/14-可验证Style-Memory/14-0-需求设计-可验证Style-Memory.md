# 14-0 需求设计：可验证 Style Memory

## 0. 文档说明

**产品核心目标**：把参考图转化为可信、可编辑的视觉风格配方，并通过“参考图 → 证据 → 生成”帮助用户在改变内容时保留可迁移风格。

**本需求定位**：在 Iteration Memory 已经能够记录、解释和恢复每次生成尝试的基础上，将 Style Memory 从“带来源图的提示模板库”改造为“由用户确认、由结果佐证、可理解且可安全复用的风格规则资产”。

## 1. 需求分析与确认

### 1.1 项目背景

当前产品已经形成“分析参考图 → 查看风格证据 → 编辑变量与提示 → 生成结果 → 在 Iteration Memory 回溯和继续”的主链路，并允许用户把成功 Iteration 保存为 Style Memory。

真实界面审查表明，现有 Style Memory 的导航、列表、主操作、异常状态和恢复链路基本可用，但资产本身仍主要由来源图、名称、提示内容和变量数组成，存在以下问题：

1. 卡片标签和复用说明主要由名称、来源图与变量数推导，无法准确说明这条 Memory 保留了哪些可迁移风格。
2. 从成功 Iteration 保存时，生成结果没有成为可见的验证依据，用户无法判断这条 Memory 是否真的产出过满意结果。
3. 缺少统一详情与编辑入口，用户无法在复用前检查来源、风格规则、变量、排除约束和代表结果。
4. 使用 Memory 进入工作台后，来源身份消失，风格证据状态与生成准备状态可能互相矛盾，用户不知道恢复是否完整、还缺什么。
5. 可见信息与搜索范围不一致，删除边界不清楚，保存与删除对话框的键盘焦点没有正确限制在弹层内。

本期目标是：**让用户能够判断一条 Style Memory 为什么值得信任，确认它保留和允许变化的内容，并在不丢失来源身份的情况下安全复用。**

### 1.2 核心问题定义

| 问题 | 用户损失 |
| --- | --- |
| Memory 没有真实风格语义 | 用户只能凭名称和来源图猜测用途，难以比较、选择和长期复用 |
| 成功结果没有成为验证证据 | 用户无法区分“保存过的提示”与“已经证明有效的风格方向” |
| 缺少详情和资产治理能力 | 用户不能在复用前检查、编辑或理解一条 Memory，也无法判断修改与删除的影响 |
| 复用过渡缺少来源与准备说明 | 用户进入工作台后需要重新理解上下文，且可能因为状态矛盾而不信任系统 |
| 搜索、弹层和错误反馈不一致 | 用户找不到眼前可见的资产信息，键盘用户可能误操作背景内容 |

### 1.3 关键设计决策

| 决策维度 | 最终选择 | 核心理由 | 否决方案 |
| --- | --- | --- | --- |
| Style Memory 定义 | 用户确认的可复用风格规则，包含来源、保留规则、可替换内容和验证依据 | 与 Iteration Memory 的“执行记录”形成清晰分工，并兑现“证据先于信任” | 继续作为提示模板库；无法形成产品差异和长期资产价值 |
| 验证状态 | 只提供“待验证”和“用户已验证”两种状态 | 是否被用户认可才是可信边界，“曾经生成过”不等于验证成功 | 增加“已生成”中间状态；增加理解成本但没有表达用户认可 |
| 验证方式 | 用户明确选择一张已完成结果作为代表结果后，才能标记为“用户已验证” | 不把系统推测或一次生成完成冒充用户认可 | 保存成功 Iteration 时自动标记已验证；会制造虚假信任 |
| 旧 Memory 处理 | 继续可用并标记为“待验证”，用户可在详情中补充代表结果和风格规则 | 保留既有资产价值，同时不伪造过去没有记录的确认动作 | 自动推断为已验证；无法证明用户真实认可 |
| 列表信息层级 | 优先展示验证状态、代表结果或来源图、核心保留规则、变量数和最近使用 | 用户能快速判断可信度与复用价值 | 继续突出名称派生标签和大幅来源图；无法支持资产决策 |
| 详情职责 | 详情成为理解、编辑、验证、复用和删除前检查的统一入口 | 避免重要资产信息散落在菜单和工作台 | 只在卡片增加更多字段；信息密度过高且仍缺少治理空间 |
| 保存流程 | 先确认结果与保留规则，再定义可替换内容，最后命名保存；完整提示收进高级信息 | 让用户实际保存“风格记忆”，而不是先面对一大段提示文本 | 继续以提示全文为第一视觉焦点；认知负担高且偏离产品语义 |
| 工作区保存 | 没有代表结果时仍可保存，但状态必须是“待验证” | 允许用户保存有潜力的方向，同时保持验证口径诚实 | 禁止无结果保存；会切断草稿式创作和已有提示资产 |
| 复用方式 | 使用前提供轻量预检，进入工作台后持续显示 Memory 身份、保留规则和未完成变量 | 减少意外替换和重新理解成本，保持上下文连续 | 点击后直接跳转且隐藏来源；当前审查已证明会造成困惑 |
| 修改后的验证状态 | 修改核心保留规则或排除约束后回到“待验证”；仅改名称、说明或变量默认值不取消验证 | 验证只对被确认的风格规则成立，不应覆盖实质变化后的新方向 | 所有修改都保留验证；会让旧结果为新规则背书 |
| 复制语义 | 复制品继承可复用内容，但以“待验证”开始，原代表结果只作为来源参考 | 复制通常意味着新方向，不能沿用原资产的认可状态 | 完整继承“用户已验证”；无法证明复制后的方向仍有效 |
| 删除边界 | 只删除 Style Memory；来源参考图、Iteration 和生成结果继续保留，并在确认前明确说明 | 用户需要知道什么会失去、什么仍被保留 | 只强调“不可恢复”；无法解释关联资产影响 |
| 产品语言 | 主导航与页面统一使用“Style Memory”，来源类型降为详情信息 | 建立一个稳定的资产名称，避免 Library、模板和作品库混淆 | 继续混用 Library、Style Memory 和模板；心智分裂 |
| 自动审计 | 本期不判断结果是否自动保持风格，只记录用户确认的验证关系 | 先建立可信资产语义，避免引入新的黑盒评分 | 同期建设自动风格评分；扩大范围并削弱证据可信度 |

### 1.4 产品范围

**本期范围**

1. 统一 Style Memory 的产品定义、导航名称和验证状态。
2. 改造资产列表和卡片，展示真实验证状态、核心保留规则、代表结果或来源图、变量数与最近使用信息。
3. 搜索覆盖名称、真实风格规则、变量和可见来源信息；提供全部、用户已验证、待验证三种状态筛选。
4. 增加 Style Memory 详情，展示来源参考图、代表结果、来源 Iteration、风格指纹、保留规则、增强词、排除约束、可替换变量和使用情况。
5. 支持在详情中修改名称、说明、变量默认值、核心保留规则和排除约束，并按修改内容正确更新验证状态。
6. 重构从成功 Iteration 保存的流程，让用户确认代表结果、保留规则、可替换内容和名称。
7. 保留从工作区保存无代表结果方向的能力，并明确标记为待验证。
8. 支持用户从详情选择一个与该 Memory 相关的已完成 Iteration，将其结果设为或替换为代表结果。
9. 增加使用前预检，说明将保留、需要替换和可能覆盖的内容；进入工作台后持续显示当前 Memory 身份与缺失变量。
10. 统一工作台的风格证据、变量完整性和生成准备说明，所有区域对同一状态给出一致结论。
11. 完善查看、使用、编辑、复制和删除动作；复制品从待验证开始，删除前明确关联资产保留边界。
12. 完善加载、空态、无结果、未登录、部分来源缺失、保存冲突和服务不可用状态。
13. 修复保存、删除和复用预检弹层的键盘焦点、背景隔离、关闭后焦点恢复与错误提示时机。

**明确不做**

1. 不做自动风格保持评分、自动相似度总分或渲染后智能审计。
2. 不做多张代表结果、结果排名或作品集管理；首版每条 Memory 只保留一个代表结果。
3. 不做批量生成、批量编辑、批量删除、批量导入或批量导出。
4. 不做完整历史版本浏览、版本回滚或多人协作审批。
5. 不新增独立色卡、动作、构图或关键词资产库。
6. 不做浏览器插件、网页捕捉、外部素材库集成或分享发布。
7. 不做用户自定义标签体系；首版搜索基于 Memory 已有的真实内容。
8. 不建设自动推荐、智能排序或个性化首页。
9. 不改造图像生成模型选择、费用、额度或商业化体系。
10. 不进行移动端工作台重设计；继续保证基础重排和键盘可用性。

## 2. 用户旅程和用户故事

### 2.1 核心用户旅程

```text
主旅程：理解并复用一条可信 Style Memory

1. 用户从主导航进入 Style Memory。
2. 列表展示每条 Memory 的验证状态、代表结果或来源图、核心保留规则、变量数和最近使用信息。
3. 用户通过风格规则或变量搜索，并筛选“用户已验证”。
4. 用户打开一条详情，先看到来源参考图与代表结果，再查看保留规则、排除约束、可替换变量和来源 Iteration。
5. 用户点击“使用这条 Memory”。
6. 复用预检说明将保留哪些风格规则、哪些变量仍需填写，以及当前工作区是否会被替换。
7. 用户填写或修改主体、场景等关键变量，并确认进入工作区。
8. 工作区持续显示当前使用的 Memory、验证状态、已恢复规则和未完成变量。
9. 所有准备状态一致指出可生成或仍缺少的内容；系统不自动生成。
10. 用户主动生成，新 Iteration 与这条 Memory 保持可见关联。

沉淀旅程：从满意结果保存用户已验证的 Memory

1. 用户在已完成 Iteration 中选择“保存为 Style Memory”。
2. 保存流程并排展示参考图与本次结果，用户决定是否把结果设为代表结果。
3. 用户确认本次值得保留的核心风格规则与排除约束。
4. 用户确认下次可替换的变量及默认值。
5. 用户填写名称并保存；完整提示内容可在高级信息中检查，不占据第一视觉焦点。
6. 若用户选择了代表结果，Memory 标记为“用户已验证”；否则标记为“待验证”。
7. 用户打开新 Memory 详情，能够看到刚才确认的来源、规则、变量与验证状态。

草稿沉淀旅程：从无代表结果的工作区保存待验证 Memory

1. 用户在工作区完成了提示、保留规则和变量编辑，但尚未获得希望长期采用的结果。
2. 用户选择“保存为 Style Memory”。
3. 保存流程说明当前没有代表结果，本次将保存为“待验证”。
4. 用户确认核心保留规则、排除约束、可替换变量和默认值，并填写名称。
5. 用户完成保存，新 Memory 详情显示工作区来源、已确认内容和“待验证”状态，不展示虚构的代表结果。
6. 用户以后可以从相关的已完成 Iteration 选择代表结果，将该 Memory 转为“用户已验证”，草稿沉淀旅程完成。

治理旅程：检查、修改、复制或删除 Memory

1. 用户从卡片进入详情，而不是直接被迫进入工作台。
2. 用户修改名称、说明或变量默认值时，原验证状态保持。
3. 用户修改核心保留规则或排除约束时，页面说明原代表结果不再验证新规则，保存后状态变为“待验证”。
4. 用户复制 Memory 时，复制品保留可复用内容，但以“待验证”开始。
5. 用户删除前看到被删除对象和仍会保留的参考图、Iteration 与结果。
6. 用户取消删除时回到原详情，内容和状态保持不变，取消分支结束。
7. 用户确认删除时回到原列表，被删除 Memory 不再显示或可使用；其参考图、来源 Iteration 与生成结果仍可从原有入口查看，确认分支结束。

键盘操作旅程

1. 用户仅使用键盘从卡片打开更多操作菜单，再打开保存、复用预检或删除弹层。
2. 焦点进入当前菜单或弹层，用户按顺序访问其中的操作，背景内容不可被聚焦或触发。
3. 用户退出当前任务时，菜单或弹层关闭，焦点回到原触发位置，取消分支结束。
4. 用户再次打开同一任务并确认时，系统完成对应动作并将焦点移到结果页面的首要内容，确认分支结束。

异常旅程

1. 无 Memory 时，页面解释如何从工作区或完成 Iteration 创建第一条 Memory。
2. 搜索无结果时，保留查询与筛选并提供清除或切换筛选动作；可见内容必须与实际搜索范围一致。
3. 旧 Memory 缺少代表结果或部分风格证据时，详情标记为“待验证”并说明仍可检查和复用的内容。
4. 保存冲突或保存服务不可用时，保留用户已确认的名称、规则、变量和当前步骤；用户修改冲突内容或直接重试，成功后进入新 Memory 详情。
5. 列表或详情服务不可用时，保留搜索、筛选、列表位置和当前工作区；重试成功后回到原视图和原操作位置。
6. 未登录时，页面说明云端 Memory 需要登录，并保留进入前的查询条件与当前工作区；登录后回到原入口和原查询状态。
```

| # | 用户故事 |
| --- | --- |
| US-01 | 作为积累多个方向的创作者，我希望快速区分用户已验证和待验证的 Memory，以便优先选择真正得到满意结果的方向。 |
| US-02 | 作为谨慎复用风格的创作者，我希望查看参考图、代表结果和保留规则，以便理解这条 Memory 为什么值得信任。 |

| US-04 | 作为满意某次结果的创作者，我希望确认代表结果和保留规则后再保存，以便沉淀的是风格经验而不是一段提示文本。 |

| US-08 | 作为维护长期资产的创作者，我希望查看和修改 Memory，并清楚知道修改是否会影响验证状态。 |

卡片中的风格规则必须来自实际保存内容，不能根据名称猜测。用户已验证卡片以代表结果为主预览并明确标注参考图；待验证卡片只展示真实可用来源，不用示例结果暗示成功。

### 3.2 关键状态

| 状态 | 页面表现 | 用户下一步 |
| --- | --- | --- |
| 首次进入且无 Memory | 解释可以从工作区保存待验证方向，或从完成 Iteration 保存用户已验证方向 | 打开工作区或查看 Iterations |
| 列表加载 | 保持页面结构稳定，卡片位置显示加载状态，搜索和筛选暂不可操作 | 等待加载 |
| 用户已验证 | 展示代表结果、参考图标识、核心保留规则和使用信息 | 查看详情或使用 |
| 待验证 | 明确没有用户确认的代表结果，不使用成功语气 | 查看详情、直接使用或补充验证 |
| 搜索无结果 | 保留搜索词与状态筛选，说明实际搜索范围 | 清除搜索或切换状态 |
| 详情部分内容缺失 | 对缺少的参考图、规则或来源单独说明，其他内容继续可用 | 使用可用内容、编辑或返回列表 |
| 保存进行中 | 保留用户已确认的步骤内容，锁定重复提交 | 等待完成 |
| 保存冲突或失败 | 说明问题并保留名称、规则、变量和当前步骤 | 修改后重试或取消 |
| 核心规则被修改 | 保存前说明原代表结果不再验证新规则，状态将变为待验证 | 确认保存或取消修改 |
| 使用预检 | 展示保留规则、必填变量和工作区替换影响 | 填写变量、取消或确认进入 |
| 工作区变量未完成 | 显示具体缺失项，生成动作不可用且原因一致 | 补充缺失变量 |
| 工作区准备完成 | 当前 Memory 与已恢复规则仍可见，生成动作可用 | 主动生成 |
| 删除确认 | 明确删除对象、不可恢复内容与仍会保留的关联内容 | 取消或确认删除 |
| 未登录 | 说明云端 Memory 需要登录，当前工作区仍保留 | 登录或返回工作区 |
| 服务不可用 | 当前列表、详情或编辑内容尽量保持可见，说明受影响动作 | 重试或返回原页面 |

### 3.3 业务规则

1. **对象分工**：Iteration Memory 记录一次具体尝试；生成结果是一张具体作品；Style Memory 记录值得再次复用的风格规则。三者在界面中不得互相替代。
2. **状态定义**：“用户已验证”表示用户明确选择了一张真实完成结果作为代表结果；“待验证”表示 Memory 可复用，但没有用户确认的结果依据。
3. **状态表达**：验证状态必须同时使用文字和视觉标识，不能只用颜色表达。
4. **代表结果**：每条 Memory 首版最多有一个代表结果。系统不能因为存在完成结果而自动替用户选择。
5. **旧资产口径**：本期上线前已经存在、但没有明确用户确认记录的 Memory 显示为待验证，仍可正常查看和使用。
6. **卡片事实**：卡片风格规则必须来自实际保存内容；不得根据名称或主体词生成看似客观的风格标签。
7. **卡片预览**：用户已验证时优先展示代表结果，并清楚标记来源参考图；待验证时只展示真实来源图或缺失说明，不展示示例结果。
8. **搜索一致性**：用户在卡片和详情中可见的名称、保留规则、变量名称和来源说明均可被搜索；搜索提示不能承诺未覆盖的信息。
9. **状态筛选**：全部、用户已验证和待验证为互斥筛选；搜索与状态筛选可同时生效，返回列表后保持原条件和浏览位置。
10. **详情优先级**：详情首先展示参考图与代表结果、核心保留规则和可替换内容；完整提示属于高级信息，不占据首屏主要注意力。
11. **保存来源**：从完成 Iteration 保存时预填当次仍可用的参考、规则、排除约束和变量；缺失内容必须明确标记，不能用推测补齐。
12. **保存验证**：只有用户主动勾选“设为代表结果”并完成保存，Memory 才标记为用户已验证；用户可以取消选择并保存为待验证。
13. **工作区保存**：从尚未产生满意结果的工作区保存时，默认状态为待验证，并说明稍后可从相关完成 Iteration 补充代表结果。
14. **输入反馈**：名称等必填项在用户尝试继续或离开输入后才显示错误；首次打开时使用中性帮助文案。
15. **编辑影响**：修改名称、说明或变量默认值不改变验证状态；修改核心保留规则或排除约束时，保存前明确说明状态会变为待验证。
16. **重新验证**：待验证 Memory 可以从与其相关的已完成 Iteration 中选择代表结果，确认后转为用户已验证。
17. **替换代表结果**：用户已验证 Memory 可以选择新的相关完成结果作为代表结果；取消操作不改变原状态和原代表结果。
18. **复制行为**：复制品保留名称以外的可复用内容并提示用户重新命名，但状态始终从待验证开始；原代表结果只能作为来源参考。
19. **使用预检**：进入工作区前必须展示将保留的核心规则、需要填写的关键变量和当前工作区替换影响；取消后两边状态不变。
20. **工作区保护**：当前工作区为空、已经使用同一 Memory 或没有不同未完成内容时可直接确认进入；存在不同未完成内容时必须明确提醒。
21. **来源持续可见**：进入工作区后，当前 Memory 名称、验证状态、已恢复规则数量和缺失变量持续可见，直到用户主动移除、替换来源或开始完全独立的新方向。
22. **准备状态一致**：所有工作区状态说明必须基于同一份用户可见事实；若不能生成，必须列出具体缺失项，不能一处显示已检测到证据、另一处显示仍在等待证据。
23. **主动生成**：使用 Memory、补全变量或确认预检均不自动生成；用户必须主动提交，新结果形成独立 Iteration。
24. **使用关联**：从 Memory 主动生成的新 Iteration 在后续详情中显示来源 Memory；Memory 详情同步展示最近使用和派生 Iteration 数量。
25. **删除影响**：删除只移除 Memory 和可复用规则；来源参考图、来源 Iteration、代表结果与其他历史记录继续保留。取消后当前详情、查询和工作区不变。
26. **异常文案**：所有空态和错误状态依次说明发生了什么、哪些内容仍被保留、用户下一步可以做什么。
27. **弹层焦点**：保存、删除和复用预检打开后，键盘焦点进入弹层并只能在当前弹层内移动；关闭后回到触发操作。
28. **弹层关闭**：非破坏性弹层可通过关闭按钮、取消或退出键关闭；删除确认不得因为误点背景而执行或丢失上下文。
29. **操作目标**：更多操作、清除搜索和弹层关闭等图标按钮必须有可理解名称和舒适的点击区域。
30. **菜单语义**：更多操作打开后，键盘用户可以按顺序访问查看、编辑、复制和删除，并能退出后回到菜单触发位置。

## 4. 验收标准

- **AC-01：列表能够表达真实风格语义和验证状态**
  - 前置：用户拥有至少一条用户已验证 Memory 和一条待验证 Memory。
  - 动作：用户进入 Style Memory 列表，观察加载过程并等待列表就绪。
  - 结果：加载期间页面结构稳定且不显示虚假资产；就绪后每条卡片明确显示验证状态、真实代表结果或来源图、核心保留规则、变量数和最近使用信息；待验证资产不使用成功结果或名称派生标签暗示已验证。

- **AC-02：搜索、筛选和可见信息保持一致**
  - 前置：不同 Memory 的名称、保留规则、变量和来源信息存在差异。
  - 动作：用户分别搜索一条卡片上可见的风格规则、变量和来源，并切换用户已验证或待验证筛选，打开详情后返回。
  - 结果：搜索结果与页面可见事实一致；搜索和筛选可组合生效；无结果时保留条件并提供清除行动；返回列表后原条件和浏览位置保持。

- **AC-03：详情能够解释一条 Memory 为什么可信以及如何复用**
  - 前置：用户拥有一条来源参考图、来源 Iteration、保留规则、变量和代表结果均完整的用户已验证 Memory。
  - 动作：用户查看详情并展开高级信息。
  - 结果：页面清楚区分参考图、代表结果、来源 Iteration、风格指纹、核心保留规则、增强方向、排除约束、可替换变量和使用情况；完整提示仅在高级信息中展示，且所有验证信息与该代表结果一致。

- **AC-04：用户可以诚实地保存已验证或待验证 Memory**
  - 前置：分别存在一条有真实结果的完成 Iteration，以及一个尚无代表结果的工作区方向。
  - 动作：用户从完成 Iteration 依次确认代表结果、保留规则、变量和名称并保存，观察保存进行中状态；随后从无代表结果的工作区确认保留规则、排除约束、变量和名称并保存另一个方向。
  - 结果：保存进行中保留已确认内容并阻止重复保存；选择代表结果的 Memory 显示为用户已验证，并可在详情看到该结果与确认规则；从工作区保存的 Memory 显示为待验证，并可在详情看到工作区来源和已确认内容；两种流程都不会在用户尚未操作时提前显示必填错误。

- **AC-05：编辑、重新验证、替换代表结果和复制不会制造虚假验证状态**
  - 前置：用户拥有一条用户已验证 Memory、一个相关的新完成结果，以及一条待验证 Memory。
  - 动作：用户先只修改已验证 Memory 的名称或变量默认值，再修改核心保留规则并确认保存；随后创建复制品；接着为待验证 Memory 选择代表结果；最后在原已验证 Memory 中选择新代表结果，先取消一次，再重新选择并确认替换。
  - 结果：名称或变量默认值修改后保持用户已验证；核心规则修改前出现状态变化说明，确认保存后转为待验证；复制品以待验证开始；待验证 Memory 在用户明确选择代表结果后转为用户已验证；取消替换时原代表结果和状态不变，确认替换后详情展示新代表结果与对应验证依据。

- **AC-06：复用前后保持来源身份与一致的准备状态**
  - 前置：用户当前工作区存在不同的未完成内容，并选择一条含必填变量的 Memory。
  - 动作：用户点击使用，查看预检并在变量未完整时尝试继续；随后取消预检；再次打开预检，补全变量并确认进入工作区；最后主动生成一次新 Iteration。
  - 结果：变量未完整时预检列出具体缺失项且不能进入；取消后原 Memory 和当前工作区均保持不变；确认后工作区持续显示 Memory 名称、验证状态和恢复规则，所有状态区域一致显示准备完成且不会自动生成；用户主动生成后，新 Iteration 显示来源 Memory，Memory 详情的最近使用时间和派生 Iteration 数量相应更新。

- **AC-07：取消或确认删除都有明确且安全的终点**
  - 前置：用户打开一条关联了来源参考图、来源 Iteration 和代表结果的 Memory。
  - 动作：用户打开删除确认并先取消；随后再次打开删除确认并确认删除；最后分别查看列表和原来源 Iteration。
  - 结果：确认层明确说明 Memory 会被移除而关联内容仍保留；取消后原详情、查询和工作区不变；确认后返回列表，被删除 Memory 不再显示、不可打开或使用，而原来源参考图、来源 Iteration、代表结果和历史记录仍可查看。

- **AC-08：弹层与操作菜单支持连续键盘操作**
  - 前置：用户仅使用键盘打开保存、删除、复用预检和更多操作菜单。
  - 动作：用户使用前进、后退、退出和确认操作完成或取消任务。
  - 结果：焦点进入当前弹层或菜单并限制在当前任务范围内；背景控件不可被误操作；状态与错误不只依赖颜色；关闭后焦点回到原触发位置，图标操作均有可理解名称和舒适点击区域。

- **AC-09：旧资产和部分来源缺失时仍保持诚实可用**
  - 前置：分别存在一条没有明确用户确认记录的旧 Memory，以及一条缺少参考图、代表结果或部分风格证据的 Memory。
  - 动作：用户进入列表并依次打开两条详情。
  - 结果：旧 Memory 显示为待验证，不自动继承用户已验证状态；缺失内容在对应位置单独说明，其他来源、规则、变量和提示继续展示；两条 Memory 均可基于仍可用内容查看、编辑或进入复用预检。

- **AC-10：空列表、未登录和服务异常均可恢复到原上下文**
  - 前置：用户分别处于无 Memory、带搜索与筛选条件但登录失效、列表服务不可用和单条详情暂不可用状态，且当前工作区已有内容。
  - 动作：用户在空列表选择创建入口；在登录失效状态完成登录；在列表和详情错误状态执行重试。
  - 结果：空列表明确提供从工作区或完成 Iteration 创建第一条 Memory 的入口；登录后返回原入口并恢复原查询条件；列表重试成功后恢复原筛选和浏览位置；详情重试期间列表保持可用，成功后重新显示原详情；所有分支均保留当前工作区。

- **AC-11：保存冲突或暂时失败后可以无损重试**
  - 前置：用户已经在保存流程中确认名称、保留规则、排除约束和变量。
  - 动作：用户确认保存后遇到名称冲突或服务暂不可用，检查当前内容，修改冲突名称或直接重试，并最终保存成功。
  - 结果：失败状态说明原因和下一步，保留当前步骤及全部已确认内容，不产生重复 Memory；重试成功后进入新 Memory 详情，展示的来源、规则、变量和验证状态与用户最后一次确认一致。
