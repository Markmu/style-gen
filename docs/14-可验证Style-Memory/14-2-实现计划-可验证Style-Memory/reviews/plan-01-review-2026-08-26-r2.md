## B1 修复复验（本轮焦点）

### 1. 实现顺序核对

`src/lib/style-memory-rules.ts:9-14`：

```ts
return [...rules]
  .map((rule) => rule.trim())
  .filter((rule) => rule.length > 0)
  .sort((a, b) => (a < b ? -1 : a > b ? 1 : 0));
```

- 顺序为 **map(trim) → filter(非空) → sort(字典序)**，与架构 §6.4「逐元素 trim → 排序」及计划实现规格 §4 一致；第一轮记录的「先按原始串排序、后 trim/过滤」已消除。
- `ruleSetsChanged` 归一化后长度比较 + 逐元素比较的实现未随修复改动，语义不受影响。
- 修复方向正确性：排序以 trim 后的串为输入，前导空白不再参与排序，第一轮实证的「顺序翻转导致元素错位比较」机理被消除。

### 2. 新增 3 用例核对（对齐规格，非放松）

`src/lib/__tests__/style-memory-rules.test.ts`（13 → 16 用例），逐一对应第一轮 B1 实证反例：

| # | 用例 | 断言 | 对应 B1 反例 |
| --- | --- | --- | --- |
| 1 | `normalizeRuleArray` 前导空白不参与排序（trim 先于排序） | `[" soft light", "golden hour"]` → `["golden hour", "soft light"]` | 前导空白使元素在排序中提前 |
| 2 | `ruleSetsChanged` 纯前导空白差异返回 false（多元素不回退） | `[" soft light", "golden hour"]` vs `["soft light", "golden hour"]` → `false` | B1 实证反例 1（修复前误判 true） |
| 3 | `ruleSetsChanged` 前导空白参与排序的等价集合返回 false（trim 后改序不回退） | `[" b", "a"]` vs `["a", "b"]` → `false`；另附 `["golden hour", " soft light"]` 变体 | B1 实证反例 2（修复前误判 true） |

三个用例全部是严格等值/布尔断言（`toEqual` / `toBe`），期望值锚定规格语义输出，不含任何放宽（无 `toBeTruthy` 弱化、无跳过）。

### 3. 既有断言纠正核对（1 处，向规格对齐而非放松）

既有用例「逐元素 trim 并过滤空串」期望修正为 `["low key", "rim light"]`。独立复算验证：

- 输入 `["  rim light  ", "", "   ", "low key"]`。
- 修复前（先按原始串排序，空格 0x20 < 字母）：排序为 `["", "   ", "  rim light  ", "low key"]`，trim/过滤后产出 `["rim light", "low key"]` —— 原期望锚定的正是该错误实现的输出顺序。
- 规格顺序（trim → 过滤 → 字典序）：`["rim light", "low key"]` 排序为 `["low key", "rim light"]`（"low key" < "rim light"）—— 与修正后期望一致。

判定：该纠正使期望从「错误实现的输出」改为「规格声明的输出」，仍为全量 `toEqual` 断言，属对齐规格，不构成放松。第一轮报告「现有用例在两种顺序下结果一致」的预测对该用例不成立，此点已在 green 证据「断言纠正说明」中如实记录，处理透明。
