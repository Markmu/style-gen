## 6. 维度 9：代码审查

**阻塞项：无。**（无正确性错误、安全隐患、数据损坏风险或阻断下游功能的契约错误）

重点核查结论：

- dirty confirm 的 pending 动作与值同存 `pendingApplyRef`，避免闭包旧 props；取消路径不触碰任何 Prompt state（零写入语义成立）。
- 手动全文 dirty 标记覆盖两条路径：V2 受控 text（写 `customPrompt` + `outputMode=custom`）与旧全文路径（编辑器持有文本，仅上抛标记）；`finalPromptText` 对 dirty/custom 的优先级一致，无双写歧义。
- `clearCustomPromptAfterSwitch` 清 dirty 后回到编译结果，`customPrompt` 置空不残留；切换后再次手动改写可重新置 dirty（TC-4.6 后半段覆盖）。
- 画幅写点全部经 `resolveAspectRatio` 或白名单 select，`ws.generationParams.aspectRatio` 不存在未清洗写入路径；未知值清洗后来源记 fallback 不冒充推荐。
- 摘要定位 keep→`setLocatedInvariantId`（RecipeCard 展开可键盘到达）、change→切 variables 视图 + `requestAnimationFrame` 聚焦目标输入，均不发起请求、不改 Prompt 数据。

**建议项（非阻塞）：**

- **S-1（一致性/可访问性）**：`prompt-switch-confirm-dialog` 为自建轻量对话框（聚焦 Cancel、取消回焦触发控件，交互契约已由测试锁定），但未复用既有 `src/components/ui/modal-dialog.tsx` 原语（该原语提供 focus trap / Escape 关闭 / 焦点还原，style-memory 系列对话框均在用）。当前实现无 Escape 关闭与焦点圈闭（Tab 可移出对话框）。建议后续统一迁移或为该对话框补 Escape=cancel。
- **S-2（可维护性）**：`handleKeepChangeLocate` 的 change 分支用 `document.querySelector('input[aria-label="..."]')` + `CSS.escape` 查找目标输入，跨组件 DOM 查询依赖 label 唯一性。plan-05 接入调整回路（`highlightedTargetId`/`announcement` 已在组件与 PromptCard props 预留但页面当前传 null）时建议改为 ref 注册定位，消除脆弱性。
- **S-3（测试基建）**：`e2e/style-memory-reuse.spec.ts` 的 `WORKSPACE_STORAGE_VERSION` 沿用字面量惯例（现为 5），下次工作台快照再升版时该 seed 会再次静默失效。注释已说明来源；可考虑后续由测试 setup 注入真实常量。
