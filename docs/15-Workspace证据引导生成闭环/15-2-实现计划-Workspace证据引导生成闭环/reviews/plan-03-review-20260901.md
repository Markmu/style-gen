## 4. 维度 4：实现规格符合度（代码逐项核对）

- **§1 Schema 与迁移**：`prompt_control_snapshot jsonb NULL`，不回填、无新表/方向实体/版本表；0006 SQL/meta/journal 审查见 §6。
- **§2 Repository 契约**：create/read/detail 均透传 `PromptControlSnapshot | null`，旧记录 null 且不改写 `promptSnapshot`（`rowToGenerationTask`/`findIterationDetail` 显式 `?? null`）；`getDirectionIterationFeed(userId, analysisTaskId, pageSize=5)` 为三个有界 select（completed `limit size`、pending/processing `inArray limit 1`、failed `limit 1`），全部 `orderBy(desc(createdAt), desc(id))` 并强制 `userId + analysisTaskId`，`Promise.all` 数据库层并发而非内存混合分组；DTO 含 `resultAssetId`/真实 URL/截断 200 的 `errorMessage`。
- **§3 Generation API**：`GET ?view=direction` 为白名单枚举（未知值 400 不静默回退）、缺 `analysisTaskId` 400、`pageSize` 仅 1-5 整数不 clamp、`direction_iterations_queried` 含 duration/completedCount/hasActive/hasLatestFailure；未带 view 保持既有 status/cursor/q 契约。POST：`promptControlSnapshot` 形状/枚举/上限（20 变量/10 adjustments/单值 200/customTemplate 6000）校验先于分析任务读取，Recipe 引用校验（invariant ⊆ `styleInvariants`、变量键 ⊆ `contentVariables` 回退 `analysisTemplateVariables`）在其后；`params.aspectRatio` 走 plan-01 `isSupportedAspectRatio` 白名单；trigger 取自快照缺省 `manual`；Provider 启动/提交置于显式 try/catch，best-effort 回写 failed（截断摘要）→ 返回 500 `SERVICE_UNAVAILABLE` retryable，终态写入失败输出 `generation_failed_status_write_failed`（taskId/analysisTaskId/provider，无 Prompt 全文）；同步超时 `SYNC_GENERATION_TIMEOUT_MS = 120_000`、Replicate `startTimeoutTimer(..., 300_000)` 字面量锁定；重试创建新 task（POST 无幂等复用）。
- **§4 已有 Asset 分析**：判别联合（`sourceAssetId` 存在即 existing_asset 模式，混入 `assetId/fileUrl/width/height/mimeType` 任一 400）；`findAssetByIdForUser` 未命中统一 404 不泄露存在性；非图片 MIME 400 防御；服务端派生 URL/MIME 交给 Vision Provider，不 upsert、不复制、不改 type；上传模式保持既有 upsert 且不触发 `findAssetByIdForUser`。
- **§5 安全与可观测性**：全部查询强制 userId；错误文本输出前截断（route 侧 `truncateForOutput` 200 与 feed 一致）；结构化事件 `analysis_existing_asset_started`、`direction_iterations_queried`、`generation_request_received`（trigger）、`prompt_control_snapshot_rejected`（stage 区分 shape/recipe_references）、`generation_provider_start_failed`、critical `generation_failed_status_write_failed` 全部落地且不记录 Prompt 全文/凭据。

## 6. 重点披露③④：迁移与性能证据文档复核

- **迁移审查（复核通过）**：`drizzle/0006_pale_darkhawk.sql` 仅一行 `ALTER TABLE "generation_tasks" ADD COLUMN "prompt_control_snapshot" jsonb;`（无 NOT NULL 即 nullable）；`0006_snapshot.json` 与 0005 的规范化 diff 仅 `public.generation_tasks` 新增该列（`primaryKey: false, notNull: false`）；`_journal.json` 追加 idx 6 且 `0006.prevId = 0005.id` 链一致；`src/lib/db/schema.ts` 字段与迁移对应。**无 destructive SQL、无回填、无新表/索引**，满足验收标准最后一条与全局护栏 6。
- **性能验收（复核通过）**：implement 证据自洽——种子 500 rows = 480 completed + 6 pending + 6 processing + 8 failed（completed 各带结果资产）；三查询合计 50 次采样 avg 0.415ms / max 3.365ms / **p95 0.389ms ≤ 300ms**；EXPLAIN (ANALYZE, BUFFERS) 声称 active 查询命中 `idx_generation_tasks_status`（该部分索引在 `src/lib/db/schema.ts` 真实存在），completed/failed 为 top-N heapsort + hash left join（与 `leftJoin(assets)` 形态一致）；按「超目标才评估复合索引」护栏未新增索引，符合验收标准。种子数据清理已记录。
