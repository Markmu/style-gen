## 四、问题汇总与修复建议

### ARCH-FINAL-01（中 / ⚠️）：快速复刻的默认控制与确认内容未被架构锁定

**需求基准**

- PRD §3.3 BR-04：自动提交必须使用“贴近复刻、平衡表达、参考图推荐画幅和当前默认生成设置”，并在确认时提前说明。
- PRD §3.3 BR-09：平衡是分析完成后的默认表达程度。
- PRD AC-01：快速确认时必须说明将采用的意图、表达程度、画幅推荐和生成设置。

**当前架构证据与差距**

- 架构文档 §3.1-1、§6.1-1 只明确了 `creationPace=analyze_edit`、`quickAuthorization=none/armed` 及“确认会自动生成一张”。
- §6.1 没有定义新方向 Prompt controls 必须初始化为 `intent=reconstruction` 和 `detailLevel=standard`，也没有定义快速确认面板必须展示这些值、已派生的画幅来源与当前生成设置。
- §7.2 只对 v4 无法识别字段的迁移 fallback 写了 `same_style / standard / variables`，这不能代替新方向的快速默认，而且 `same_style` 与快速复刻要求的 `reconstruction` 不同。

**影响**

实现者可能合法地按架构选择 `same_style`、`concise/professional` 或仅显示“会自动生成一张”，从而让快速路径的生成语义或成本确认与 PRD 发生静默偏移。

**修复建议**

1. 在 §3.1 / §6.1 定义新方向 Prompt controls 的确定性初始值，至少锁定 `reconstruction + standard`；快速确认应在参考图选择前说明之后将根据完成分析派生推荐画幅。
2. 在 §6.1 定义“确认时快照”：自动提交必须使用已向用户披露的 `reconstruction + standard + reference/fallback aspect ratio + current default generationParams`；若确认后再允许编辑，需明确自动提交是读确认快照还是读最新值，避免竞态。
3. 在 §2.4 AC-01 承接矩阵、§7.2 Schema 或工作区初始化契约、Phase A/C 测试中增加断言：快速确认显示四类设置，最终 task 快照与披露值一致。
