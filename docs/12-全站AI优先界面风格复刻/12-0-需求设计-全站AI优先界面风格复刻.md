# 12-0 需求设计：全站 AI 优先界面风格复刻

## 0. 文档说明

**产品核心目标**：将 Visoryn 升级为 AI 优先的视觉风格工作台，让用户在参考图、风格理解、提示编辑、生成结果和风格记忆之间获得连续、可解释、可复用的创作体验。

**本需求定位**：在全站 Precision Glass 视觉改造和 Workspace 三栏工作台基础上，本期以已选中的 Evidence Copilot Workbench 视觉方向为目标，先统一设计规范，再完成工作台高保真风格复刻，最后迁移风格记忆库、首页和全站状态体验。

**相关文档**：

- AI-first Redesign Brief
- 全站交互与 UI 样式改造

## 1. 需求分析与确认

### 1.1 项目背景

**产品当前状态**

Visoryn 已具备完整的视觉创作链路：用户上传参考图，获得风格拆解，编辑生成提示，生成同风格新图，并可保存和复用模板。

**存在的问题**

1. **AI 仍像后台处理器**：用户能看到结果，但不容易理解 AI 正在观察什么、相信什么、建议下一步做什么。
2. **参考图、风格判断和提示文本之间的关系不够可见**：用户难以判断哪些风格证据影响了当前提示内容，也难以有把握地编辑意图。
3. **生成前的关键判断过于压缩**：生成是否就绪、变量是否完整、风格信号是否足够、服务是否可用等信息没有形成明确的行动区。
4. **历史和模板更像存储列表，不像创作记忆**：用户可以保存和复用内容，但页面没有充分表达来源图、变量形态、复用价值和迭代关系。
5. **全站设计源头与目标风格不一致**：当前规范仍偏 Precision Glass 基础口径，缺少与目标图一致的 AI 协作状态、证据面板、紧凑数据标签和多语义强调色。

**本期目标**

用户从进入首页、打开工作台、上传参考图、理解 AI 风格判断、编辑提示、确认生成、查看历史、保存和复用风格记忆的全过程中，都能看到同一套 AI 优先的界面语言：AI 主动解释，证据清晰可追踪，下一步行动明确，全站风格一致。

### 1.2 核心问题定义

| 问题 | 用户损失 |
|------|---------|
| AI 判断缺少主动解释 | 用户不知道当前结果是否可信，也不知道下一步该编辑什么 |
| 风格证据与提示文本关系不明显 | 用户编辑提示时缺少依据，容易破坏想保留的参考风格 |
| 生成入口只像一个按钮 | 用户在生成前无法快速确认变量、风格信号和服务状态，误操作或犹豫增加 |
| 历史和模板缺少“记忆”表达 | 用户难以从过往结果中学习、比较、恢复和复用风格 |
| 全站风格与目标图不一致 | 用户在首页、工作台、风格记忆库和状态页之间切换时会感到体验断层 |

### 1.3 关键设计决策

| 决策维度 | 最终选择 | 核心理由 | 否决方案 |
|---------|---------|---------|---------|
| 视觉目标 | 以 Evidence Copilot Workbench 为本期目标风格 | 目标图已经明确 AI 协作、证据关系、生成操作区和迭代记忆的界面方向 | 继续停留在基础 Precision Glass，会无法解决 AI 存在感不足 |
| 推进顺序 | 先统一设计规范，再复刻工作台，最后迁移其他页面 | 工作台是核心创作场景，设计规范先行可以避免页面各自发挥 | 同时重绘所有页面，容易造成口径不一且验收困难 |
| 工作台表达 | 保留三栏专业工作台，但强化 AI 状态、证据关系和生成操作区 | 既不打断既有创作心智，又能让 AI 从后台处理变成前台协作者 | 重新发明工作流，会扩大范围并增加用户学习成本 |
| 风格记忆库表达 | 将模板库表达为可复用的风格记忆 | 用户保存的不只是文本，而是来源图、变量和复用意图 | 继续表现为普通文件列表，会削弱复用价值 |
| 全站状态表达 | 所有关键行动都必须说明当前状态、不可用原因和下一步 | AI 创作链路等待和失败较多，用户需要确定感和控制感 | 只用禁用按钮或简短错误文案，用户会误以为产品卡住 |
| 首版适配范围 | 首版聚焦常规宽屏桌面体验 | 主要创作发生在桌面工作台，目标图也是宽屏工作台 | 同期完整重做移动端，会分散本期的视觉复刻质量 |

### 1.4 产品范围

**本期范围**

1. **设计规范升级**：将全站视觉规范更新为 AI 优先的 Evidence Workbench 方向，明确颜色、表面层级、控件状态、证据表达、生成操作区和风格记忆的规则。
2. **全站视觉语言统一**：首页、工作台、风格记忆库、登录入口、空态、加载态、失败态和受限状态统一为目标图风格。
3. **工作台高保真复刻**：工作台呈现左侧导航、AI 协作状态、参考画布、风格理解、提示与生成、近期迭代的完整结构。
4. **AI 证据关系表达**：参考图中的可观察线索、风格分类、提示文本和生成行动之间建立可见关系。
5. **生成操作区强化**：生成前集中展示变量完整度、风格信号、服务状态和主要生成行动。
6. **风格记忆库迁移**：模板库升级为风格记忆库，突出来源图、变量、风格标签、最近使用和复用入口。
7. **全站状态体系补齐**：空态、等待、处理中、完成、失败、未登录、服务不可用等状态均提供明确下一步。

**明确不做**

- 不改变参考图上传、风格分析、提示编辑、图片生成、历史恢复和模板复用的核心业务流程。
- 不新增对话式创作、节点式编辑、多人协作或运营看板。
- 不改变产品名称、付费策略、账号体系或已有创作资产含义。
- 不把本期目标定义为完全像素级复刻；本期关注视觉系统、信息层级、交互结构和 AI 优先表达的一致性。
- 不在首版完整重做移动端工作流；窄屏体验后续单独定义。

## 2. 用户旅程和用户故事

### 2.1 核心用户旅程

```text
主旅程：完成一次 AI 可解释的风格再创作

1. 用户进入首页或直接打开工作台。
2. 页面用清晰的 AI 风格工作台预览说明：参考图会被理解、拆解、编辑并生成新结果。
3. 用户开始创作，进入工作台。
4. 工作台显示当前工作区、AI 协作状态、参考画布、风格理解区、提示与生成区以及近期迭代区。
5. 用户上传或替换参考图。
6. 页面保留参考图，并说明 AI 正在读取色彩、构图、光线、质感和情绪等风格信号。
7. 分析完成后，用户看到风格理解结果、可追踪证据和可信度提示。
8. 用户查看提示文本，理解哪些片段来自哪些风格判断，并编辑本次创作意图。
9. 用户查看生成操作区，确认变量、风格信号和服务状态均已就绪。
10. 用户开始生成。
11. 页面展示生成进度，并保留参考图、提示内容和上一轮结果作为上下文。
12. 生成完成后，用户比较结果、恢复历史版本、继续生成变体，或保存为风格记忆。
13. 用户进入风格记忆库，看到来源图、变量和复用意图，并可选择某个记忆继续创作。
14. 用户在首页、工作台和风格记忆库之间切换时，导航选中、页面层级、状态语言和主要操作反馈保持一致。
15. 用户完成一次可追溯、可恢复、可复用且跨页面体验一致的风格创作。

异常旅程：参考图分析失败

1. 用户上传参考图后进入分析等待状态。
2. 分析失败时，页面保留参考图和当前工作区。
3. 页面说明失败原因，并提供重试分析和更换参考图两个选择。
4. 用户选择重试时，页面回到分析等待状态。
5. 用户选择更换参考图时，页面回到可上传状态，并在新图上传后继续分析。

异常旅程：生成前条件未满足

1. 用户准备生成，但变量、风格信号或服务状态尚未满足。
2. 生成操作区说明当前不可生成的具体原因。
3. 用户根据提示补齐变量、调整提示内容、等待服务恢复或返回风格理解区检查信号。
4. 条件满足后，生成行动变为可用。
5. 用户继续生成。

异常旅程：生成失败

1. 用户开始生成后进入等待状态。
2. 生成失败时，页面保留参考图、提示内容、变量和当前迭代记录。
3. 页面说明失败原因，并提供重新生成、返回编辑和保存当前内容三个选择。
4. 用户重新生成时，页面回到生成等待状态。
5. 用户返回编辑时，页面回到可编辑状态，修改后可再次生成。
6. 用户保存当前内容时，页面确认保存成功并留在可编辑状态，用户之后可从风格记忆库继续使用该内容。

异常旅程：风格记忆库为空或受限

1. 用户进入风格记忆库。
2. 若当前没有可用记忆，页面说明可以从当前工作台保存，或从参考图开始创建。
3. 若访问受限，页面说明限制原因，并提供登录或返回可用工作台的入口。
4. 用户完成登录或创建第一条风格记忆后，回到可浏览和可复用状态。
```

### 2.2 用户故事

**核心用户故事**

| # | 用户故事 |
|---|---------|
| US-01 | 作为首次访问的创作者，我希望首页快速说明产品如何用 AI 理解并再创作参考图，以便我判断是否值得开始创作。 |
| US-02 | 作为正在创作的用户，我希望工作台清楚展示 AI 正在读取哪些风格信号，以便我理解分析结果是否可信。 |
| US-03 | 作为正在编辑提示的用户，我希望看到风格证据与提示文本之间的关系，以便我改变创作意图时不破坏想保留的风格。 |
| US-04 | 作为准备生成的用户，我希望生成前看到变量、风格信号和服务状态是否就绪，以便我知道何时可以放心生成。 |
| US-05 | 作为反复尝试结果的用户，我希望近期迭代可以比较、恢复和继续生成，以便我从历史结果中找到更好的方向。 |
| US-06 | 作为保存风格的用户，我希望风格记忆展示来源图、变量和复用意图，以便我之后能快速判断哪条记忆适合当前任务。 |
| US-07 | 作为遇到失败或限制的用户，我希望页面保留我的输入并说明下一步，以便我可以继续完成任务而不是重新开始。 |
| US-08 | 作为高频创作者，我希望首页、工作台和风格记忆库使用一致的视觉语言和交互反馈，以便我在页面切换时不需要重新学习。 |

| US-10 | 作为新用户，我希望空态能说明 AI 会做什么和我可以做什么，以便我不会面对一组空白面板。 |
| US-11 | 作为长时间创作的用户，我希望界面保持低噪音和清晰层级，以便我能专注于参考图、提示和结果。 |

### 3.2 关键状态

| 状态 | 页面表现 | 用户下一步 |
|------|---------|-----------|
| 首次访问 | 首页展示 AI 风格工作台价值、产品预览和开始创作入口 | 开始创作或浏览风格记忆 |
| 工作台空态 | 参考画布提示上传，风格理解区说明将读取的信号，生成区说明等待分析 | 上传参考图或选择已有风格记忆 |
| 分析中 | 参考图保持可见，AI 状态说明正在读取的风格信号 | 等待、替换参考图或在失败后重试 |
| 分析完成 | 风格理解区展示分类结果、证据和可信度，提示区展示可编辑内容 | 检查风格判断并编辑创作意图 |
| 编辑中 | 提示文本、变量和约束处于可调整状态，生成操作区同步显示就绪程度 | 补齐变量、锁定风格信号或准备生成 |
| 生成就绪 | 主要生成行动可用，生成操作区说明当前条件均已满足 | 开始生成 |
| 生成中 | 保留参考图、提示和上一轮结果，展示处理进度 | 等待完成，避免重复提交 |
| 结果完成 | 结果成为当前焦点，近期迭代新增记录 | 比较、恢复、继续生成或保存为风格记忆 |
| 失败 | 保留用户输入和上下文，说明失败原因 | 重试、返回编辑、更换参考图或稍后再试 |
| 未登录或权限不足 | 页面说明当前限制，不突然打断原任务 | 登录、返回可用页面或继续浏览可见内容 |
| 风格记忆库空态 | 说明记忆库用途，并提供从工作台保存或从参考图创建的入口 | 创建第一条风格记忆 |
| 服务不可用 | AI 状态区说明服务不可用或暂时等待 | 继续编辑、保存当前内容或稍后生成 |

### 3.3 业务规则

1. **设计规范先行**：所有页面改造必须先遵循同一套 AI 优先视觉规范，避免工作台、首页和风格记忆库各自形成不同风格。
2. **每屏只有一个当前任务中心**：首页突出开始创作，工作台突出当前创作，风格记忆库突出查找和复用。
3. **AI 先解释再请求行动**：在上传、分析、编辑、生成和失败状态中，页面必须说明 AI 当前知道什么、缺什么、建议用户做什么。
4. **证据必须可见**：主要风格判断应能回到参考图线索，并能解释提示文本中哪些内容来自这些判断。
5. **生成行动必须可判断**：用户点击生成前，应能看到变量完整度、风格信号、服务状态和不可用原因。
6. **失败不清空上下文**：分析失败、生成失败、受限访问或服务不可用时，应保留用户已上传、已编辑或已选择的内容。
7. **风格记忆必须表达复用价值**：每条记忆应展示来源图、变量形态、风格标签和使用入口，而不是只展示名称。
8. **近期迭代是创作回路的一部分**：历史结果不仅用于查看，还应支持比较、恢复和继续生成。
9. **全站状态语言一致**：空态、加载、失败、未登录和服务不可用都使用简洁、确定、可行动的文案。
10. **首版聚焦常规宽屏**：本期优先保证桌面工作台和相关页面的结构稳定，窄屏完整旅程后续单独定义。

## 4. 验收标准

- AC-01：设计规范完成并可指导全站改造
  前置：团队开始实现任一页面的视觉迁移。
  动作：查看本期设计规范。
  结果：能明确页面底色、面板层级、状态表达、证据关系、生成操作区、风格记忆卡片和主要控件反馈的统一规则。

- AC-02：工作台符合目标风格结构
  前置：用户在常规宽屏桌面打开工作台。
  动作：查看页面整体布局。
  结果：页面包含工作区导航、AI 协作状态、参考画布、风格理解、提示与生成、近期迭代，并与目标图保持同一信息层级和视觉气质。

- AC-03：AI 风格判断可解释
  前置：用户完成参考图分析。
  动作：查看风格理解和提示内容。
  结果：用户能看到主要风格信号、相关证据、可信度提示，并理解这些判断如何影响当前提示内容。

- AC-04：生成前状态可判断
  前置：用户准备生成新图。
  动作：查看生成操作区。
  结果：用户能判断变量是否完整、风格信号是否足够、服务是否可用；若不可生成，页面可见说明原因和下一步行动。

- AC-05：迭代记忆可用于继续创作
  前置：用户至少完成一次生成。
  动作：查看近期迭代并操作历史结果。
  结果：用户可以比较、恢复、继续生成变体，或将满意方向保存为风格记忆。

- AC-06：风格记忆库表达来源和复用价值
  前置：用户进入风格记忆库。
  动作：浏览、搜索、使用、复制或删除风格记忆。
  结果：每条记忆优先展示来源图、风格标签、变量和复用意图；空态或受限状态也提供明确下一步。

- AC-07：全站风格一致
  前置：用户在首页、工作台、风格记忆库、登录入口和状态页面之间切换。
  动作：观察页面壳层、面板、按钮、状态点、标签和文案。
  结果：页面之间使用同一套 AI 优先视觉语言；导航选中、当前任务层级、状态语言和主要操作反馈保持一致，用户能判断当前所在页面和下一步行动，不出现明显旧体系残留或像不同产品的断层。

- AC-08：异常和恢复路径完整
  前置：用户遇到分析失败、生成失败、未登录、服务不可用或风格记忆库为空。
  动作：查看状态提示并尝试继续任务。
  结果：页面保留可复用上下文，说明发生原因，并提供重试、返回编辑、更换输入、登录或创建记忆等可继续行动。

- AC-09：首页和空态能引导第一步
  前置：用户首次进入首页，或进入没有参考图、没有分析结果、没有风格记忆的空态页面。
  动作：查看首屏或空态内容。
  结果：用户能判断 AI 会如何理解参考图、拆解风格、辅助编辑并生成新结果；页面提供明确的开始创作、上传参考图、创建第一条风格记忆或返回可用工作台的入口。
