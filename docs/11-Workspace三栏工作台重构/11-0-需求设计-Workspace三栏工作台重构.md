# 11-0 需求设计：Workspace 三栏工作台重构

## 0. 文档说明

**产品核心目标**：将 Workspace 从当前双栏布局重构为专业级三栏工作台——左侧导航栏 + 顶部模式切换栏 + 中央三列卡片主工作区 + 底部历史条 + 右侧生成按钮，实现"参考图 → 视觉配方 → 提示词"全链路一屏可视。

**本需求定位**：在 09 期布局与生成弹窗重构、10 期模板变量自动填充基础上，本期聚焦工作台整体布局架构升级，从双栏分析+编辑模式升级为完整的专业设计工具界面。

## 1. 需求分析与确认

### 1.1 项目背景

**产品当前状态**

Workspace 已具备完整功能闭环：上传参考图 → AI 视觉分析 → 视觉配方 → 提示词编辑 → AI 图片生成。09 期完成了双栏布局重构（左分析 + 右编辑），10 期上线了模板变量自动填充。

**存在的问题**

1. **缺少全局导航**：用户无法在工作台内快速切换到模板库、历史记录、素材库等页面，需依赖浏览器导航
2. **分析/编辑/生成模式无明确切换**：用户无法直观感知当前处于"分析参考图"还是"编辑提示词"还是"查看结果"的阶段
3. **视觉配方与提示词争抢右侧空间**：分析完成后 Recipe 和 Prompt 编辑器在同一列堆叠，信息密度过高
4. **参考图分析结果展示不够结构化**：当前分析结果以 Recipe 卡片形式展示，缺少按维度（Style/Material/Lighting/Composition/Mood）的百分比评分和色彩色板可视化
5. **生成参数分散**：宽高比、分辨率等参数设置与生成按钮分离，操作路径长

**本期目标**

用户进入工作台后看到稳定的专业三栏布局：左侧窄导航栏提供全局入口，顶部模式切换栏明确当前阶段，中央三列卡片（Reference / Visual Recipe / Prompt）承载核心创作流程，底部历史条提供快速回溯，右侧浮动生成按钮触发图片生成。

### 1.2 核心问题定义

| 问题 | 用户损失 |
|------|---------|
| 缺少全局导航 | 需通过浏览器前进后退访问其他页面，工作流被打断 |
| 无模式状态指示 | 不清楚当前该做什么，功能发现困难 |
| Recipe 与 Prompt 同列 | 高价值信息（配方结构）与操作区（编辑器）竞争注意力 |
| 分析结果不够可视化 | 风格维度评分只以文字呈现，无法快速感知"这个参考图擅长什么" |
| 生成参数分散 | 调整参数和触发生成需要在不同区域操作，效率低 |

### 1.3 关键设计决策

| 决策维度 | 最终选择 | 核心理由 | 否决方案 |
|---------|---------|---------|---------|
| 整体布局 | 左导航 + 顶栏 + 三列卡片 + 底部历史条 | 与专业设计工具（Figma/Sketch）心智模型一致 | 保留双栏，仅新增侧边导航 |
| 导航结构 | 左侧垂直导航栏（窄模式，图标+文字） | 竖式导航节省水平空间，同时保留文字标签降低认知成本 | 顶部水平导航栏（占用垂直空间） |
| 模式切换 | 顶部标签式按钮组（Analyze / Editing / Generate / Result） | 明确阶段感，引导线性工作流 | 隐式状态切换（自动感知） |
| 配方展示 | 独立 Visual Recipe 卡片，按维度分组 + 缩略图预览 | 提升配方阅读体验，与 Prompt 编辑解耦 | 保留配方在分析区内的折叠展示 |
| 生成触发 | 右侧固定浮动按钮 + 快捷键(Enter) | 始终可见，无需滚动，操作最短路径 | 保留在底部工具栏内 |
| 历史记录 | 底部横向缩略图条 | 不占用主工作区垂直空间，支持快速预览 | 右侧独立面板（占用过多宽度） |

### 1.4 产品范围

**本期范围**

- 左侧垂直导航栏（9 个导航项，Workspace/Prompts/History 可跳转，其余显示"即将上线"）
- 顶部模式切换栏（Analyze / Editing / Generate / Result 四阶段标签）
- 中央三列卡片：Reference（上传+图片展示+分析摘要）、Visual Recipe（5 分类模块+缩略图预览）、Prompt（正向/负向文本框+参数设置）
- 底部历史条（横向缩略图，点击预览，查看全部跳转）
- 右侧浮动生成按钮（点击/Enter 触发，loading/禁用态）
- 状态联动（分析完成后自动填充 Recipe 和 Prompt，更换参考图重新分析）
- 各状态下的正确 UI 表现（空态/上传中/分析中/分析完成/生成中/生成完成）

**明确不做**

- 风格下拉选择器（需风格保存能力，后续阶段）
- 帮助/通知/用户菜单交互功能（P2 阶段）
- 配方内容一键复制到提示词（P2 阶段）
- Recipe 缩略图放大预览（P2 阶段）
- 分析摘要 5 维度评分的自动化计算（初期由前端从配方字段提取）
- Recipe 缩略图的智能图片匹配（初期使用占位图）
- 组件库、素材库、设置页面的实际开发（仅标记"即将上线"）
- 数据指标埋点与阈值监控
- 响应式断点适配（本期聚焦桌面端 ≥1024px）

## 2. 用户旅程和用户故事

### 2.1 核心用户旅程

**主旅程：参考图风格再创作**

```
[用户进入 Workspace]
  → 看到三栏布局，中央三列卡片（Reference 空 / Visual Recipe 空 / Prompt 空）
  → 点击 Reference 卡片上传区域，选择参考图
  → 图片上传中，Reference 卡片显示上传进度
  → 上传完成，自动进入 Analyze 模式（顶部高亮 Analyze 标签）
  → 分析进行中，Reference 卡片显示分析进度 + Reference 图下方出现分析加载态
  → 分析完成：
      - Reference 卡片底部展示分析摘要（5 个维度评分）
      - Visual Recipe 卡片填充结构化配方（5 个分类 + 缩略图 + 色板）
      - Prompt 卡片填充生成的提示词
  → 用户浏览 Visual Recipe，点击各分类查看详细子项
  → 用户切换到 Editing 模式，编辑 Prompt 文本
  → 用户调整生成参数（宽高比、分辨率、引导强度）
  → 点击右侧 Generate 按钮或按 Enter
  → 切换到 Generate 模式，显示生成进度
  → 生成完成，切换到 Result 模式，显示结果图
  → 底部历史条新增一条缩略图记录
  → 用户可点击底部历史条回溯之前的生成结果
```

**辅助旅程 A：历史回溯**

```
[用户在底部历史条]
  → 点击某张历史缩略图
  → 右侧面板或弹窗展示该次生成的详情（结果图 + Prompt 快照 + 参数）
  → 点击"恢复到工作台"将历史状态还原到三个卡片中
```

**辅助旅程 B：侧边导航跳转**

```
[用户点击左侧导航]
  → 点击 Workspace：回到工作台（当前页）
  → 点击 Prompts：跳转到模板库页面
  → 点击 History：跳转到完整历史记录页面
  → 点击其他项：显示"即将上线"提示
```

**辅助旅程 C：更换参考图**

```
[用户在 Reference 卡片]
  → 点击"更换图片"按钮
  → 弹出文件选择器或拖拽上传
  → 新图片上传 + 自动重新分析
  → 三个卡片内容更新
```

**异常旅程 D：上传失败**

```
[用户选择参考图后]
  → 上传过程中网络中断或文件格式不支持
  → Reference 卡片显示错误提示（"上传失败，请重试"）
  → 提供"重新上传"按钮
  → 用户点击后重新进入文件选择流程
```

**异常旅程 E：分析失败**

```
[参考图上传成功，系统开始分析]
  → 分析超时或模型返回错误
  → Reference 卡片显示分析失败状态
  → Prompt 和 Recipe 卡片显示"分析失败，请更换图片或重试"
  → 提供"重新分析"按钮
  → 用户可选择更换图片或重试分析
```

**异常旅程 F：生成失败**

```
[用户点击生成按钮]
  → 图片生成服务超时或返回错误
  → 顶部模式切回 Editing，显示错误提示（"生成失败，请调整提示词后重试"）
  → Prompt 卡片保留当前编辑内容，不丢失
  → 生成按钮恢复可用状态
  → 用户可修改提示词后重新触发生成
```

### 2.2 用户故事

**核心用户故事**

| 编号 | 用户故事 |
|------|---------|
| US-01 | 作为创作者，我希望上传参考图后系统自动分析并展示视觉配方，以便我理解图片的风格构成 |
| US-02 | 作为创作者，我希望在一个屏幕内同时看到参考图、视觉配方和提示词三列信息，以便对比参考并快速调整 |
| US-03 | 作为创作者，我希望通过顶部模式标签清楚地知道当前工作阶段，以便聚焦于当前任务 |
| US-04 | 作为创作者，我希望快速触发生成并查看历史结果，以便反复迭代找到最佳效果 |

**延伸用户故事**

| 编号 | 用户故事 |
|------|---------|
| US-05 | 作为创作者，我希望在配方卡片中直接编辑风格描述，以便微调分析结果 |
| US-06 | 作为创作者，我希望将配方内容一键复制到提示词，以便快速组装生成指令 |
| US-07 | 作为创作者，我希望通过左侧导航快速跳转到模板库或历史记录，以便在不同功能间无缝切换 |
| US-08 | 作为创作者，我希望上传失败或分析失败时看到明确的提示和重试入口，以便不会因错误而迷失 |

**底部历史条**（高度 72px）

**右侧生成按钮**（固定定位，垂直居中于三列卡片区域）

蓝色圆形/胶囊按钮，闪电图标+"Generate"文字，下方小字"Enter 生成"。始终可见不随滚动。悬停发光效果。生成中显示加载动画，提示词为空或正在分析时按钮置灰。

### 3.3 业务规则

**模式切换规则**

- 上传完成→分析完成：系统自动切换，顶部依次高亮 Analyze → Editing
- 分析完成后：用户可手动点击 Analyze / Editing 标签自由切换查看
- Generate 标签仅在提示词非空时可点击
- Result 标签仅在生成完成后可点击
- 手动切换模式不改变当前工作台数据状态，仅改变顶部高亮和卡片聚焦

**卡片数据联动规则**

- 分析完成后，Recipe 和 Prompt 卡片同时填充数据
- 更换参考图时，三个卡片内容全部更新（新分析结果覆盖旧数据）
- 生成完成前修改 Prompt 不影响已提交的生成任务

**生成按钮状态规则**

- 禁用条件：提示词为空 / 正在上传 / 正在分析
- 可用条件：提示词非空且不在上传/分析/生成中
- 加载中：点击生成后到生成完成期间
- Enter 快捷键等同点击生成按钮

**历史条交互规则**

- 每次生成完成后，历史条左侧自动新增一条缩略图
- 点击历史缩略图弹出该次生成详情（结果图+提示词快照+参数）
- "恢复到工作台"将历史状态还原到三列卡片，顶部切换到 Editing 模式
- "查看全部"跳转到完整历史页面

**降级呈现规则**

- 上传失败：Reference 卡片显示错误信息+"重新上传"按钮，其他卡片保持空态
- 分析失败：Reference 卡片保持图片展示+失败状态，Recipe/Prompt 卡片显示"分析失败"提示+"重新分析"按钮
- 生成失败：顶部切回 Editing 模式，显示错误提示，Prompt 内容不丢失，生成按钮恢复可用
