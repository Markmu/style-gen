# 02-0 需求设计：用户登录与数据打通

## 0. 文档说明

本文件是 02 期需求总文档，用于统一用户登录、身份识别和数据关联的需求，作为后续架构文档、原型和开发的基础。

**产品核心目标：为产品建立用户身份体系，通过 Google 登录实现用户识别，并将所有业务数据（资产、分析任务、生成任务）与用户打通，使用户登录后可查看和管理自己的全部历史创作记录。**

本需求是 01 期"参考图风格提取与再创作"的后续需求，属于 1 to N 阶段的功能增强。

---

# 第一部分 需求分析与确认

## 1.1 项目背景

Style-Gen 01 期已完成核心创作闭环（上传参考图 -> 结构化分析 -> 可编辑 Prompt -> 同风格再创作），但"首次体验不强制登录"导致以下问题：

- 用户无法跨会话保留创作数据
- 无用户身份，无法实现历史记录、资产管理和后续付费能力
- 所有数据是匿名的，无法做用户级别的行为分析和个性化
- 无法为后续团队协作、模板库、风格资产化等能力提供基础

本期目标：**用户 -> 访问首页（了解产品）-> 点击 CTA -> 未登录则触发 Google 登录 -> 登录后跳转工作区 -> 所有数据关联到用户 -> 登录后查看历史资产和任务**

---

## 1.2 核心问题定义

| 问题 | 影响 |
| --- | --- |
| 数据无法跨会话保留 | 用户关闭浏览器后，之前的上传、分析、生成记录全部丢失 |
| 无法区分不同用户 | 无法实现"我的资产"、"我的历史记录"，无法为付费、配额管理提供基础 |
| 无法建立用户级别数据洞察 | 无法追踪使用频率、创作偏好和留存，无法做精细化运营 |
| 产品安全性和可控性不足 | API 完全暴露，无法防止滥用和做用户级速率限制 |

**如果不做：** 产品无法从"试用工具"升级为"长期工作台"，后续历史记录、付费体系、团队协作都缺少基础。

---

## 1.3 竞品分析

围绕"AI 创作工具的用户体系"，竞品大致可分为三类：

| 类型 | 代表产品 | 登录方式 | 数据管理 | 与本产品关系 |
| --- | --- | --- | --- | --- |
| 社交登录为主 | Midjourney、Google Whisk | Google / Discord | 历史记录 + 配额 + 订阅 | 最接近参考 |
| 邮箱注册为主 | Krea、Leonardo、OpenArt | Google / 邮箱 / GitHub | 历史记录 + 资产管理 + 社区 | 间接参考 |
| 企业 SSO 为主 | Adobe Firefly | Adobe ID / 企业 SSO | 企业级权限 + 品牌资产 | 后续参考 |

已被验证的实践：

- Google 登录是 AI 创作工具最主流的登录方式，用户接受度高
- 登录后应立即可用，不需要额外填写资料
- 历史记录和资产管理是登录后的核心价值

本产品的差异化方向：首版只做 Google 登录追求最简体验；不做"先体验后登录"，直接要求登录才能使用；用户信息展示最小化，不提供资料编辑页面。

---

## 1.4 方案比较与取舍

### 登录方式：仅 Google 登录

| 方案 | 优点 | 缺点 | 判断 |
| --- | --- | --- | --- |
| 仅 Google 登录 | 实现最简，体验一致 | 覆盖面受限 | **选用** |
| Google + 邮箱 | 覆盖面更广 | 需实现注册、忘记密码、邮箱验证 | 不选 |
| 多方式登录 | 最灵活 | 实现复杂度最高 | 不选 |

Google 账号覆盖面足够广，后续如需扩展，现有认证框架的插件机制可低成本添加新的登录方式。

### 登录时机：首页可访问 + CTA 触发登录

| 方案 | 优点 | 缺点 | 判断 |
| --- | --- | --- | --- |
| 先体验后登录 | 转化漏斗更平滑 | 匿名数据迁移成本高 | 不选 |
| 首页可访问 + CTA 触发登录 | 首页可被任何人看到，数据创建前已关联用户 | 需处理 OAuth 回调后跳转 | **选用** |
| 首次生成前登录 | 折中方案 | 部分数据仍需匿名处理 | 不选 |

兼顾首页可访问性和数据关联的清晰性：用户可以先了解产品，但真正开始创作前必须登录。

### 用户信息展示：顶部下拉框

| 方案 | 优点 | 缺点 | 判断 |
| --- | --- | --- | --- |
| 独立用户资料页 | 信息展示完整 | 需开发额外页面 | 不选 |
| 顶部下拉框 | 轻量、不打断工作流 | 信息展示空间有限 | **选用** |
| 侧边栏用户面板 | 空间充足 | 占用工作区空间 | 不选 |

---

## 1.5 产品范围

### 本期必须交付（P0）

- Google OAuth 登录
- 用户记录创建与数据关联（资产、分析任务、生成任务均关联到对应用户）
- 页面访问控制（首页开放，工作区等受保护页面需登录，未登录重定向到首页）
- 接口访问验证（所有业务接口需确认用户身份）
- 顶部导航栏用户信息下拉框（头像 + 名称 + 邮箱 + 退出登录）
- 退出登录

### 建议尽快补充（P1）

- 历史记录列表页
- 登录失败重试和错误提示
- 会话过期自动跳转登录页

### 后续扩展（P2）

- 多登录方式（GitHub、邮箱等）
- 用户资料编辑页
- 配额管理
- 团队与权限体系

### 明确不做

- 用户资料编辑、多登录方式、团队组织、角色权限、配额付费、社交分享
- 忘记密码/重置密码、更换邮箱/绑定手机、账号注销/数据导出
- 多设备登录管理、登录设备历史查看
- 现有匿名数据迁移

# 第二部分 用户旅程和用户故事

## 2.1 核心用户类型

本期用户类型与 01 期一致，新增诉求：

### 独立创作者

- 希望创作数据不会丢失，换设备后还能看到之前的作品
- 希望登录过程尽可能快，不打断创作冲动

### 设计师 / 视觉从业者

- 希望有明确的"我的创作空间"概念，能管理历史作品
- 对账号安全有一定要求

### 轻量探索型用户

- 可能不太愿意登录，但登录过程够简单的话可以接受
- 关心"登录对我有什么好处"

---

## 2.2 核心用户旅程

登录的主旅程融入现有创作旅程，不独立存在：

```text
用户首次访问产品
  -> 首页展示产品价值 + CTA 按钮（上传图片 / 试试示例图）
  -> 右上角显示"登录"按钮（未登录状态）
  -> 用户点击 CTA 按钮
  -> 未登录：触发 Google OAuth 登录
  -> 已登录：直接跳转工作区
  -> （未登录路径）跳转 Google 授权页 -> 用户授权
  -> 回调成功，创建/更新用户记录 -> 跳转工作区
  -> 顶部显示用户头像 -> 完成创作流程
  -> 下次访问首页自动恢复登录状态

用户点击右上角"登录"按钮（未登录状态）
  -> 同样触发 Google OAuth 登录 -> 登录后停留在首页

用户点击顶部用户头像（已登录状态）
  -> 展开下拉菜单 -> 查看信息 -> 点击退出登录
  -> 右上角恢复为"登录"按钮
```

### 次旅程 A：会话过期

```text
用户在操作中 -> 会话过期 -> 系统提示身份无效
-> 前端拦截，引导重新登录 -> 回到之前想访问的页面
```

### 次旅程 B：用户更换账号

```text
退出登录 -> 点击 CTA 或右上角"登录"
-> 使用另一个 Google 账号登录 -> 看到新账号的数据
```

---

## 2.3 异常与边界矩阵

| 场景 | 触发条件 | 系统处理 | 用户可继续动作 |
| --- | --- | --- | --- |
| 未登录访问首页 | 用户未登录直接访问首页 | 正常展示首页，右上角显示"登录"按钮 | 浏览首页 / 点击 CTA 触发登录 |
| 未登录访问工作区 | 未登录直接访问 /workspace | 重定向到首页 | 在首页点击 CTA 触发登录 |
| 未登录点击 CTA | 未登录用户点击上传或示例图按钮 | 触发 Google OAuth | 授权登录 / 取消返回首页 |
| 登录授权失败 | 用户拒绝授权或 Google 返回错误 | 回到首页，展示提示 | 重新点击 CTA 或右上角登录 |
| 会话过期 | 登录凭证过期 | 下次操作提示身份无效，引导重新登录 | 重新登录 |
| 会话自动续期失败 | 自动续期凭证无效或过期 | 强制退出，首页恢复"登录"按钮 | 重新登录 |
| 退出登录失败 | 退出请求异常 | 前端清除本地会话，恢复"登录"按钮 | 重新登录 |
| 数据关联失败 | 数据关联用户身份时失败 | 任务创建失败，提示错误 | 重试操作 |
| 多标签页会话不一致 | 一个标签页退出，另一个仍在操作 | 下次操作提示身份无效，引导重新登录 | 重新登录 |

### 状态恢复原则

- 登录失败时，用户回到首页（而非独立登录页），可重新点击 CTA 或右上角登录
- 会话过期时，优先记住用户想访问的目标页面，登录后自动跳转
- 退出登录时，清除所有本地会话数据，右上角恢复为"登录"按钮
- 任何登录相关错误不应暴露敏感信息（如内部错误详情）

## 2.4 用户故事

### P0

- 作为首次访问产品的用户，我希望先在首页了解产品能做什么，再决定是否开始创作。
- 作为想开始创作的用户，我希望点击 CTA 按钮后，如果尚未登录则自动触发 Google 一键登录，登录成功后直接进入工作区。
- 作为已登录用户，我希望点击 CTA 按钮后直接进入工作区，登录状态对我透明无感。
- 作为已登录用户，我希望在页面右上角看到自己的身份标识（头像），确认当前登录状态。
- 作为已登录用户，我希望点击头像后能看到自己的基本信息（名称、邮箱），确认登录了正确的账号。
- 作为已登录用户，我希望能够退出登录，切换账号或保护隐私。
- 作为再次访问的用户，我希望首页右上角自动显示我的头像，点击 CTA 即可直接进入工作区。
- 作为已登录用户，我希望我的所有创作数据都关联到我的账号，不会丢失。
- 作为会话过期的用户，我希望系统自动引导我重新登录，无缝继续使用。

### P1

- 作为已登录用户，我希望看到自己的历史创作记录列表，回顾和继续之前的工作。
- 作为登录失败的用户，我希望看到清晰的错误提示，知道出了什么问题并重试。
- 作为退出登录的用户，我希望系统确认退出操作，避免误触。

### P2

- 作为希望使用其他方式登录的用户，我希望支持 GitHub 或邮箱登录。
- 作为希望管理个人信息的用户，我希望有资料编辑页面。
- 作为关注安全的用户，我希望查看和管理我的登录设备。

# 第三部分 UX / UE 设计

## 3.1 设计目标

1. 首页保持可访问，用户可以先了解产品再决定登录
2. 登录过程尽可能无感，作为 CTA 按钮的自然延伸
3. 用户身份信息展示不打断创作流程
4. 退出登录操作明确但不突兀

设计原则：登录是"基础设施"不是"功能"，应该透明而非突出；用户信息展示最小化，够用即可；错误提示清晰但不吓人。

## 3.6 业务规则

### 登录规则

- 只支持 Google OAuth 登录，不支持其他方式
- 同一个 Google 账号始终映射到同一个用户记录
- 首次登录自动创建用户记录，不需要额外注册步骤
- 再次登录更新用户信息（名称、头像如有变化）
- 登录后 7 天内免重复登录

### 数据关联规则

- 所有新建的资产必须关联当前登录用户
- 所有新建的分析任务必须关联当前登录用户
- 所有新建的生成任务必须关联当前登录用户
- 用户只能查询和操作自己关联的数据
- 现有匿名数据不迁移，不展示

### 页面访问控制规则

- 首页：不需要登录即可访问
- 工作区（/workspace）：必须登录，未登录重定向到首页
- 所有业务接口需要认证，无效请求返回身份无效提示
- CTA 按钮点击时：已登录直接跳转工作区；未登录触发 Google 授权，回调后跳转工作区
- 右上角"登录"按钮点击时：触发 Google 授权，回调后停留在首页

### 权限规则

- 本期只有"已登录"和"未登录"两种状态，不做复杂的权限分层
- 退出登录后，前端清除所有用户相关状态和缓存

# 第四部分 数据指标与验收标准

## 4.1 核心验收指标

| 指标 | 定义 | 目标 |
| --- | --- | --- |
| 登录成功率 | 登录成功次数 / 点击登录按钮次数 | >= 99% |
| 登录到可操作耗时 | 从点击登录到进入工作区的中位时间 | <= 5 秒 |
| 数据关联准确率 | 数据 user_id 正确关联的任务数 / 总任务数 | = 100% |
| 数据隔离准确率 | 用户只能查到自己数据的请求数 / 总查询请求数 | = 100% |
| 会话恢复率 | 再次访问时自动恢复登录的用户数 / 再次访问用户数 | >= 95% |
| CTA 登录转化率 | 登录成功后进入工作区的用户数 / 点击 CTA 的未登录用户数 | >= 80% |

## 4.2 过程观察指标

| 指标 | 定义 | 观察目的 |
| --- | --- | --- |
| 首页跳出率 | 到达首页后未点击 CTA 或登录按钮就离开的用户比例 | 判断首页价值传达是否足够 |
| OAuth 授权拒绝率 | 在 Google 授权页点击取消的用户比例 | 判断用户对 Google 登录的接受度 |
| 会话过期触发率 | 触发身份无效跳转登录页的请求比例 | 判断会话有效期是否合理 |

## 4.3 通过标准

- 登录成功率 >= 99%，登录到可操作耗时中位数 <= 5 秒
- 数据关联准确率 100%，数据隔离准确率 100%
- 未登录用户无法访问工作区等受保护页面，但可以正常访问首页
- 会话过期后正确跳转登录页，退出登录后数据完全隔离
- 不存在安全漏洞（登录凭证泄漏、跨站请求伪造、数据泄漏）

## 4.4 暂停放量条件

- 登录成功率低于 95%
- 发现任何数据泄漏或隔离失败
- 首页跳出率超过 50%（大量用户浏览首页后不点击 CTA 也不登录）

# 第五部分 风险与兜底方案

## 5.1 风险清单

| 风险类别 | 具体风险 | 影响 |
| --- | --- | --- |
| 用户理解 | 用户不理解为什么点击 CTA 后需要登录，在授权页犹豫或取消 | 降低转化率 |
| 体验 | 登录流程过长、OAuth 跳转慢，用户在等待中放弃 | 转化率降低 |
| 数据 | 用户身份关联错误或数据隔离失败 | 严重安全问题 |
| 合规 | Google 账号信息使用不符合隐私政策 | 上线受阻 |
| 安全 | 登录凭证泄漏、跨站请求伪造、会话劫持 | 用户数据泄漏 |

## 5.2 降级策略

按风险场景分组的降级行为描述：

### 登录服务不可用时

- Google 授权服务暂时不可达：首页正常展示，CTA 按钮点击后展示"登录服务暂时不可用，请稍后重试"提示，用户可继续浏览首页
- 持续不可用超过 30 分钟：通过系统配置开关临时开放工作区匿名访问模式，确保已登录用户不受影响

### 数据关联异常时

- 用户身份关联失败：整个事务回滚，不创建孤立的业务数据
- 会话中用户身份丢失：系统返回身份无效提示，前端跳转登录页

### 安全事件时

- 怀疑登录凭证泄漏：立即使相关用户的会话失效，要求重新登录
- 发现数据隔离失败：立即暂停服务，排查并修复后再恢复

## 5.3 回滚方案

- 通过系统配置开关临时关闭工作区页面访问控制，恢复匿名访问模式
- 回退到上一版不包含身份验证的接口部署
- 清除所有活跃会话，强制所有用户重新登录

## 5.4 合规底线

- 首页底部展示隐私政策链接
- 只存储必要信息（google_id、email、name、avatar_url），不存储 Google Token
- 遵守 Google API 使用条款
- 退出登录时彻底清除服务端会话，不留残留

# 第六部分 结论

## 6.1 推进结论

**建议推进。** 理由：

- 用户体系是产品从"试用工具"升级为"长期工作台"的必要前提
