## 3. 重点审查：sourceGenerationTaskId 落库取舍（Task 9 报告项）

**取舍内容**: `templates.source_generation_task_id` 未在清单外的 `template-repository.ts` 的 `createTemplate` INSERT 中落库，改为在路由层 `createTemplate` 成功后调用清单内 `generation-task-repository.linkTemplateToGenerationTask`（UPDATE templates + `templates.userId = :userId` 归属过滤）。

**结论: 取舍成立，判定为语义等价、风险可接受，不构成 blocker。**

- **语义等价性**: 最终数据状态一致（templates 行的 `source_generation_task_id` 被赋值且 FK 完整），归属被双重保障（路由先经 `findGenerationTaskById(id, userId)` 校验任务归属，UPDATE 再带 userId 过滤）。可观察差异仅两处且均无契约影响：(a) POST /api/templates 响应体是 link 前的模板对象，不回显 `sourceGenerationTaskId`——架构 §7.3 对该端点只定义了请求侧新增字段、响应"复用"既有形状，下游已保存态由详情 `savedTemplate` 反查（ADR-5），plan-05 不依赖该响应字段；(b) updatedAt 被多刷一次，无业务影响。文件清单纪律（README §6 全局护栏：只许修改清单内文件）是该取舍的直接动因，属合规选择。
- **事务/竞态评估**: 确认存在窄窗口——`createTemplate` 已提交而 link UPDATE 失败（连接中断/进程崩溃）时，模板存在但无来源关联，且客户端收到 500 后重试会撞 409 同名冲突。但后果有界：模板本身完整可用（内容/变量/来源资产不受影响，无数据损坏、无 FK 悬挂）；详情仅表现为"未保存"态，用户换名重存即可恢复；ADR-5 本身容忍 1:N 关联（重复保存取最新一条），该失败模式落入同一容忍语义。并发保存同一迭代产生两条关联也与 ADR-5 一致（DISTINCT ON 最新）。仓库层全站无 `db.transaction` 先例（POST /api/generation 的 insert→update→provider 序列同样非事务），该写法与既有模式一致。
- **后续建议**: 在后续涉足 `template-repository.ts` 的计划（如 plan-05 保存流程完善）中把该字段收拢进 `createTemplate` 直写，或以 `db.transaction` 包裹两步写入，并顺带回显响应字段。已记为建议项 S-1，不阻塞本期。

## 5. 契约核对（维度 8，对照架构 §7 与 §6.1/6.2/6.4）

- `IterationListItem`（§7.2）：id / status / promptSummary / resultFileUrl / params / createdAt + nextCursor，逐字段一致；promptSummary 服务端 120 字符截断。
- `IterationDetail`（§7.2）：架构 shape 全字段一致（含 `recipeSource`/`variablesSource` 三值、`sourceAssetId`、`savedTemplate`）；额外超集字段 `resultAssetId`、`analysisTemplateVariables`、`sourceTemplateId` 均为计划 §2/§7 显式要求（`use-history-restore` 兼容与 plan-04 恢复链路依赖），"只增不删"成立。
- 游标：`"createdAt::id"` keyset，与 `listCompleted` 既有格式及边界处理一致；非法游标返回空结果而非报错，与近期条行为一致。
- GET /api/generation（§6.1）：默认 `completed`（近期条兼容）；q trim ≤100 超出 400 不截断；status 白名单 400；pageSize clamp [1,50]；`pending` 归并 processing（SQL 层 `IN ('pending','processing')`）；q 命中 prompt_snapshot 或来源模板名 ILIKE（LEFT JOIN）；`iteration_list_queried` 含 duration/itemCount/hasQ/statusFilter（+userId 冗余字段，无害）。
- GET /api/generation/[id]（§6.2）：统一走 `findIterationDetail`；组装算法 `snapshot ?? fallback ?? missing` 逐字段显式；completed 才返回 resultFileUrl；401/404/500 结构保持；`iteration_detail_queried` 含 status/recipeSource/hasSavedTemplate（+taskId，无害）。
- POST /api/generation（§7.3 / ADR-2）：快照由服务端从 analysis task 固化（`validateBody` 不接受客户端快照字段，不可篡改）；`sourceTemplateId` 可选 + 归属校验 400。
- POST /api/templates（§6.4）：`sourceGenerationTaskId` 归属 + completed + resultAssetId 校验，非法 400；同名 409、限流 30/h/IP、其余校验链保持既有。
- Schema（§2.1/§7.6）：列名 snake_case、26 位 varchar、两索引命名与架构一致；状态枚举数据库四值不变、DTO 三值。
