## 3. 实现期两处修正的复核（重点项）

### (a) TC-2.4 到达等待：`app-shell` 可见 → `toHaveURL(/\/workspace$/)`

**判定：修正合理，未放宽行为断言（实际是收紧）。**

- 事实核验：`data-testid="app-shell"` 位于 `src/components/app-shell.tsx:66`，由根布局 `src/app/layout.tsx` 渲染，在**所有路由**可见。原断言 `expect(app-shell).toBeVisible()` 在点击 "Generate" 后的任何时刻（含仍在 `/workspace/iterations`）立即为真，无法等待 SPA 导航提交；随后 `goBack()` 可能在 history entry push 之前执行，退到标签页初始 `about:blank`，得到与功能无关的空白页——失败形态被功能文件修正记录准确描述。
- 替换断言 `toHaveURL(/\/workspace$/)` 正则锚定 URL 结尾，`/workspace/iterations` 不匹配，只有真实到达 `/workspace` 才通过；且 `app-shell` 可见断言仍保留在其后（spec 第 272-273 行）。
- **往返保位四项行为断言全部原样保留**（spec 第 277-283 行）：搜索词 `toHaveValue('neon')`、`Completed` 单选 `toBeChecked()`、已加载条数 `toHaveCount(completedCount)`、`scrollTop > 400`。该修正只改"等待到达"的机制，不动任何被测行为。

### (b) `mockLoggedOutSession` 返回体：`{}` → `JSON.stringify(null)`

**判定：修正合理，提高 mock 保真度，未放宽断言。**

- 事实核验：真实 Auth.js session 端点在无 session token 时响应体为 `null`（`useSession()` 据此返回 `data: null`）。原 mock 返回 `{}` 会使 `useSession()` 得到真值对象且无 `user` 字段，既有 `LeftSidebar`（`src/components/workspace/left-sidebar.tsx:38-40`，`session?.user.name` 等——`?.` 只保护 `session` 一层）会抛 TypeError，令 TC-2.6 因无关的布局崩溃而失败，掩蔽真正要测的未登录面行为。
- TC-2.6 的五项断言全部原样保留：unauthorized 面可见、含登录引导行动、返回工作台行动、列表条目为 0、`style-gen-workspace-state` localStorage 未被清空。mock 对齐真实端点后，测试走的是与生产一致的登出路径。

两处修正均已按流程记录在功能文件"实现期发现与修正记录（2026-08-17）"第 1、2 条，green 证据"与 red 证据的对照说明"亦如实披露 spec 曾修正且 green 运行未再改 spec。
