# 13-0 需求设计：Iteration Memory 闭环补全

## 0. 文档说明

**产品核心目标**：把参考图转化为可信、可编辑的视觉配方，并让用户在每次生成后都能理解、找回和继续原有创作方向。

**本需求定位**：基于现有 Reference -> Evidence -> Render 工作台、近期迭代条和 Style Memory，本期补全 Iteration Memory 的完整浏览、理解与恢复路径，使每次生成尝试都成为可追溯、可继续的创作上下文。本期属于已有产品的新功能完善，不扩展批量生成或新的参考控制能力。

## 1. 需求分析与确认

### 1.1 项目背景

**产品当前状态**

用户可以上传参考图、查看风格证据、编辑提示内容、生成一张新图，并从工作台底部的近期迭代条打开已完成结果、恢复到工作台或继续生成。

**存在的问题**

1. 近期迭代条只能承载少量已完成结果，“查看全部”没有形成可到达的完整页面，用户无法系统回看过去的创作。
2. 已完成、进行中和失败的生成尝试没有统一入口；失败记录容易从用户视野中消失，恢复仍依赖记忆或重新开始。
3. 当前详情以结果图和提示内容为主，参考图、当时采用的风格证据、变量和生成设置没有形成一条易读的上下文链。
4. “恢复”和“生成变体”的意图接近，用户难以判断二者差别，也不确定继续操作是否会覆盖当前工作区。
5. Style Memory 可以保存可复用方向，但用户无法直接从一条经过成功结果验证的迭代判断是否已保存、为什么值得保存。

**本期目标**

用户可以从工作台进入完整 Iteration Memory，快速找到任意一次生成尝试，理解它从参考图和风格证据到提示内容与结果的完整关系，并安全地从该上下文继续创作或保存为 Style Memory。

### 1.2 核心问题定义

| 问题 | 用户损失 |
| --- | --- |
| 没有完整可浏览的迭代入口 | 用户只能看到少量近期结果，较早的有效方向难以找回 |
| 进行中和失败记录缺少统一呈现 | 用户不确定任务是否仍在运行、失败后保留了什么，也容易重复提交 |
| 详情中的来源、证据和结果关系不完整 | 用户看到结果，却无法快速理解当时为何这样生成、哪些内容值得复用 |
| 继续创作可能影响当前工作区 | 用户担心覆盖未完成编辑，因此不敢从历史恢复 |
| 成功迭代与 Style Memory 脱节 | 有效结果没有自然沉淀为可复用的风格方向，下一次仍要重新整理 |

### 1.3 关键设计决策

| 决策维度 | 最终选择 | 核心理由 | 否决方案 |
| --- | --- | --- | --- |
| Iteration 的范围 | 一次正式提交的图片生成尝试就是一条 Iteration，覆盖进行中、完成和失败 | 用户关心的是每次付出与结果，不应只记录成功图片 | 同时纳入纯分析任务，会让本期范围与页面心智过大 |
| 工作台入口 | 保留近期迭代条，并由“查看全部”进入完整 Iteration Memory | 近期条适合快速回看，完整页面适合查找与理解，职责清楚 | 用不断扩大的底部横条承载全部历史，不利于筛选和详情阅读 |
| 完整页面结构 | 列表负责查找，详情负责解释和继续，选择详情时不丢失列表上下文 | 高频用户需要连续查看多条记录，而不是来回跳转 | 每条记录都打开独立孤立页面，会增加回退成本 |
| 对比方式 | 参考图与生成结果并排呈现，并附当时的证据、提示和设置 | 用户需要同时判断来源、规则和结果，不需要抽象相似度 | 首版提供自动相似度总分，容易制造不可解释的准确感 |
| 核心继续动作 | 合并为“继续此方向”，恢复当次上下文但不自动生成 | 一个明确动作即可覆盖恢复与变体意图，避免重复入口 | 同时保留“恢复”和“生成变体”两个近义主操作 |
| 当前工作区保护 | 当继续动作会替换不同的未完成工作区时，必须先明确提醒并允许取消 | 用户最担心的是历史操作导致当前编辑丢失 | 无提示直接覆盖，破坏产品的上下文保留原则 |
| Style Memory 入口 | 真实完成且有结果的迭代可以直接保存；失败和进行中记录不标记为已验证方向 | Style Memory 应优先承接被结果验证过的可复用方向 | 所有失败提示都直接保存为可信记忆，会降低资产质量 |
| 首版管理范围 | 支持查找、筛选、浏览、继续和保存，不提供删除与批量动作 | 首版先验证找回和复用价值，避免扩展为通用文件管理器 | 同期加入删除、导出、批量下载和批量保存，范围过大 |

### 1.4 产品范围

**本期范围**

1. 从工作台近期迭代条进入完整 Iteration Memory。
2. 展示当前用户的所有图片生成尝试，包括进行中、已完成和失败状态。
3. 支持按提示内容查找；当记录来自已命名的 Style Memory 时，也可按该名称找到。筛选提供全部、进行中、已完成和失败四种。
4. 支持继续浏览较早记录，返回列表时保留筛选、搜索、选中项和浏览位置。
5. 列表项展示结果预览或明确状态占位，以及创建时间、提示摘要、状态和主要生成设置。
6. 已完成详情展示参考图、生成结果、当时采用的风格证据与不变量、提示内容、变量、排除项和生成设置。
7. 进行中详情展示当前阶段、已保留上下文和下一步；失败详情展示失败说明、已保留上下文和可恢复动作，不伪造结果图。
8. 提供“继续此方向”动作，将当次上下文恢复到工作台并保持可编辑，不自动开始生成。
9. 当继续动作会替换不同的未完成工作区时，先显示确认提示。
10. 已完成且有真实结果的迭代可以保存为 Style Memory；已保存时展示可识别状态并允许打开对应记忆。
11. 登录要求、空记录、加载中、服务不可用和单条记录暂不可用时，均说明发生了什么、保留了什么和下一步可以做什么。

**明确不做**

- 不纳入纯参考图分析记录；Iteration Memory 首版只管理正式图片生成尝试。
- 不新增多张批量生成、部分完成或按张补全。
- 不提供批量下载、批量保存、批量删除、单条删除或历史保留期限管理。
- 不增加自动风格保持评分或渲染后 AI 审计；本期只展示生成当时已存在的证据与不变量。
- 不新增色卡、动作参考、浏览器捕捉或第三方素材管理集成。
- 不改变 Style Memory 本身的完整资产模型；本期只补充从成功迭代进入现有保存流程的入口和状态。
- 不增加公开分享、协作评论、收藏分组、标签管理或商业化用量设计。
- 不重做移动端专业编辑流程；窄屏只保证信息可访问和操作不丢失。

## 2. 用户旅程和用户故事

### 2.1 核心用户旅程

```text
主旅程：从过去的成功迭代继续创作

1. 用户在工作台底部看到近期已完成结果，点击“查看全部”。
2. 用户进入完整 Iteration Memory，默认看到最近的所有生成尝试。
3. 用户通过提示关键词或状态筛选缩小范围，并继续浏览较早记录。
4. 用户选择一条已完成记录。
5. 详情同时展示参考图、生成结果、当时的风格证据与不变量、提示内容、变量、排除项和生成设置。
6. 用户确认这个方向值得继续，点击“继续此方向”。
7. 如果当前工作区存在不同的未完成内容，页面说明将被替换的内容，并提供取消与继续；取消后留在详情，当前工作区与列表状态均保持不变。
8. 用户确认后回到工作台；参考图、证据上下文、提示内容、变量和生成设置恢复为该次迭代快照，原结果作为上一轮迭代保留可见。
9. 用户修改任意可编辑内容并主动开始下一次生成。
10. 新提交形成一条新的 Iteration，原记录保持不变。

成功沉淀：

1. 用户在已完成详情中确认结果和风格方向可靠。
2. 用户点击“保存为 Style Memory”。
3. 保存流程使用该次迭代的来源、提示与可编辑变量作为起点。
4. 保存成功后，详情显示已保存状态，并提供打开该 Style Memory 的入口。

异常旅程：任务仍在进行

1. 用户打开一条进行中记录。
2. 页面显示当前阶段，并明确参考图、提示和设置已经保留。
3. 页面不展示虚假结果，也不允许重复提交同一次任务。
4. 用户可以返回列表（保持原筛选、搜索与浏览位置）或继续处理其他工作；任务完成后状态和真实结果更新。

异常旅程：生成失败

1. 用户打开一条失败记录。
2. 页面显示失败说明，并保留参考图、提示、变量、证据和生成设置。
3. 用户点击“修正并继续”，将该上下文带回工作台。
4. 用户修改内容后主动重新生成；新尝试成为独立 Iteration，失败记录保留。

异常旅程：记录或服务暂不可用

1. 完整列表无法加载时，页面说明当前工作区不受影响，并提供重试和返回工作台。
2. 单条记录无法打开时，列表、筛选和浏览位置保持不变，用户可以重试或查看其他记录。
3. 未登录时，页面说明需要登录才能查看云端 Iteration；当前工作区快照保持不变，登录后返回原入口。
```

### 2.2 用户故事

**核心用户故事**

| # | 用户故事 |
| --- | --- |
| US-01 | 作为反复试验的创作者，我希望查看全部生成尝试，以便找回不在近期横条中的有效方向。 |
| US-02 | 作为拥有较多记录的创作者，我希望按提示内容和状态查找，以便快速定位目标迭代。 |
| US-03 | 作为评估过去结果的创作者，我希望同时看到参考图、结果、风格证据、提示和生成设置，以便理解当时为什么得到这个结果。 |
| US-04 | 作为想延续成功方向的创作者，我希望安全地把一次迭代带回工作台，以便修改后继续生成，而不是从零开始。 |
| US-05 | 作为当前仍在编辑的创作者，我希望恢复历史前得到明确提醒，以便避免误覆盖未完成内容。 |
| US-06 | 作为遇到生成失败的创作者，我希望失败记录仍保留完整上下文，以便修正后继续，而不是重新整理全部信息。 |
| US-07 | 作为发现可靠结果的创作者，我希望直接把该迭代保存为 Style Memory，以便下一次快速复用这个方向。 |

**延伸用户故事**

| # | 用户故事 |
| --- | --- |
| US-08 | 作为等待生成的创作者，我希望从 Iteration Memory 看到任务当前阶段，以便判断是继续等待还是处理其他工作。 |
| US-09 | 作为连续查看多条记录的创作者，我希望关闭详情后仍停留在原筛选和浏览位置，以便高效比较不同迭代。 |
| US-10 | 作为遇到登录或服务问题的创作者，我希望页面明确说明当前工作区仍被保留，以便稍后继续而不担心丢失。 |

### 3.1 线框图与说明

**工作台近期迭代条**


### 3.2 关键状态

| 状态 | 页面表现 | 用户下一步 |
| --- | --- | --- |
| 首次进入且无记录 | 说明 Iteration Memory 会在首次生成后记录尝试，并提供返回工作台入口 | 开始第一次创作 |
| 加载列表 | 显示稳定的列表骨架，搜索和筛选暂不可操作 | 等待加载 |
| 列表就绪 | 显示最近记录、状态、提示摘要和设置 | 搜索、筛选、选择记录或浏览更早记录 |
| 搜索无结果 | 保留搜索词和筛选条件，说明没有匹配项 | 清除搜索或切换筛选 |
| 进行中 | 使用状态面替代结果图，说明上下文已保留 | 返回列表或等待完成 |
| 已完成 | 显示真实结果和完整上下文 | 继续此方向或保存为 Style Memory |
| 失败 | 不展示虚假结果，说明失败和已保留内容 | 修正并继续或返回列表 |
| 当前工作区可能被替换 | 显示当前方向与目标方向摘要 | 取消或确认切换 |
| 已保存为 Style Memory | 保存动作变为可识别的已保存状态 | 打开对应 Style Memory 或继续创作 |
| 列表服务不可用 | 说明当前工作区不受影响 | 重试或返回工作台 |
| 单条详情不可用 | 保留列表状态并在详情位置说明问题 | 重试、关闭详情或查看其他记录 |
| 未登录 | 说明云端记录需要登录，当前工作区快照仍被保留 | 登录或返回工作台 |

### 3.3 业务规则

1. **Iteration 定义**：用户每次正式提交图片生成，就形成一条独立 Iteration。重试或从旧方向继续生成会创建新记录，不覆盖原记录。
2. **状态范围**：完整页面展示进行中、已完成和失败的生成尝试；工作台近期迭代条只展示有真实图片的近期完成结果。
3. **默认顺序**：列表按创建时间从新到旧排列。继续浏览较早记录后，返回页面仍保持当前搜索、筛选、选中项和浏览位置。
4. **搜索范围**：搜索匹配当次提交的提示内容；当记录来自已命名的 Style Memory 时，也可通过该名称找到。
5. **状态筛选**：首版提供全部、进行中、已完成和失败四种互斥筛选。搜索与状态筛选可以同时生效。
6. **列表预览**：只有真实完成结果才能显示图片。进行中和失败状态必须使用文字和状态图形表达，不能使用示例图或空白图片框冒充结果。
7. **提示摘要**：列表只显示足以识别方向的短摘要；完整文本在详情中查看，不让列表变成长文档。
8. **详情上下文**：已完成详情必须区分参考图、生成结果、模型观察、用户可编辑内容和生成设置，不能把它们合并成一个不可追溯文本块。
9. **来源缺失**：旧记录的参考图或部分证据不可用时，详情明确说明缺失内容；结果、提示和仍可用设置继续展示，用户仍可基于保留内容继续。
10. **进行中更新**：进行中记录完成后，状态面替换为真实结果；若失败，则切换为失败状态并保留原上下文。
11. **失败恢复**：失败记录的“修正并继续”与成功记录的“继续此方向”使用同一恢复原则，均不自动提交新生成。
12. **继续此方向**：恢复参考图、当时的风格证据与不变量、提示内容、变量、排除项和生成设置，并把原结果保留为上一轮上下文。用户必须主动确认下一次生成。
13. **工作区保护**：当当前工作区为空、已经是同一 Iteration，或没有不同的未完成编辑时，可以直接继续；否则必须先确认。取消后当前工作区和历史列表均保持不变。
14. **保存 Style Memory**：只有真实完成并有结果的 Iteration 提供保存入口。保存流程打开时预填当次可复用提示、变量和来源；用户仍需确认名称与内容。
15. **重复保存**：一条 Iteration 已关联 Style Memory 时，详情显示已保存状态和打开入口，不重复制造含义不明的相同资产；用户可以在 Style Memory 中选择复制。
16. **返回行为**：从详情返回列表不重置搜索和筛选；从“继续此方向”进入工作台后，用户使用正常导航返回 Iteration Memory 时，最近的列表视图仍可继续浏览。
17. **错误文案**：所有不可用状态都依次说明发生了什么、哪些上下文仍然保留、用户下一步可以做什么。

## 4. 验收标准

- **AC-01：完整 Iteration Memory 可达且覆盖全部生成状态**
  - 前置：用户已登录，并已分别存在进行中、已完成和失败的生成尝试。
  - 动作：用户从工作台近期迭代条点击“查看全部”。
  - 结果：用户进入完整 Iteration Memory；页面按最近创建顺序展示进行中、已完成和失败记录，完成记录显示真实结果预览，其他状态显示明确状态面。

- **AC-02：用户可以找到并连续浏览目标 Iteration**
  - 前置：用户拥有多条不同提示内容和状态的记录。
  - 动作：用户输入提示关键词、选择一个状态筛选、继续浏览较早记录，并打开其中一条详情后返回。
  - 结果：列表只显示同时满足搜索和筛选的记录；较早记录可继续访问；返回后搜索词、筛选、选中项和浏览位置保持不变；无匹配项时提供清除搜索或切换筛选的行动。

- **AC-03：已完成详情提供可理解的完整创作上下文**
  - 前置：一条 Iteration 已完成，并具有参考图、生成结果和当次创作上下文。
  - 动作：用户打开该记录详情。
  - 结果：页面并排展示参考图与真实生成结果，并清晰区分当时采用的风格证据与不变量、提示内容、变量、排除项和生成设置；缺失的旧数据被明确标记，不影响仍可用内容。

- **AC-04：进行中与失败记录提供确定感和恢复路径**
  - 前置：分别存在一条进行中记录和一条失败记录。
  - 动作：用户依次打开两条详情。
  - 结果：进行中记录显示当前阶段和已保留内容，不展示虚假结果或重复提交入口；失败记录显示失败说明、保留的参考与创作上下文，并提供“修正并继续”。进行中任务完成或失败后，页面更新为对应真实状态。

- **AC-05：继续历史方向时完整恢复且不误覆盖当前工作区**
  - 前置：用户在当前工作区有一个不同的未完成方向，并从 Iteration Memory 选择另一条成功或失败记录。
  - 动作：用户点击“继续此方向”或“修正并继续”。
  - 结果：页面先显示当前方向和目标方向的替换提醒；取消后两边状态均不变；确认后进入工作台，恢复所选记录的参考图、证据与不变量、提示、变量、排除项和生成设置，不自动生成，并保留原结果作为上一轮上下文。

- **AC-06：成功 Iteration 可以沉淀为 Style Memory**
  - 前置：一条 Iteration 已完成且有真实结果，尚未关联 Style Memory。
  - 动作：用户在详情点击“保存为 Style Memory”，确认保存内容并完成保存。
  - 结果：保存流程以该次迭代的来源、可复用提示和变量为起点；成功后详情显示已保存状态和打开入口。进行中、失败或无真实结果的记录不显示已验证保存入口。

- **AC-07：空态、登录和服务异常不破坏现有上下文**
  - 前置：分别处于无记录、未登录、列表加载失败和单条详情加载失败状态。
  - 动作：用户进入 Iteration Memory 或打开详情。
  - 结果：每种状态都说明发生了什么、当前工作区或列表上下文保留了什么，以及下一步行动；重试或登录成功后回到原入口；返回工作台时当前工作区快照不被清空。
