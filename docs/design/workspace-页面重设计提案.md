# Workspace 页面重设计提案

> 文档类型：设计提案
> 范围：桌面版 Workspace
> 当前结论：移动版暂不纳入本轮方案
> 相关文档：
> - [03-0-需求设计-视觉设计改造](../03-0-需求设计-视觉设计改造.md)
> - [03-1-架构文档-视觉设计改造](../03-1-架构文档-视觉设计改造.md)

## 1. 背景

当前 `workspace` 页面已经具备完整功能闭环：

- 上传参考图
- 自动触发分析
- 展示视觉配方
- 编辑 Prompt
- 生成结果图

但从产品体验看，当前页面更接近“功能模块并列摆放”，还不是一个围绕用户创作任务组织的专业工作台。

本提案的目标不是单纯做视觉翻新，而是重新定义页面的信息架构与任务流，让用户更清楚地知道：

- 当前处于哪一步
- AI 已经产出了什么
- 下一步最合理的操作是什么
- 结果如何继续迭代

## 2. 现状问题

### 2.1 任务流不够清晰

页面目前采用左中右三栏结构，上传、分析、生成分别占据一个区域，但缺少明确的步骤关系。对用户来说，这些模块是同时出现的，优先级不够明确。

### 2.2 图片主角感不足

参考图和生成结果虽然重要，但在页面中的视觉地位与控制面板接近，没有形成“内容是主角，工具退后”的专业工作台体验。

### 2.3 分析结果的产品化表达不够

`recipe`、`prompt`、`generate` 都存在，但目前更像技术模块串联，而不是“理解风格 -> 调整意图 -> 输出结果”的连贯创作路径。

### 2.4 生成完成后的重心没有切换

一旦结果生成成功，页面仍保留较强的“分析阶段”结构，缺少以结果为中心的展示和迭代操作区。

## 3. 设计目标

### 3.1 产品目标

- 把 `workspace` 重新定义为一个面向创作任务的专业工作台
- 让用户以最低认知成本完成首轮生成
- 为二次迭代提供顺滑入口

### 3.2 体验目标

- 图片始终是页面主角
- 操作区围绕步骤组织，而不是围绕组件组织
- 每个状态都明确回答“现在发生了什么”和“下一步做什么”

### 3.3 视觉目标

- 延续深色、克制、专业的品牌气质
- 弱化模板化 SaaS 后台感
- 强化影像工具 / 创作工作台的专注感

## 4. 设计原则

### 4.1 内容优先

参考图和结果图是页面核心资产，所有 UI 都应服务于内容理解与创作决策。

### 4.2 任务优先

页面不是在展示功能，而是在陪用户完成一条创作路径：

`上传参考图 -> 理解风格 -> 调整意图 -> 生成结果 -> 继续迭代`

### 4.3 渐进披露

先给用户可快速理解的摘要，再提供完整配方和深度编辑能力，避免首屏信息过载。

### 4.4 结果导向

当生成完成后，页面重心应自动从“分析输入”切换到“展示结果与继续迭代”。

## 5. 信息架构

新版页面采用“两段式工作台”结构：

- 左侧：内容画布
- 右侧：决策面板

### 5.1 左侧内容画布

职责：

- 承载参考图或生成结果的大图展示
- 在不同阶段承担视觉中心
- 提供结果查看、对比、下载等高频动作

建议状态：

- 空状态：上传区
- 分析后：参考图主视图
- 生成后：结果图主视图，可切换对比查看

### 5.2 右侧决策面板

右侧严格按照 3 个步骤组织：

1. `风格拆解`
2. `生成指令`
3. `输出设置`

每一步只承载一种决策，避免多个同级面板互相竞争注意力。

## 6. 页面骨架

### 6.1 顶部总览条

顶部不只是页面标题，而是轻量的工作区状态栏。

包含：

- 页面标题：`基于参考图创作`
- 页面说明：`上传参考图，提炼风格特征，再生成可继续迭代的新图`
- 状态标签：`未开始 / 分析中 / 可生成 / 生成中 / 已完成`
- 次级操作：`更换参考图`

目的：

- 告诉用户页面用途
- 告诉用户当前阶段
- 保持主要动作稳定，不在页面中四处寻找入口

### 6.2 主体结构

桌面端整体比例建议：

- 左侧内容画布：约 60% - 65%
- 右侧决策面板：约 35% - 40%

## 8. 模块级设计说明

### 8.1 上传区

要求：

- 更像内容入口，而不是表单控件
- 明确支持格式与大小限制
- 通过一句流程说明降低首次使用心理负担

建议：

- 大尺寸上传区
- 居中引导文案
- 补充“上传后会自动分析”的预期提示

### 8.2 风格拆解

推荐分两层：

- 第一层：核心摘要
- 第二层：完整配方

核心摘要建议字段：

- 主体
- 场景
- 光线
- 色彩
- 情绪

完整配方用于承载更专业的拆解字段，如构图、镜头语言、质感、关键词、保留项、可替换项。

### 8.3 Prompt 编辑

当前的双文本框能力保留，但表达方式需要更产品化。

建议：

- 标题不只是 `Prompt 编辑`
- 增加一句辅助文案，说明这个区域的价值
- `Negative Prompt` 保持次级位置

推荐表达：

- 主标题：`生成指令`
- 辅助文案：`保留核心风格，按你的创作目标微调描述`

### 8.4 输出设置

建议把生成参数区从普通表单升级为“输出决策区”。

包含：

- 宽高比
- 画质
- 主按钮

按钮文案随阶段变化：

- `生成首版`
- `重新生成`
- `正在生成`

### 8.5 结果查看

生成完成后，结果相关操作要集中在同一视图上下文中：

- 查看结果图
- 切换对比
- 下载
- 再次生成

这样可以避免下载、对比、编辑、生成动作散落在多个模块里。

## 9. 状态设计建议

### 9.1 空状态

页面需要传达：

- 可以做什么
- 做完会得到什么
- 整体只需 3 步

### 9.2 分析中

不要只显示“正在分析”，还应传达系统正在识别：

- 主体
- 光线
- 构图
- 色彩

排队态应平静表达，不引发焦虑。

### 9.3 分析完成

第一时间让用户看到“AI 理解到了什么”，并立即进入可编辑状态。

### 9.4 生成中

页面应保持当前参考图或最近结果图可见，避免用户在等待期间失去上下文。

### 9.5 生成完成

默认展示结果图，让“结果评估”和“继续迭代”成为主要任务。

### 9.6 失败态

错误提示不只说明失败，还应明确下一步：

- 重试
- 更换参考图
- 保留已有内容继续编辑

## 10. 本轮不纳入

- 移动版布局方案
- 新功能范围扩展
- 后端状态机或 API 契约调整
- 新依赖或大规模组件体系重构

## 11. 下一步建议

若该提案被确认，建议按以下顺序推进：

1. 输出中保真布局说明，补足模块尺寸、优先级和交互细节
2. 将现有组件映射到新信息架构，判断哪些复用、哪些需要重组
3. 再进入页面代码改造

---

该提案的核心不是“做一个更好看的 Workspace”，而是把页面重新定义为一个围绕创作任务推进的专业工作台。
