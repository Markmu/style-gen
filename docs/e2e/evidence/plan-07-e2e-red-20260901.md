## 存量断言对齐记录（plan-07 实现规格 §4，加强不放宽）

- 主 spec TC-2.3/TC-2.5：`generation-dialog` 可见 → 「方向 rail 内联终态可见（`direction-completed-item`）+ 弹层不出现」。理由：plan-07 §4 明确「更新旧 spec 为『成功不弹层』；修正因主流程改变而失效的断言但不得放宽行为标准」；同一 spec 内 TC-7.x 断言「不弹层」与旧断言「弹层可见」互斥，须以新契约收敛。TC-2.5 原「等待终态暴露重放窗口」语义由 rail 内联终态等待保留。这两条在本 red 运行按计划转红（弹层仍在）。
- `workspace-generation-dialog.spec.ts` 三条与 `ai-first-visual-regression.spec.ts` TC-8.3：「弹层出现并展示进度/成功/失败」→「内联结果可见（active face / completed item / failure face + 截断原因 + 恢复入口）+ 弹层不出现」，保留原有上下文保留断言（Reference/Recipe/Prompt editor、Render Dock 紧凑、空 negative prompt 请求体）。
- 未在本阶段修改、将在 green 阶段按 plan-07「允许修改的额外文件」最小对齐的存量弹层断言：`e2e/error-path.spec.ts`「生成 API 失败展示错误」「Generation Failed保留 Prompt 和Retry入口」两条（仍断言失败弹层，plan-07 实现后转红，届时改为内联失败断言并在 green evidence 列明）。

## 1280×720 视口归属决策（plan-05 review S-2 移交）

- **决策**：1280×720 不纳入架构 §8.5 的显式验收视口清单（保持 1440×900 / 1280×800 / 390×844 截图验收），但归属为「功能可用视口」：rail 三组可见、无结构性横向溢出、Prompt/Render 控件可点击（不得出现本次 red 证实的行为性遮挡）。
- **依据**：主 spec 默认视口即 1280×720——TC-7.5 的 click 拦截实证该视口下 rail 出现后编辑控件不可用，属于必须修复的功能缺陷而非可选截图基线；同时 plan-05 review S-2 的 49px 旧形态挤压由 TC-7.9 的最小 DOM 守卫（无横向溢出）+ 主 spec 默认视口行为断言共同认领。
- **落点**：TC-7.9 末尾以 `setViewportSize(1280×720)` 执行 rail 可见 + 无横向溢出 DOM 断言（不拍截图、不进截图基线）；建议 implementer 在 Task 4 一并消除该视口的 Prompt 卡折叠。
