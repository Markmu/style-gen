## 编排修复合规性裁定

### 修复 1：TC-6.2 seed 时序移到 goto 之后 —— 合规成立

**技术依据核实（本复核独立探针，playwright@1.58.2 + Chromium headless）：**
导航前 `page.evaluate(() => sessionStorage.setItem(...))` 抛出
`SecurityError: Failed to read the 'sessionStorage' property from 'Window': Access is denied for this document`
（about:blank opaque origin）。该错误在应用代码加载之前触发、与被测实现状态完全无关，
构成「任何实现均不可能通过」的测试侧硬缺陷。修复后采用与同文件 TC-6.1 一致的
「先导航后种快照」模式（该模式被其余 12 个用例稳定使用），前置条件语义不变
（打开预检时工作台仍含不同未完成内容）。

**断言零放宽核实：** 当前 TC-6.2 保留弹层可见 + 含 Memory 名称 + URL 不跳
`?templateId=` 三组断言，定位器不变（详情页头按钮 testid 容器 + 可访问名正则）。对快照
字节级断言仅存在于 TC-6.1 标题与代码（列表入口）。red evidence 的 TC-6.2 行写
「同上（入口换详情页头按钮）；不发生跳转」，其尾部措辞与 TC-6.2 自身测试标题
「…打开复用预检弹层：不跳转工作区」精确镜像，而 TC-6.1 行的「快照字节不变」对应其自身标题；
据此判定 red 版本 TC-6.2 即不含快照断言，非本轮删除。旁证二：若 red 时序已是「先种后导」，
SecurityError 应使 red 期 TC-6.2 死于种子步骤而非点击后，与 red evidence
「入口类（TC-6.1/6.2）点击后首个失败断言为 dialog not found」矛盾——两者只能一真，
无论哪一版本为真，「当前断言集合不多于 red 契约」均成立或差异点无事实依据。
该快照不变量本身仍由 TC-6.1（同组件实例）、TC-6.9/TC-8.1（取消/Escape 零写盘）充分承保，
无行为类失去覆盖。

### 修复 2：TC-6.13 移除固定 processing mock —— 合规成立

**技术依据核实（静态链 + 探针双通道）：**
- 静态：`mockGenerationPolling(page, taskId, ...)` 注册 `**/api/generation/${taskId}**` 固定响应；
  `mockIterationDetail(page, detail)` 注册 `**/api/generation/${detail.id}**`。TC-6.13 中
  `taskId === detail.id === 'reuse-new-iteration'`，两 handler 通配串完全相同。
- 探针：playwright@1.58.2 同串双 route handler 场景下，先注册者 5 次请求 0 次调用、
  后注册者 5/5 全部胜出——LIFO 成立且后者 `fulfill` 后前者永久不可达。固定 processing mock
  若注册在后即永久压制 completed mock，生成永不能完成，属装配缺陷。
- 断言三段保持原文逐字核实：恰 1 次 POST + body.`sourceTemplateId` 精确比对；
  Iterations 详情面板来源标注两断言；usage 聚合（最近使用可见 / 「尚未使用」0 次 /
  `/派生.*4.*次/`）。均未被放宽或删除。
- 无掩盖缺陷：processing→completed 迁移类行为由存量 spec 矩阵继续承保
  （ai-first-shell / workspace-generation-dialog / workspace-layout / workspace-iteration-detail /
  workspace-iteration-save-style-memory / workspace-iteration-memory-integration 共 6 个文件
  使用序列型 polling mock）；本用例职责（AC-06 关联链路）不受影响。removal 使 UI 少经一次中间态，
  属该用例本来就无从达成的假路径清理，非能力收窄。
