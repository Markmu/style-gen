## 测试中固化的新契约（供 implementer 对齐）

- `getDirectionIterationFeed(userId, analysisTaskId, pageSize = 5)`：三个独立有界 select（completed limit pageSize、pending/processing limit 1、failed limit 1），全部 `orderBy(desc(createdAt), desc(id))` 并强制 `userId + analysisTaskId`；DTO 为 `DirectionIterationFeed` 同形（createdAt 为 Date，路由负责 ISO 序列化）；failed `errorMessage` 截断上限固化为 **200 字符**（"输出前截断"的具体口径，测试以 400→200 断言）
- `createGenerationTask` 增加可选 `promptControlSnapshot`（透传 insert values，缺省持久化 `null`）；`GenerationTask`/`IterationDetail` 增加 `promptControlSnapshot: PromptControlSnapshot | null`
- `GET /api/generation?view=direction&analysisTaskId=…&pageSize=5`：`view` 为白名单枚举（仅 `direction`，未知值 400）；缺 `analysisTaskId` 400；`pageSize` 仅 1-5（0/6 → 400，不做 clamp）；成功日志 `direction_iterations_queried` 携带 `duration/completedCount/hasActive/hasLatestFailure`；未带 `view=direction` 时保持既有 status/cursor 契约
- `POST /api/generation`：可选顶层 `promptControlSnapshot`（与 plan-02 已上线的 `submitGeneration` 客户端 payload 一致），trigger 取自快照（缺省 `manual`）并进入 `generation_request_received` 日志；校验枚举（intent/detailLevel/editorMode/trigger）、≤20 变量、≤10 adjustments、单值 ≤200、customTemplate ≤6000、`enabledInvariantIds`/`adjustments[].invariantId` ⊆ Recipe invariant ID、`variableValues` 键 ⊆ Recipe 变量名（V2 `contentVariables`，回退 `analysisTemplateVariables`）；拒绝时 400 并输出 `prompt_control_snapshot_rejected`；`params.aspectRatio` 必须在 `SUPPORTED_ASPECT_RATIOS`（plan-01 共享白名单）内；接入 `checkRateLimit(userId, "generation", RATE_LIMIT_CONFIGS.generation)`，超限 429 `RATE_LIMITED`
- Provider 启动/提交异常：task 进入 processing 后置于显式 try/catch；先 best-effort `updateGenerationTask(id, { status: "failed", errorMessage })` 再返回 500 `SERVICE_UNAVAILABLE` retryable；终态写入失败输出 `generation_failed_status_write_failed`（console.error critical，含 taskId/analysisTaskId/provider，不含 Prompt）；非 critical 结构化事件沿用 `log()`（console.log）
- `POST /api/analysis`：判别联合——上传模式（assetId/fileUrl/width/height/mimeType）或已有资产模式（仅 `sourceAssetId`）；混入元数据 400；`findAssetByIdForUser` 未命中（不存在/不归属）404 `NOT_FOUND`；非图片 MIME 400 防御；成功日志 `analysis_existing_asset_started`（含 assetId）；接入 `checkRateLimit(userId, "analysis", RATE_LIMIT_CONFIGS.analysis)`，超限 429

## 判定

- 失败原因全部是 plan-03 目标功能（`prompt_control_snapshot` 持久化与详情回证、`getDirectionIterationFeed` 三组有界查询、direction GET、快照/画幅校验、Provider 启动异常终态与 critical 日志、analysis `sourceAssetId` 判别联合、两条用户级限流与 §8.5 结构化事件）尚未实现，不是测试语法、mock 或环境错误：五个测试文件 ESLint 0 error 0 warning（仅 2 个存量 unused-vars warning，为本步骤之前已存在的解构写法）；全部沿用文件内既有 Drizzle mock 链、route mock 工厂与 `RATE_LIMIT_CONFIGS` mock 模式，不依赖 live Provider/R2/DATABASE_URL。
- 123 个既有用例全部通过（含 plan-01 快照固化、模型解析、列表 cursor/status、analysis 既有管线），符合「实现后必须保持」约束；8 个即绿新用例均为 plan-03 明示的回归锁或防御/兼容锁定。
- 附注：测试文件引用了尚不存在的导出（`getDirectionIterationFeed`、`findAssetByIdForUser`）与尚不存在的 DTO 字段（`promptControlSnapshot`）；`tsconfig.json` 已排除 `**/__tests__/**`，`pnpm type-check` 不受影响，green 阶段随 Task 2-6 实现自然消除。
- 结论：**预期失败，测试有效。**
