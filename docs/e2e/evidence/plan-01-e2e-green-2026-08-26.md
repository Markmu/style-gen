## 2026-08-26 B1 修复后复跑

> task-review（`docs/14-可验证Style-Memory/14-2-实现计划-可验证Style-Memory/reviews/plan-01-review-2026-08-26.md`）判定 blocker B1 后，`src/lib/style-memory-rules.ts` 已按架构 §6.4 修复并补充回归用例。本节为修复后同一命令的复跑记录；frontmatter `phase: green` 保持不变，上文 51/51 为修复前历史记录。

### 修复摘要（B1）

- 位置: `src/lib/style-memory-rules.ts` `normalizeRuleArray`。
- 原实现顺序为「按**原始串**字典序排序 → trim → 过滤空串」，与架构 §6.4 及 plan-01 实现规格 §4 声明的「逐元素 trim → 过滤空串 → 按字典序排序」相反：空格（0x20）小于所有字母，带前导空白的元素在原始串排序中提前，trim 后相对顺序翻转，导致"仅空白差异/仅改序"被误判为实质变更而多回退 `pending_verification`。
- 修复: 顺序调换为 `map(trim) → filter(非空) → sort(字典序)`，与架构 §6.4、计划实现规格 §4、函数自身 docstring 三处口径一致。本证据未改动任何实现或测试代码（修复先于本次复跑完成）。

### 测试变更（B1 修复引入）

`src/lib/__tests__/style-memory-rules.test.ts` 新增 3 个 B1 回归用例（13 → 16）：

1. `normalizeRuleArray` 前导空白不参与排序（trim 先于排序）: `[" soft light", "golden hour"]` → `["golden hour", "soft light"]`
2. `ruleSetsChanged` 纯前导空白差异返回 false（多元素不回退）: `[" soft light", "golden hour"]` vs `["soft light", "golden hour"]` → false
3. `ruleSetsChanged` 前导空白参与排序的等价集合返回 false（trim 后改序不回退）: `[" b", "a"]` vs `["a", "b"]` → false

**断言纠正说明（1 处既有用例期望按架构 §6.4 规格顺序修正）**：既有用例「逐元素 trim 并过滤空串」中 `normalizeRuleArray(["  rim light  ", "", "   ", "low key"])` 的期望修正为规格顺序的 `["low key", "rim light"]`。该输入在修复前的「先排序后 trim」实现下产出 `["rim light", "low key"]`，原期望锚定了错误实现的输出顺序（review 报告"现有用例在两种顺序下结果一致"的预测对该用例不成立）；本次修正是期望向规格对齐（trim → 过滤 → 字典序排序），不是放松断言。`src/lib/repositories/__tests__/template-repository.test.ts` 用例数不变（38）。
