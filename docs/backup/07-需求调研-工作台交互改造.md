## 1. 需求概述

- **一句话描述**：将工作台从两段式布局升级为三段式专业工作台，增加生成历史面板和独立模板库页面
- **核心问题**：04 期重构建立了两段式布局（画布+决策面板），但随着模板系统（06期）上线，工作台承载的功能越来越多，出现了布局跳变、右列内容过载、缺少生成历史回溯、模板管理体验割裂等问题。需要参照 Stitch 设计和行业标准，升级为三段式布局（左导航 + 中央工作区 + 右侧历史面板），同时将模板库独立成页面。
- **目标用户**：使用 Visoryn 进行风格提取和图像生成的创作者
- **触发场景**：
  - 用户在工作台多次迭代生成时，无法回顾之前的尝试
  - 用户在分析完成后布局突然跳变，认知被打断
  - 用户想浏览/管理模板时，抽屉式 UI 空间不足、无法搜索过滤
  - 用户想快速编辑风格拆解结果时，当前 RecipeStep 信息密度过高
- **成功标准**：
  - 布局状态切换无跳变，过渡动画流畅
  - 用户可在右侧面板回溯最近 N 次生成结果及其参数
  - 模板库支持搜索、过滤、卡片网格浏览
  - 风格拆解以 4 行可编辑模式呈现，信息密度降低

### 2.3 核心路径拆解

**Midjourney Web — Create 工作流**

```text
步骤1: 点击左侧 Sidebar "Create" 进入生成工作区
步骤2: 在顶部 Prompt Bar 输入文本描述
步骤3: 点击 Settings 图标调整 Aspect Ratio/Model/Stylize 等参数
步骤4: 按 Enter 或点击 Generate 提交
步骤5: 中央 Feed 实时展示生成进度和结果
步骤6: Hover 结果图 → 出现 Variant/Upscale/Reference 工具
步骤7: 点击结果图 → 右侧面板展示原始 prompt + 参数 + seed
步骤8: 左侧 "Organize" 管理历史生成的 Gallery
```

关键体验点：**生成结果即历史**——每次生成自动成为 Feed 的一部分，无需手动保存。点击任何历史图都能完整回溯参数。

**Stitch 设计 — Prompt Architect 工作流**

```text
步骤1: 左侧 Sidebar 选择 "Generate" 进入工作台
步骤2: 中央区域拖放参考图到 Upload Drop Zone
步骤3: 系统自动提取 Extracted Structure（Subject/Style/Lighting/Composition）
步骤4: 点击任一行的编辑图标进行调整
步骤5: Quick Edit 输入框快速修改主题焦点
步骤6: 选择 Aspect Ratio（pill 按钮：1:1/16:9/9:16）
步骤7: 点击 "Generate Output" 生成
步骤8: 右侧 Recent History 面板自动添加结果缩略图
步骤9: 点击 "Save as Template" 保存当前配置
步骤10: 左侧 Sidebar 切换到 "Library" 浏览/管理模板
```

关键体验点：**4 行可编辑结构**将风格拆解从"阅读理解"简化为"选择修改"；**右侧历史面板常驻**让迭代有据可查。

### 2.4 差异化洞察

**可借鉴**：
- **三段式布局已成 2025 行业标准**（4/4 竞品均已采用）— 不做就是落后于行业基线
- **生成历史作为持久面板**（而非弹窗或抽屉）— Midjourney/ComfyUI 验证了这是迭代工作流的必需品
- **Stitch 4 行编辑模式**（Subject/Style/Lighting/Composition）— 简洁直觉，降低 RecipeStep 的认知负荷

**应避免**：
- **ComfyUI 的过度复杂度** — 我们的目标用户不是极客，不需要节点编辑器级别的灵活性
- **Firefly 的对话式交互** — 对轻量单任务工具来说太重
- **Midjourney 的纯 Feed 式展示** — 我们有结构化 Recipe，不应退化为纯文本 prompt

**差异化机会**：
- **"图片分析 → 结构化 Recipe → 模板变量系统" 的完整闭环** — 无竞品同时具备这三个能力
- **模板库作为独立页面** — 竞品的 Preset 都是侧边栏下拉或弹窗，独立 Library 页面传达更专业的产品信号
- **4 行编辑 + 参数回溯结合** — 历史面板点击可恢复完整的 Recipe + Prompt 配置，支撑精准迭代

## 3. 可行性评估

| 维度 | 评级 | 说明 |
|------|------|------|
| 必要性 | **高** | 三段式布局和生成历史是 2025 行业标准，当前体验已成短板。04 期两段式在功能增加后暴露了内容过载和布局跳变问题。 |
| 紧迫性 | **高** | 06 期模板系统上线后，模板管理（抽屉）和工作台的交互冲突更加明显。不做的话每次新功能都会让右列更拥挤。 |
| 技术可行性 | **高** | 前端布局重构有 04 期经验可复用。后端历史 API 所需的 DB schema 已完备（generation_tasks 表已存储所有必要字段），只需补充索引、仓储方法和 API 端点。模板库页面可复用已有模板 API。 |
| 资源投入 | **大（1-2 周）** | 前端：三段式布局 + 过渡动画 + Recipe 4 行编辑 + 历史面板 + 模板库页面（约 5-7 天）。后端：历史 API + DB 索引 + 模板列表 API 增强（约 2-3 天）。废弃组件清理（1 天）。 |

**主要风险**：

1. **三段式布局在窄屏下的适配** — 左侧 Sidebar + 中央 + 右侧历史面板在 < 1280px 屏幕上可能拥挤
   - 缓解思路：左侧 Sidebar 可折叠为 icon-only 模式（48px）；右侧历史面板可折叠/隐藏；设定最小宽度断点
2. **RecipeStep → 4 行编辑模式的信息损失** — 当前 RecipeStep 有 10+ 个字段（composition、cameraLanguage、texture 等），简化为 4 行可能丢失细节
   - 缓解思路：4 行为核心摘要，保留"展开完整配方"能力（与 04 期渐进披露策略一致）
3. **生成历史与 sessionStorage 的冲突** — 当前工作台状态存 sessionStorage，历史面板要从 DB 拉数据，两者需要协调
   - 缓解思路：当前 session 状态继续用 sessionStorage 管理进行中的任务；历史面板独立使用 React Query 从 API 拉取；点击历史项时替换当前 session 状态

**评估结论**：**建议推进**。需求真实、紧迫、技术可行。行业竞品已验证了三段式布局和历史面板的有效性。数据层已具备基础，前端有 04 期经验可复用。

## 4. 初步范围建议

### P0（必须做）

1. **三段式布局重构**：Header + [可折叠 Left Sidebar | 中央工作区 | 可折叠 Right History Panel]
   - Left Sidebar：Workspace 品牌标题 + 导航（Generate / Library）+ 底部辅助链接（Docs / Support）
   - 中央工作区：保持当前画布 + 决策面板的核心结构，但移除两段式中的布局跳变
   - Right History Panel：生成历史缩略图列表 + 点击回溯参数

2. **布局过渡动画**：解决当前两列→三列的硬切跳变
   - 各面板出现/消失使用 CSS transition（宽度、opacity）
   - 状态切换时中央工作区平滑调整宽度

3. **Recipe 展示重构 — 4 行编辑模式**
   - 4 个核心维度：Subject / Style / Lighting / Composition
   - 每行显示维度名称 + 当前值摘要 + 编辑图标
   - 点击编辑图标展开内联编辑（与 Stitch 设计一致）
   - 保留"查看完整配方"展开能力（渐进披露）

4. **生成历史面板（前后端全链路）**
   - 后端：DB 索引 `(userId, createdAt DESC)` + Repository `listByUser` 方法 + `GET /api/generation` 列表 API
   - 前端：React Query hook `useGenerationHistory` + 右侧面板缩略图列表
   - 点击历史项：加载该次生成的参考图、Recipe、Prompt、结果图到工作区
   - 当前进行中的任务在历史面板顶部显示进度状态

5. **模板库独立页面**
   - 路由：`/workspace/templates`（或通过 Left Sidebar "Library" 切换）
   - 布局：Header + [Left Sidebar | 主内容区（搜索 + 过滤 + 卡片网格）]
   - 卡片：模板名称 + 标签 chips + 预览图 + hover "Use Template" 按钮
   - 复用已有模板 CRUD API，增加搜索/过滤能力

6. **废弃组件清理**
   - 移除 DecisionPanel、GeneratePanel、RecipeCard、ResultDisplay、ComparisonView 等已不被引用的组件
   - 移除 TemplateDrawer（被独立页面替代）

### P1（建议做）

1. **左侧 Sidebar 折叠模式**：可折叠为 48px icon-only 模式，增大中央工作区面积
2. **右侧历史面板折叠**：可隐藏历史面板，最大化画布空间
3. **面板宽度可拖拽调整**：使用 `react-resizable-panels` 支持用户自定义比例
4. **真实上传进度**：将 `useUpload` 的假进度替换为 XHR `onUploadProgress` 实时进度
5. **替换参考图不丢文件**：修复 `UploadZone` 中 replace confirm 丢失文件的 bug

### P2（可以后做）

1. **模板库搜索增强**：全文搜索、标签过滤、排序（最近使用/最多使用）
2. **历史面板参考-结果配对展示**：缩略图配对显示参考图和结果图
3. **快捷键支持**：Cmd+Enter 触发生成、Cmd+Z 撤销编辑
4. **Session 恢复优化**：修复 sessionStorage 恢复硬编码 `analysis_ready` 的问题
5. **TemplateWizard 与 PromptEditor 并排显示**

### 明确不做

- **Landing Page 改造**：03 期已完成视觉改造，本次不动
- **移动端适配**：延续 04 期决策，聚焦桌面端
- **对话式交互**：Firefly 风格过重，不适合当前产品定位
- **节点编辑器**：ComfyUI 风格过于极客，不符合目标用户画像

## 6. 研究过程记录

### 关键问答摘要

**Q: 本次改造的核心方向——保持两段式还是采纳三段式布局？**
A: 采纳三段式布局（Left Sidebar + Center Workbench + Right History Panel）。完全按照 Stitch 设计的结构方向。

**Q: 模板管理方式——保持抽屉还是独立页面？**
A: 独立页面。当前抽屉空间不足，无法支撑搜索和卡片浏览。

**Q: 优先解决的交互痛点？**
A: ①布局跳变 + 过渡动画 ②Recipe 展示重构（4 行编辑模式）③生成历史 & 迭代体验。上传体验优化不作为本次重点。

**Q: 竞品模式中最值得借鉴的？**
A: Stitch 4 行编辑模式（Subject/Style/Lighting/Composition），简洁直觉。其他竞品模式（Midjourney 导航、ComfyUI Queue、Firefly 四支柱）暂不引入。

**Q: 历史面板展示形式？**
A: 纯缩略图 + 参数回溯。轻量级，与 Stitch 设计一致。不采用任务进度合并或配对展示模式。

**Q: Landing Page 是否纳入？**
A: 不改。03 期已做过视觉改造。

**Q: 改造边界——纯前端还是全链路？**
A: 前后端全链路。包括生成历史 API（新建 DB 索引 + Repository + API 端点 + React Hook）和模板库页面的后端支撑。
