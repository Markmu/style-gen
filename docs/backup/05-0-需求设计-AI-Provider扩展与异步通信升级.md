# 05-0 需求设计：AI Provider 扩展与异步通信升级

## 0. 文档说明

**产品核心目标**：从参考图中提取视觉风格，生成结构化 Recipe 并用于 AI 图片再创作

**本需求定位**：在现有硬编码单一 provider + 同步等待的基础上，完成两项升级：① 视觉分析和图像生成增加 Replicate provider 并设为默认；② 引入 Replicate 异步回调接收，释放服务端长连接（前端仍使用轮询获取任务状态）。属于现有功能的技术迭代。

## 第一部分：需求分析与确认

### 1.1 项目背景

当前 AI 管线涉及三个外部模型调用，各自硬编码为单一 provider：

| 阶段 | 当前 provider | 当前模型 |
|------|-------------|---------|
| 视觉理解 | Gemini | `gemini-2.5-flash` |
| LLM 结构化整理 | Gemini | `gemini-2.5-flash` |
| 图像生成 | fal.ai | `fal-ai/flux/dev` |

异步通信采用轮询模式（ADR-3）：前端定时轮询任务状态，后端同步等待 AI 调用完成后写入数据库。

存在的问题：

| 问题 | 用户损失 |
|------|---------|
| 视觉分析 provider 硬编码为 Gemini，无法切换 | Gemini API 不稳定或质量不符预期时无替代方案 |
| 图像生成 provider 硬编码为 fal.ai，无法切换 | 无法使用 Replicate 上的生成模型 |
| 两个阶段的 provider 切换都需要改动核心代码 | 迭代和试验新模型的成本高 |
| 后端同步等待 AI 调用，长时间占用服务端连接 | 并发能力受限，容易超时 |

**本期目标**：
1. 视觉分析和图像生成支持 Replicate provider 并设为默认
2. 通过 Replicate 异步回调接收结果，释放服务端长连接（前端仍使用轮询获取任务状态）

### 1.2 核心问题定义

| 核心问题 | 用户损失 |
|---------|---------|
| 视觉分析和图像生成受限于单一模型，无法切换或试验替代方案 | 质量天花板被锁死，模型不稳定时无备选 |
| 服务端同步等待 AI 结果返回，长时间占用连接 | 并发能力受限，容易超时 |

### 1.3 关键设计决策

| 决策维度 | 最终选择 | 核心理由 | 否决方案 |
|---------|---------|---------|---------|
| 视觉分析默认 provider | Replicate | 用户明确要求 | Gemini 保留为备选 |
| 图像生成默认 provider | Replicate | 用户明确要求 | fal.ai 保留为备选 |
| provider 切换方式 | 配置项切换 | 最简实现，无需 UI，运维友好 | 界面切换（过度设计）|
| 结构化阶段是否也切换 | 不切换，仍用 Gemini | 结构化需要结构化输出能力，Gemini 原生支持好 | 全部切换（超出范围）|
| Replicate 结果接收方式 | 异步回调通知 | 释放服务端长连接，Replicate 原生支持 | 轮询 Replicate 接口（浪费资源）|
| 前端获取任务状态方式 | 保留轮询 | 最简实现，架构不变，可靠性高 | 实时推送（引入长连接复杂度）|

### 1.4 产品范围

**P0 — 本期必须交付**：
- 视觉分析阶段支持 Replicate provider，设为默认
- 图像生成阶段支持 Replicate provider，设为默认
- 通过配置项可分别切换回 Gemini / fal.ai
- 服务端接收 Replicate 异步回调通知，更新任务状态
- 前端通过轮询获取任务进度和结果（保留现有轮询机制）

**P1 — 建议尽快补充**：
- 前端优化轮询策略（如指数退避、自适应频率）

**P2 — 后续扩展**：
- 自动降级机制（某 provider 失败自动切换到备选 provider）
- 前端界面上的 provider 选择

**明确不做**：
- 结构化整理阶段的 provider 切换
- 实时推送（WebSocket / SSE 等长连接方式）

## 第二部分：用户旅程和用户故事

### 2.1 核心用户旅程

用户操作流程不变，后端从同步等待改为异步回调接收，前端仍通过轮询获取任务状态：

```text
用户上传参考图
  → 服务端提交 Replicate 视觉分析任务，立即返回任务标识
    → 前端开始轮询任务状态
      → Replicate 完成后异步回调服务端
        → 服务端更新任务状态和结果到数据库
          → 前端下次轮询时获取到完成状态，展示风格配方 + Prompt

用户编辑 Prompt → 点击生成
  → 服务端提交 Replicate 图像生成任务，立即返回任务标识
    → 前端开始轮询任务状态
      → Replicate 完成后异步回调服务端
        → 服务端更新任务状态和结果到数据库
          → 前端下次轮询时获取到完成状态，展示生成图片
```

异常路径：
- 回调返回失败状态：服务端更新任务为失败，前端下次轮询时获取到失败状态，展示失败提示并可重试
- 超时未收到回调：服务端主动将任务标记为失败，前端轮询获取到超时错误，展示超时提示并可重试

### 2.2 用户故事

**P0**：
- 作为运维人员，我希望通过配置项分别切换视觉分析和图像生成的 provider，以便在不改代码的情况下快速切换模型
- 作为用户，我希望提交分析/生成任务后，能通过页面自动刷新看到任务进度和结果，以便减少等待焦虑并及时获得反馈
- 作为用户，我希望上传图片后获得与之前一样或更好的风格分析结果，以便确保 provider 切换不影响核心体验
- 作为用户，我希望生成图片时获得与之前一样或更好的图像质量，以便对生成结果保持信心

## 第三部分：UX/UE 设计

### 3.1 线框图与说明

前端布局不变，交互变化集中在等待阶段的进度反馈：

```
┌─────────────────────────────────────────┐
│              Workspace                   │
│                                         │
│  ┌──────────────┐  ┌──────────────────┐ │
│  │  参考图区域    │  │   结果区域        │ │
│  │              │  │                  │ │
│  │  [已上传图片]  │  │  状态：分析中...   │ │
│  │              │  │  ████░░░░ 50%    │ │  ← 轮询更新状态
│  │              │  │                  │ │
│  │              │  │  [分析完成后]      │ │
│  │              │  │  Recipe + Prompt  │ │
│  │              │  │  [生成按钮]       │ │
│  └──────────────┘  └──────────────────┘ │
└─────────────────────────────────────────┘
```

P0 阶段进度展示与当前一致（loading spinner + 状态文案），前端定时轮询任务状态。

### 3.2 关键状态

| 状态 | 页面表现 | 用户下一步 |
|------|---------|-----------|
| 任务已提交 | 显示 loading + "分析中" / "生成中" | 等待结果 |
| 轮询中 | loading 状态持续，定时轮询任务状态 | 继续等待 |
| 任务完成 | 轮询获取到完成状态，展示结果 | 查看 Recipe / 编辑 Prompt / 下载生成图 |
| 任务失败 | 轮询获取到失败状态，显示错误提示 + 重试按钮 | 点击重试或更换参考图 |

### 3.3 业务规则

- 默认使用 Replicate 作为视觉分析和图像生成的 provider
- 可通过配置项分别切换为 Gemini（视觉分析）和 fal.ai（图像生成）
- 提交任务后，前端通过定时轮询获取任务状态（保留现有轮询机制）
- 异步回调超时（如 5 分钟未收到回调）时，任务自动标记为失败
- 结构化整理阶段仍使用 Gemini，不受本次变更影响
- 使用 Gemini / fal.ai 备选 provider 时，不走异步回调路径，保留原有同步调用 + 轮询获取结果的方式

## 第四部分：验收标准

所有 P0 用户故事对应的路径可正常走通，即视为通过：

1. 默认配置下（Replicate），上传图片 → 异步回调完成 → 前端轮询获取 → 展示风格配方 + Prompt
2. 默认配置下（Replicate），编辑 Prompt → 生成图片 → 异步回调完成 → 前端轮询获取 → 展示生成结果
3. 切换视觉分析配置后（Gemini），上传图片 → 完成分析 → 前端轮询获取结果
4. 切换图像生成配置后（fal.ai），生成图片 → 前端轮询获取结果
5. Replicate 调用失败时（回调返回失败 / 超时未收到回调），任务标记为失败，前端轮询获取到错误状态并可重试
