# 06-0 需求设计：Prompt 模板化与变量系统

## 0. 文档说明

**产品核心目标**：让分析后的 prompt 可保存为参数化模板，支持变量插入与批量复用，完成 Reference → Recipe → **Template** → Render 的闭环

**本需求定位**：在已有 style-gen 工作台（Reference → Recipe → Render 三段式流程）基础上，新增「模板化」能力层，使用户能将一次性的 prompt 分析结果转化为可复用的风格模板。本期覆盖 P0（核心 CRUD + 变量机制）+ P1（向导式填值 + 管理增强）

## 第一部分：需求分析与确认 {#第一部分}

### 1.1 项目背景

style-gen 当前核心链路为 **参考图上传 → AI 视觉分析 → 结构化 Prompt → 图像生成**，用户在 workspace 三列布局中完成全流程。

**存在的问题**：

1. **Prompt 是一次性产物**：分析完成后生成的 prompt 存储在分析任务记录中，用户编辑后直接用于生成，没有"保存"的概念——关闭页面即丢失
2. **同风格换主体必须重复劳动**：用户对某次分析的 prompt 满意后，想用同一风格生成不同主体/场景的内容，只能重新分析一张新图，或手动复制粘贴 prompt 再逐处修改文字——体验断裂
3. **无「风格模式」沉淀机制**：设计师积累的风格偏好无法在产品内持久化，每次都从零开始

**本期目标**：用户完成分析并满意 prompt 后，可一键保存为命名模板；模板支持 `{{变量名}}` 语法的参数化；加载模板时通过向导式 UI 填写变量值即可快速生成新图。

### 1.2 核心问题定义

| 问题 | 用户损失 |
|------|----------|
| Prompt 无法保存复用 | 每次想用相同风格都要重新分析或从头手写 prompt |
| 无变量机制，只能整段替换 | 改一个主体词需要通读整段 prompt 定位修改位置，容易遗漏或改错 |
| 风格偏好无法沉淀 | 用户越用越熟练的"好用的 prompt 写法"无法积累，产品粘性低 |

### 1.3 关键设计决策

| 决策维度 | 最终选择 | 核心理由 | 否决方案 |
|----------|----------|----------|----------|
| 变量语法格式 | `{{variableName}}` | 与行业惯例一致（Mustache/Handlebars 风格），用户认知成本低 | `${var}`（Shell 风格，易与环境变量混淆）；`{var}`（ComfyUI 风格，过于简短易与普通文本冲突） |
| 变量元信息范围（MVP） | name + defaultValue | 覆盖最小可用场景，后续 JSONB 可扩展 type/hint/options | 含完整类型系统（MVP 过度设计） |
| 模板存储方式 | 云端数据库持久化 | 支持跨设备同步、结构化查询、与现有数据模型统一 | 浏览器本地存储（不可跨设备、无结构化能力） |
| 模板是否关联来源分析任务 | 是，记录 来源分析任务编号 | 方便追溯模板来源，未来可展示来源图缩略图 | 不记录（丢失溯源信息） |
| 模板面板呈现形式 | 右侧滑出面板（~320px）+ 变量向导内嵌替换右列编辑区 | 面板不遮挡核心工作区；向导内嵌保持生成参数设置可见，空间利用高效 | 独立弹窗/全屏模态（打断工作流）；左列嵌入（挤压图片展示空间） |
| 变量交互方式 | 编辑器内联高亮 + 向导式表单填值双模式 | 兼顾高级用户的编辑效率和新手的易用性 | 仅文本框手写 `{{var}}`（非技术用户不友好）；仅表单填值（失去灵活性） |
| 「保存为模板」触发位置 | 指令编辑区 区域内的操作按钮 | 符合用户心智模型——正在编辑 prompt 时自然想到保存 | 工具栏/右键菜单（发现性差） |
| Prompt 输入方式 | 单一文本框（合并正负 prompt 为一个输入区） | 当前生图 API（fal.ai FLUX）实际不使用负向参数，双输入增加认知负担无实际收益；用户可在单一文本中自行组织正负内容（如用 `--neg` 分隔或自然语言描述） | 维持双文本框（Positive + Negative 分开）；完全去掉负向概念（部分用户有负向需求） |

### 1.4 产品范围

**P0（本期必须交付）**：

- 模板数据持久化存储与管理能力（数据表及后端增删改查接口）
- 模板后端数据接口（列表查询、创建、更新、删除）
- 独立模板管理界面（模板列表、编辑器、变量管理——界面自身能力完备，workspace 集成布局延后）
- 从当前分析结果「保存为模板」入口（指令编辑区 区域内操作按钮）
- 变量插入交互：工具栏按钮 → 弹出变量配置 → 插入 `{{variableName}}` 到光标位置
- 模板加载到编辑器：选中模板 → 填充 prompt 文本到指令编辑区

**P1（本期建议交付）**：

- 变量向导填值 UI：加载模板后自动识别 `{{var}}`，展示表单让用户填写变量值，确认后替换生成最终 prompt
- 模板列表管理增强：重命名、复制模板、删除确认

**P2（后续扩展）**：

- 预设模板库（系统内置通用风格模板）
- 模板分类/标签
- 模板导入/导出
- 模板分享/社区
- 批量生成（一次填值 → 多组变体）

**明确不做（本期）**：

- 预设模板库（聚焦自定义模板，预设留待 P2）
- 模板分享/社区功能（涉及用户系统和权限，范围过大）
- 与 ComfyUI 工作流的互导入（技术方向差异大）

## 第二部分：用户旅程和用户故事 {#第二部分}

### 2.1 核心用户旅程

**主旅程：从分析结果保存模板 → 加载模板生成新图**

```
步骤1: 用户在 workspace 完成参考图分析，AI 返回结构化 prompt
步骤2: 用户在 指令编辑区 中查看和编辑 prompt，对结果满意
步骤3: 用户点击 指令编辑区 区域内的「保存为模板」按钮
步骤4: 系统弹出「新建模板」对话框：
       - 输入模板名称（必填）
       - 预填充当前 prompt 文本（可编辑）
       - 显示变量工具栏（插入变量按钮）
步骤5: 用户在 prompt 文本中标记可替换部分：
       - 选中一段文字 → 点击「插入变量」→ 输入变量名和默认值
       - 或点击「插入变量」→ 在光标位置插入 {{newVariable}} → 再编辑变量名
步骤6: 用户确认保存 → 模板存入数据库，显示成功提示
────── 分割线：后续会话 ──────
步骤7: 用户进入模板面板，看到已保存的模板列表
步骤8: 用户选择一个模板 → 系统将模板的 模板正文 加载到 指令编辑区
步骤9: （P1）系统检测到模板含变量 → 自动展示「变量填值」向导面板
步骤10: 用户在向导表单中填写各变量值（每个变量一个输入框，带默认值预填）
步骤11: 用户确认 → 系统将变量值替换到 prompt 中 → 用户点击生成
```

**异常旅程：模板加载时变量解析失败**

```
步骤A: 用户选择一个模板加载
步骤B: 系统解析 模板正文 中的 {{var}} 标记
步骤C: 若遇到格式异常（如未闭合的 {{ 、嵌套标记等）：
       - 不阻断加载，原样显示原始文本
       - 在编辑器上方显示轻量提示："部分变量格式可能不正确"
       - 用户仍可正常编辑和使用该 prompt
```

**异常旅程：删除模板**

```
步骤A: 用户在模板列表中点击删除
步骤B: 系统弹出确认对话框：「确定删除模板"XXX"？删除后不可恢复。」
步骤C: 用户确认 → 模板从数据库移除，列表刷新
步骤D: 用户取消 → 对话框关闭，无变化
```

### 2.2 用户故事

**P0 用户故事**

| # | 用户故事 | 覆盖旅程步骤 |
|---|----------|-------------|
| US-01 | 作为已完成分析的用户，我希望将当前 prompt 一键保存为命名模板，以便日后快速复用这个风格配置 | 步骤 3–6 |
| US-02 | 作为模板编辑者，我希望在 prompt 文本中插入 `{{变量名}}` 标记可替换的部分，以便加载模板时只需填写变量值就能生成不同内容 | 步骤 5 |
| US-03 | 作为模板使用者，我希望从模板列表中选择模板并加载到编辑器，以便基于已有风格快速开始创作 | 步骤 7–8 |
| US-04 | 作为模板管理者，我希望能删除不再需要的模板，以便保持模板列表整洁 | 异常旅程：删除模板 |
| US-05 | 作为模板管理者，我希望能看到所有已保存模板的列表（名称、变量数量、创建时间），以便了解自己积累了哪些风格资源 | 步骤 7 |

**P1 用户故事**

| # | 用户故事 | 覆盖旅程步骤 |
|---|----------|-------------|
| US-06 | 作为模板使用者，我希望加载含变量的模板后自动看到向导式填值表单（每个变量对应一个输入框），以便不需要理解 `{{var}}` 语法就能快速填值生成 | 步骤 9–11 |
| US-07 | 作为模板管理者，我希望能重命名已保存的模板，以便修正命名或更好地组织模板 | 模板列表管理 |
| US-08 | 作为模板管理者，我希望能复制一个模板（创建副本），以便基于现有模板微调出新变体而不影响原模板 | 模板列表管理 |

- 「保存为模板」按钮位于 指令编辑区 标题行右侧（见右列顶部），用户在编辑 prompt 时自然可见

- 「插入变量」按钮点击后在光标位置插入 `{{newVariable}}`，同时弹出小窗让用户输入变量名和默认值
- 已定义的变量列表实时同步显示当前模板中提取到的所有变量

### 3.3 业务规则

**变量语法规则**：

- 变量标记格式为 `{{变量名}}`，其中变量名只允许英文字母、数字、下划线，不以数字开头
- 同一模板中变量名不可重复（重复时视为同一变量，填值时统一替换）
- 变量标记不支持嵌套（如 `{{outer{{inner}}}}` 视为格式异常）
- 未闭合的 `{{` 或 `}}` 视为格式异常，按异常态处理（不阻断，仅警告）

**模板命名规则**：

- 名称必填，长度 1–50 字符
- 名称不可与用户已有模板重复（重复时提示"已存在同名模板"）

**保存为模板的数据规则**：

- 保存时记录当前 prompt 文本作为模板正文（单一文本，用户自行组织内容）
- 记录来源分析任务的编号，方便追溯
- 自动从模板正文文本中提取所有 `{{var}}` 标记，构建变量定义列表（名称 + 默认值）
- 若用户未手动设置某变量的 defaultValue，defaultValue 为空字符串

**加载模板的行为规则**：

- 「使用」操作将模板正文原文填充到指令编辑区（保留 `{{var}}` 标记）
- 若模板包含至少一个变量且用户未选择跳过，自动弹出变量向导面板
- 向导中每个字段的默认值来自变量定义列表中的默认值
- 向导「应用」后，执行全局字符串替换：将每个 `{{varName}}` 替换为用户填写的值

**模板列表排序规则**：

- 默认按创建时间倒序（最新在前）
- P1 阶段支持：最近使用的模板置顶（软逻辑，可在后续迭代）

**删除保护规则**：

- 删除前必须弹出确认对话框，文案包含模板名称
- 删除操作不可撤销（无回收站概念）

**模板内容格式与变量解析规则（D-08）**：

> 本规则回答：当模板内容包含类 JSON 结构或特殊字符时，`{{var}}` 的提取和替换是否安全。

**核心原则：模板内容始终作为纯文本处理，不做 JSON 解析。**

具体规则：

| 场景 | 处理方式 | 示例 |
|------|---------|------|
| 纯文本模板（常见） | 正则提取 `{{\w+}}`，字符串替换 | `photo of {{subject}}` → `photo of a cat` |
| 模板内容含 JSON 片段 | **不解析 JSON**，在原始文本层面做正则匹配和替换；`{{var}}` 位于 JSON 字符串值内部时同样有效 | `{"prompt": "{{subject}} photo", "style": "cinematic"}` → 正确提取 `subject`，替换后得到有效 JSON 文本 |
| 变量值含双引号/花括号等特殊字符 | 替换时对变量值不做转义（因为不经过 JSON 解析），直接原样插入 | `{{desc}}` = `a "cool" item` → 结果文本中自然出现引号 |
| 模板本身是合法 JSON（用户手动保存的结构化模板） | 同上——纯文本层面操作，不校验 JSON 合法性；替换后的结果是否为合法 JSON 由用户自行保证 | 用户责任边界 |
| `{{` 或 `}}` 出现在非变量上下文（如 LaTeX、emoji） | 仅匹配 `{{字母或下划线开头}}` 格式，纯数字/符号/中文变量名不匹配，降低误判率 | `$$ f(x) = {{ }} $$` 不匹配；`{{中文}}` 不匹配（按语法规则已排除） |

**变量提取规则**：从模板正文中匹配所有符合 `{{变量名}}` 格式的标记（变量名仅允许英文字母、数字、下划线，不以数字开头）。

**替换操作的执行顺序**：
1. 从模板正文原始文本中提取所有 `{{varName}}` 标记
2. 与变量定义列表比对，构建填值映射表
3. 按「长变量名优先」顺序执行字符串替换（避免短名覆盖长名的子串，如 `{{name}}` 误替 `{{fullName}}` 中的前缀）
4. 输出最终文本到指令编辑区

**已知限制（本期不处理）**：

- 若用户在变量值中输入了 `{{anotherVar}}` 文本，不会被二次替换（单次替换策略）
- 若模板中同一变量名出现多次，所有出现位置统一替换为同一值（无"每次出现不同值"的能力）
- 不支持转义语法（如 `\{{literal}}` 输出字面 `{{`）
