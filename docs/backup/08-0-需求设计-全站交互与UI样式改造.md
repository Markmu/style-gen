# 08-0 需求设计：全站交互与 UI 样式改造

## 0. 文档说明

**产品核心目标**：将 Visoryn 从局部可用的视觉创作工作台升级为统一、通透、克制且具有高级工具感的全站体验，让用户在首页、工作台、模板库和过程状态中都能获得一致的专业信任感。

**本需求定位**：在 03 期视觉改造和 07 期工作台交互改造基础上，本期聚焦全站层面的交互一致性和 UI 样式统一，以 Stitch Precision Glass 参考设计为视觉方向，补齐页面之间、状态之间、控件之间的体验断层。

**相关文档**：
- 《设计系统实施手册》：Stitch Precision Glass 参考方向
- 《视觉设计改造》：上一轮品牌视觉升级需求
- 《工作台交互改造》：上一轮工作台布局与模板库需求
- Stitch Precision Glass 首页与工作台参考稿

## 1. 需求分析与确认

### 1.1 项目背景

**产品当前状态**

Visoryn 已具备完整创作链路：用户上传参考图，获得风格拆解，编辑生成提示，生成同风格新图，并可在工作台和模板库之间继续复用创作资产。

**存在的问题**

1. **全站视觉语言不统一**：首页、工作台、模板库、状态提示和浮层的质感不一致，用户在页面切换时会感到像进入了不同产品。
2. **界面边界过重或过碎**：过多硬边框、分割线和卡片堆叠削弱了高级工具应有的安静感，内容主次被界面结构抢走。
3. **交互反馈不成体系**：按钮、输入区、上传区、缩略图、模板卡片的悬停、按下、选中、禁用、处理中反馈口径不一，用户需要反复判断哪些区域可操作。
4. **关键状态缺少一致表达**：空态、加载中、分析中、生成中、失败、恢复成功等状态各自呈现，缺少统一的语气、视觉层级和下一步引导。
5. **常规宽屏布局缺少全站口径**：首页、工作台和模板库在常规宽屏下的主次比例、信息密度和辅助区域位置不统一，影响连续创作效率。

**本期目标**

用户从首页进入工作台、浏览模板库、上传参考图、等待分析、编辑内容、生成结果、查看历史的过程中，始终感受到同一套精密、轻盈、可信的产品体验；每个可操作区域都有清晰反馈，每个状态都有明确下一步。

### 1.2 核心问题定义

| 问题 | 用户损失 |
|------|---------|
| 页面之间视觉风格不一致 | 用户难以建立品牌记忆，专业信任感被削弱 |
| 边界和卡片层级过重 | 用户注意力被容器干扰，无法快速聚焦当前任务 |
| 控件反馈口径不统一 | 用户需要猜测按钮、卡片、图片和文本区域是否可点击 |
| 过程状态表达割裂 | 用户等待时缺少确定感，失败后缺少恢复路径 |
| 常规宽屏布局口径不统一 | 用户在首页、工作台和模板库之间切换时需要重新适应信息位置和操作节奏 |

### 1.3 关键设计决策

| 决策维度 | 最终选择 | 核心理由 | 否决方案 |
|---------|---------|---------|---------|
| 全站视觉方向 | 采用 Precision Glass：明亮、通透、低噪音、高留白 | 与 Stitch 参考稿一致，能把产品从暗色工具感升级为高级创作环境 | 继续沿用深色界面，无法解决旧体验的沉重感 |
| 页面结构表达 | 用空间、背景层次和轻质浮层区分区域 | 能减少硬边界，让内容成为视觉中心 | 继续依赖大量分割线，界面会显得碎 |
| 全站交互反馈 | 统一为轻微抬升、柔和高亮、明确选中和可恢复状态 | 用户可在不同页面复用同一套操作直觉 | 每个页面单独定义反馈，学习成本高 |
| 核心工作台布局 | 保留专业工作台信息架构，但以更轻的表面层级重绘 | 不打断 07 期已确认的工作流，同时修正视觉一致性 | 重新设计工作流，风险高且偏离本期目标 |
| 首页角色 | 首页承担品牌信任和快速进入工作台，不承载复杂说明 | 用户最需要快速判断产品价值并开始创作 | 将首页做成长说明页，容易拖慢行动 |
| 模板库角色 | 模板库呈现为轻量资产浏览空间，强调查找、比较和使用 | 模板是复用资产，应与工作台形成清晰但一致的体验 | 继续像工具抽屉，空间不足且不利于浏览 |
| 常规宽屏策略 | 以桌面常规宽屏为唯一适配目标，统一主任务、辅助信息和历史区域的空间口径 | 本期目标是修正主要创作场景的全站体验一致性，避免被多断点适配分散 | 同期处理窄屏适配，会扩大范围并稀释宽屏体验质量 |

### 1.4 产品范围

**本期范围**

1. **全站视觉基调统一**：首页、工作台、模板库、顶部导航、侧边导航、底部区域、浮层和提示统一为 Precision Glass 方向。
2. **页面层级重整**：用留白、浅色表面、轻质浮层和柔和背景变化表达层级，减少不必要的硬分割。
3. **全站控件状态统一**：按钮、图标按钮、输入区、上传区、模板卡片、历史缩略图、选择器、菜单和弹窗具备一致的默认、悬停、按下、选中、禁用、处理中、错误状态。
4. **首页体验改造**：强化首屏品牌信任、主行动入口、产品视觉预览和上传入口，让用户能快速进入创作。
5. **工作台体验改造**：上传、分析、风格拆解、编辑、生成、历史回溯在同一视觉语言下呈现，减少面板拥挤感。
6. **模板库体验改造**：模板浏览、搜索、筛选感知、卡片操作和使用模板流程与工作台保持一致。
7. **全站状态体系**：统一空态、加载、排队、处理中、成功、失败、恢复、无权限或未登录状态的表现和下一步行动。
8. **常规宽屏布局统一**：首页、模板库和工作台在常规宽屏下保持稳定比例、清晰主次和一致的信息密度。
9. **文案语气统一**：按钮、状态提示、错误提示和空态文案统一为简洁、确定、可行动的产品语气。

**明确不做**

- 不改变参考图上传、风格分析、提示编辑、图片生成和模板使用的核心业务流程。
- 不新增复杂数据统计、运营看板或增长指标模块。
- 不引入新的创作模式，例如对话式创作、节点式编辑或多人协作。
- 不把本期做成品牌营销站重写，首页仍服务于快速理解和开始创作。
- 不重新定义产品名称、核心定位或付费策略。
- 不处理窄屏、小屏或移动端适配；本期仅覆盖常规宽屏场景。

## 2. 用户旅程和用户故事

### 2.1 核心用户旅程

```text
主旅程：首次访问并完成一次创作

1. 用户进入首页。
2. 首屏通过清晰标题、轻盈视觉预览和主行动按钮传达产品价值。
3. 用户移动到主行动按钮、上传入口或导航入口时，页面给出明确的可操作反馈。
4. 用户选择上传参考图或直接进入工作台。
5. 页面进入工作台，导航选中状态、页面层级和控件反馈与首页保持一致，当前任务区域突出，次要面板保持可见但不抢占注意力。
6. 用户上传参考图，上传区给出明确的选中、上传中和完成反馈。
7. 系统进入分析中状态，工作台保持稳定布局，并展示当前正在处理什么。
8. 分析完成后，用户看到清晰分层的风格拆解和可编辑内容。
9. 用户调整生成提示和输出设置，主要行动按钮始终表达当前下一步。
10. 用户开始生成，页面展示生成中状态，避免误以为页面卡住。
11. 生成完成后，结果成为视觉中心，历史区域新增记录，用户可继续下载、回溯或再次生成。
12. 用户切换到模板库或返回首页时，页面结构、图片承载方式和主要控件反馈保持同一套体验口径。

延伸旅程：从模板库开始创作

1. 用户从首页或工作台进入模板库，导航选中状态和页面视觉层级与前一页面保持一致。
2. 用户通过搜索和卡片浏览找到合适模板，搜索区、筛选入口和模板卡片都有清晰反馈。
3. 用户在卡片上看到清晰的使用入口，并能区分悬停、选中和不可用状态。
4. 用户使用模板后回到工作台。
5. 工作台加载模板内容，并引导用户继续上传参考图或直接编辑生成提示。
6. 用户继续创作时，模板内容、当前任务和主要行动按钮处于同一可继续状态。

异常旅程：上传失败

1. 用户在首页或工作台选择参考图。
2. 上传失败后，上传区保留用户刚才选择文件的上下文。
3. 页面说明失败原因，并在同一区域提供重新选择文件的入口。
4. 用户重新选择文件后，上传区回到上传中状态。
5. 上传成功后，用户进入分析中状态；如果再次失败，用户仍停留在可重新选择文件的上传区。

异常旅程：分析或生成等待过久

1. 用户上传参考图或开始生成后进入等待状态。
2. 等待时间超过用户可明显感知的范围时，页面继续展示当前正在排队或处理中。
3. 页面提供继续等待和更换输入两个选择。
4. 用户选择继续等待时，页面保持当前等待状态并持续反馈进展。
5. 用户选择更换输入时，页面回到上传区或编辑区，并保留仍可复用的已有内容。

异常旅程：分析失败

1. 用户上传参考图后进入分析中状态。
2. 分析失败时，工作台保留已上传参考图和当前任务上下文。
3. 页面展示可理解的失败原因，并提供重试分析和更换参考图两个入口。
4. 用户选择重试分析时，页面回到分析中状态。
5. 用户选择更换参考图时，页面回到上传区；上传新图后重新进入分析中状态。

异常旅程：生成失败

1. 用户完成编辑并开始生成。
2. 生成失败时，页面保留用户已编辑的生成提示、输出设置和参考内容。
3. 页面展示失败原因，并提供重新生成和返回编辑两个入口。
4. 用户选择重新生成时，页面回到生成中状态。
5. 用户选择返回编辑时，页面回到可编辑状态，用户修改后可再次生成。

异常旅程：未登录或权限不足

1. 用户访问需要登录或更高权限的能力。
2. 页面说明当前限制，不把用户突然带离当前页面。
3. 页面提供登录、返回可浏览内容或回到工作台的入口。
4. 用户选择登录时，登录完成后回到原受限页面或原任务位置。
5. 用户选择返回可浏览内容或回到工作台时，页面进入对应可用位置，并保持导航选中状态明确。
```

### 2.2 用户故事

**核心用户故事**

| # | 用户故事 |
|---|---------|
| US-01 | 作为首次访问的创作者，我希望首页在第一屏就呈现产品价值和专业感，以便我快速判断是否值得开始创作 |
| US-02 | 作为创作者，我希望从首页到工作台再到模板库的视觉语言一致，以便我确认自己始终在同一个可信产品中 |

| US-05 | 作为创作者，我希望失败状态保留我的输入和上下文，以便我能快速重试而不是重新开始 |
| US-06 | 作为创作者，我希望模板库像资产库一样易于浏览和比较，以便我更快找到可复用模板 |
| US-07 | 作为创作者，我希望常规宽屏下首页、工作台和模板库都有稳定清晰的主次布局，以便我在连续创作时不需要重新适应页面结构 |

**延伸用户故事**

| # | 用户故事 |
|---|---------|
| US-08 | 作为回访用户，我希望历史记录、模板卡片和主要操作使用同一套选中样式，以便我快速理解当前选择 |
| US-09 | 作为新用户，我希望错误提示用明确的人话告诉我下一步该做什么，以便我不会因为一次失败而离开 |
| US-10 | 作为高频用户，我希望界面减少装饰噪音，以便长时间创作时不被强对比和密集边框打扰 |

### 3.2 关键状态

| 状态 | 页面表现 | 用户下一步 |
|------|---------|-----------|
| 首次访问首页 | 首屏突出价值表达、产品预览和开始创作入口 | 上传参考图或进入工作台 |
| 工作台空态 | 当前任务区展示上传入口，辅助区展示简短流程提示 | 选择或拖放参考图 |
| 上传中 | 上传区保持原位，展示进行中反馈和文件名称 | 等待或取消后重新选择 |
| 分析中 | 参考图可见，分析状态覆盖在当前任务区域内 | 等待，必要时更换参考图 |
| 分析完成 | 风格拆解和编辑区成为主操作区域 | 修改内容并开始生成 |
| 生成中 | 主要行动按钮进入处理中，结果区展示等待状态 | 等待生成完成 |
| 生成完成 | 结果图成为视觉中心，历史区域新增记录 | 下载、回溯或再次生成 |
| 模板库空态 | 说明尚无模板或未找到匹配结果，并提供返回创作入口 | 清空搜索或回到工作台 |
| 操作失败 | 当前上下文保留，错误说明和重试入口同屏出现 | 重试、更换输入或返回 |
| 未登录受限 | 说明当前能力需要登录，并提供登录入口 | 登录或返回可浏览内容 |
| 常规宽屏访问 | 主任务、辅助信息和历史区域保持稳定比例，页面切换时信息位置和视觉层级一致 | 完成上传、编辑、生成、模板使用和历史回溯 |

### 3.3 业务规则

1. **全站层级规则**：每个页面只能有一个最突出的当前任务区域；辅助信息不得在视觉重量上超过当前任务。
2. **轻边界规则**：页面区域优先用留白、背景深浅和轻质浮层区分；只有在可操作、选中或需要强调边界时才使用细边界。
3. **主要行动规则**：每个关键状态只保留一个主行动按钮；次要操作必须降级为轻按钮或文字入口。
4. **控件反馈规则**：所有可点击区域都必须在悬停、按下和选中时给出可感知反馈；禁用状态必须解释原因或通过上下文让用户理解。
5. **图片区域规则**：参考图、结果图、模板预览和历史缩略图必须使用统一的承载方式，图片边缘不能显得像随意贴在页面上。
6. **输入区域规则**：上传区、搜索区和文本编辑区在默认、聚焦、错误和禁用状态下必须清晰区分，并保留用户已输入内容。
7. **状态文案规则**：状态文案必须回答“正在发生什么”和“我还能做什么”；失败文案不得只说失败，必须给出恢复行动。
8. **等待反馈规则**：上传、分析和生成等待超过用户可明显感知的时间时，页面必须持续提供状态反馈，避免用户误判为卡死。
9. **页面切换规则**：首页、工作台和模板库切换时，导航选中状态必须明确，页面结构变化不能造成明显跳闪。
10. **模板使用规则**：用户从模板库使用模板后，必须回到可继续创作的位置，并清楚看到模板内容已被带入。
11. **历史回溯规则**：用户点击历史记录后，当前工作区必须明确显示已恢复的内容，并允许继续编辑或重新生成。
12. **常规宽屏规则**：常规宽屏下优先保证当前任务、辅助信息和历史区域的稳定比例；页面切换不能让主操作位置大幅漂移。
13. **语气规则**：全站文案保持简洁、确定、可行动，不使用夸张营销语替代功能说明。

## 4. 验收标准

- AC-01：首页首屏体验
  前置：用户首次打开首页。
  动作：用户浏览首屏内容。
  结果：用户能在首屏看到产品价值说明、主要行动入口、产品视觉预览和上传入口；页面视觉方向与 Precision Glass 参考一致，且没有被复杂说明或多重按钮干扰。

- AC-02：全站视觉一致性
  前置：用户依次访问首页、工作台和模板库。
  动作：用户在三个页面之间切换。
  结果：三个页面的导航、表面层级、控件样式、卡片质感、图片承载方式和文字层级保持一致；用户不会感到进入了不同产品。

- AC-03：控件状态一致性
  前置：页面存在按钮、图标按钮、上传区、输入区、模板卡片、历史缩略图和选择器。
  动作：用户分别进行悬停、点击、选择、取消选择、禁用场景下的操作。
  结果：每类控件都呈现清晰且一致的默认、悬停、按下、选中、禁用和处理中状态；可操作区域与静态内容能被明确区分。

- AC-04：工作台核心流程
  前置：用户进入工作台且尚未上传参考图。
  动作：用户上传参考图，等待分析，编辑生成提示，开始生成，并查看结果。
  结果：工作台在上传、分析、分析完成、生成中和生成完成状态下保持稳定布局；当前任务始终突出，用户已上传或已编辑内容不会在状态切换中丢失。

- AC-05：模板库浏览与使用
  前置：用户进入模板库。
  动作：用户搜索模板，浏览卡片，并点击使用某个模板。
  结果：模板库以资产浏览方式呈现；空结果有清晰提示；使用模板后用户回到工作台，并能看到模板内容已进入可继续编辑的位置。

- AC-06：失败与恢复路径
  前置：上传、分析、生成或模板加载出现失败。
  动作：用户阅读失败状态并尝试恢复。
  结果：页面保留失败前的上下文和用户输入，展示可理解的失败说明，并提供重试、更换输入、返回工作台或登录等可行动入口。

- AC-07：常规宽屏布局稳定性
  前置：用户在常规宽屏窗口中访问首页、工作台和模板库。
  动作：用户完成上传、编辑、生成、模板使用和历史回溯。
  结果：三个页面的主任务、辅助信息和历史区域保持稳定比例和清晰主次；页面切换不会造成主操作位置大幅漂移或信息密度突然变化。

- AC-08：全站文案一致性
  前置：用户遇到空态、加载、排队、处理中、成功、失败、未登录或无结果状态。
  动作：用户阅读状态提示。
  结果：所有状态文案都用简洁、确定、可行动的语气说明当前情况和下一步；不存在只表达情绪或只报错但不给恢复路径的提示。
