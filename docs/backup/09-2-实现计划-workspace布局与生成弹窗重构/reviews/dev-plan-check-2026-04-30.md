## 六、问题清单

| 严重级别 | 位置 | 问题 | 修补建议 |
| --- | --- | --- | --- |
| 建议 | FEAT-01 前端边界场景表 | 架构 §6.6 step 1 明确写"上传或分析失败只接管左侧对应区域"，但 FEAT-01 边界场景表和 AC-08 验收只列出"分析失败"，未显式包含"上传失败"。现有 hooks 保留了上传失败处理，但缺少显式验收断言。 | 在 FEAT-01 边界场景表中增加"上传失败"行："左上显示错误和重试，左下保持占位，右侧不清空"。在验收标准 AC-08 或降级回归验收中补充一条上传失败断言。 |
| 建议 | FEAT-03 或 README | 架构 §3.3 状态机包含 `history_restored` 状态（点击历史项恢复模板上下文或完整提示），但三个 FEAT 均无显式验收项或 E2E 覆盖。FEAT-03 风险备注提到"不要把历史恢复改成弹窗行为"，但未验证历史恢复在新布局下仍可用。 | 在 FEAT-03 验收标准或全局验证中增加一条回归断言："历史恢复点击后工作台保持左右双区，模板/文本内容正确恢复，不触发弹窗"。或在 FEAT-03 风险备注中补充"全局验证时应覆盖历史恢复回归"。 |
| 建议 | FEAT-02 | 架构 §3.2 定义"模板加载"关键分支（工作台 query 携带模板 ID → 进入模板模式），§7.3 列出 `GET /api/templates/:id`。FEAT-02 实现规格中提到了初始值规则，但 E2E spec 未明确覆盖模板加载 query 参数场景。 | 在 `e2e/workspace-unified-editor.spec.ts` 中增加一个 test case：携带模板 ID query 进入工作台，验证进入模板模式、模板原文和变量列表正确加载。或在 FEAT-02 验收标准中补充一条模板加载验收。 |
| 建议 | FEAT-01 降级回归验收 | 架构 §8.2 定义 L3 可恢复失败为"分析失败"，但 §6.6 将上传失败和测试失败合并为同一处理原则。当前 FEAT-01 降级回归验收只提到 L3 分析失败，上传失败作为前置步骤应同样适用 L3 原则。 | 与问题 1 合并处理：将上传失败加入 FEAT-01 降级回归验收，作为 L3 的补充场景。 |
