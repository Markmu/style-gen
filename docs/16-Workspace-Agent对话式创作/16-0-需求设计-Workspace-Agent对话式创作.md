# 16-0 需求设计：Workspace Agent 对话式创作

## 0. 文档说明

**产品核心目标**：让视觉创作者从参考图提取可信、可编辑的风格，通过改变内容而保留风格完成新图创作。

**本需求定位**：在证据引导生成闭环及可验证风格记忆的基础上，将 Workspace 改为 Agent 对话推进、视觉工作区持续展示的创作界面，并交付真实的多轮请求理解、修改提案与恢复能力。

**依据与状态**：用户于 2026-09-08 确认交互「就这样了」，并要求准备实施前需求文档；已确认的最后修订为生成按钮位于对话框下方，与模型选择放在一起。本文件承接该交互决定，不表示实现、应用验收或部署完成。

## 1. 需求分析与确认

### 1.1 项目背景

当前已能完成参考图分析、证据审阅、提示编辑、单图生成、多轮比较及风格记忆保存，但用户仍需自己在多个同级区域间组织创作步骤。

本期目标：用户用自然语言表达目标，由 Agent 将目标变成有依据的可检查修改，用户在同一页面完成生成、比较、修正和复用。

### 1.2 核心问题定义

| 问题 | 用户损失 |
| --- | --- |
| 参考、证据和提示同时展开且需要自行串联 | 首次创作要先理解工具结构 |
| 修改目标需要翻译成字段或提示文本 | 不熟悉提示编写的用户难以准确调整 |
| 多轮反馈容易丢失引用对象和保留约束 | 容易修改错版本或破坏原本满意的部分 |
| 若聊天消息承担全部操作与结果 | 图像、当前草稿和执行状态会被历史消息淹没 |

### 1.3 关键设计决策

| 决策维度 | 最终选择 | 核心理由 | 否决方案 |
| --- | --- | --- | --- |
| 页面组织 | 左侧对话，右侧视觉工作区 | 同时保持操作连续性与视觉参照 | 所有内容塞入聊天记录，难以比较 |
| 执行入口 | 输入框内发送，下方生成操作栏 | 明确消息与图像任务是两种动作 | 一颗按钮随输入变化切换含义 |
| Agent 修改 | 提出可编辑差异，由用户应用 | 保留用户对创作方向的控制 | 静默覆盖草稿 |
| 可解释性 | 观察、风格规则、用户修改分别标识 | 用户能判断依据和修改来源 | 单一不可解释的提示文本 |
| 迭代上下文 | 查看结果与修改草稿分开 | 防止回看历史破坏当前工作 | 点击旧结果即自动恢复 |
| 自动化边界 | 明确的一次生成授权 | 降低意外任务与重复生成 | 默认自动生成或循环优化 |

### 1.4 产品范围

**本期范围**：

1. 重构 Workspace 全部核心交互及中小屏布局，保留现有全局导航和身份入口。
2. 参考图附件发送、上传与分析、快速复刻、首页图片与历史/风格记忆进入的合流。
3. 真实多轮对话：解释证据、改变主体/场景、调整保留规则、明确引用对象、澄清歧义及生成意图；按钮与直接字段编辑同时可用。
4. 可编辑修改提案、冲突检查、应用与撤销、专家提示编辑。
5. 单次生成、结果对比、继续迭代、首选、下载、作为新参考及历史入口。
6. 对话与当前方向恢复、草稿保存、风格记忆保存/代表结果更新，以及失败、重复操作和处理中编辑的恢复规则。

**明确不做**：

- 多参考融合、批量生成、图层编辑、局部重绘、联网素材检索及无人确认的循环优化。
- 自动相似度总分或自动判定风格验证通过。
- 重做 Iteration Memory、Style Memory 的独立列表和详情页；其 Workspace 入口及交互衔接在范围内。
- 独立聊天会话管理中心、多用户协作、跨设备同步承诺、新模型、额度或计费体系。

## 2. 用户旅程和用户故事

### 2.1 核心用户旅程

```text
主旅程 A
A1 进入 Workspace，添加参考图并描述创作目标 → 发送
A2 完成上传与分析 → 查看证据摘要及初始草稿
A3 提出修改 → 查看保留/改变差异 → 编辑并应用，或放弃
A4 必要时直接修改变量/提示 → 查看底部参数和生成就绪说明
A5 点击下方生成按钮 → 收到固定提交记录 → 等待结果
A6 查看结果并与参考/另一结果比较 → 引用偏差提出新修改 → 回到 A3
A7 选择满意结果 → 下载或确认代表结果并保存风格记忆 → 完成本次创作

快速旅程 B
B1 附件就绪 → 选择快速复刻并核对一次性授权
B2 在下方操作栏确认分析并生成一张 → 分析完成后自动提交一次
B3 到 A6 评估；退出授权则到 A2，失败则走异常旅程

复用/恢复旅程 C
C1 从历史或风格记忆进入 → 预览来源与待恢复内容
C2 有未保存内容时选择保留为另一方向或替换；取消则回原草稿
C3 补齐缺失变量 → 到 A3；只有旧快照时不生成虚构对话
C4 同一浏览器重新打开当前方向 → 恢复对话和任务状态 → 到 A3 或 A6

异常旅程 D
D1 上传/分析/对话失败 → 保留输入与已完成内容 → 重试失败步骤 → 回 A2/A3
D2 生成提交状态未知 → 先核对是否已提交 → 已有任务到 A5，确认未创建才允许重试
D3 生成失败 → 选择重试原提交或修改草稿后生成 → 到 A5
D4 保存失败 → 保留表单并重试；已保存但刷新失败只刷新 → 到 A7
D5 登录/服务限制 → 保留草稿，可继续允许的编辑 → 恢复后主动继续；也可保存草稿后退出
```

### 2.2 用户故事

**核心故事（均为本期必须交付）**：

- US-01：作为视觉创作者，我希望上传参考后直接描述目标，以便无需先理解提示字段即可开始创作。
- US-02：作为视觉创作者，我希望看清 Agent 的依据和拟修改内容，以便决定是否采纳。
- US-03：作为视觉创作者，我希望在模型设置旁明确提交一张图片，以便知道本次执行的内容。
- US-04：作为视觉创作者，我希望比较结果并只调整不满意之处，以便连续改进而不丢失有效风格。
- US-05：作为视觉创作者，我希望保存经自己确认的风格及代表图，以便后续可信复用。
- US-06：作为视觉创作者，我希望失败或重新打开时保留草稿、对话和任务状态，以便继续工作而不重复执行。

**延伸故事（同属本期交付）**：

- US-07：作为视觉创作者，我希望一次性授权先分析再生成，以便更快得到可评价的首图。
- US-08：作为视觉创作者，我希望直接编辑字段或全文提示，以便精确控制对话难以表达的细节。
- US-09：作为视觉创作者，我希望在手机上切换对话与画布仍保持上下文，以便小屏也能继续当前方向。

## 3. UX/UE 设计

### 3.1 线框图与说明

桌面创作状态：

```text
+-------------------------------+---------------------------------------+
| 对话                          | Reference / Result / Compare          |
| 用户：改变主体，保留光线      |                                       |
| Agent：解释与证据引用         |           参考 / 结果 / 对比           |
|                               |                                       |
| 修改提案                     | 查看结果 v1 / 编辑草稿 v3              |
| Keep / Change / 前后差异      | 本方向结果条（最多五个成功结果）         |
| [编辑] [放弃] [应用]          |                                       |
|                               | Evidence / Draft / Prompt             |
| +---------------------------+ | 按需检查证据、变量、规则和提示           |
| | 引用对象                  | |                                       |
| | 描述想保留或改变的内容    | |                                       |
| | +参考                Send | |                                       |
| +---------------------------+ |                                       |
| 模型  画幅  质量  [生成一张] |                                       |

```

空白与处理中：

```text
空白：开始提示 → 附件预览与目标输入 → Send；下方生成不可用并说明缺参考
分析中：真实阶段与已上传参考 → 输入目标仍保留 → 等待分析或重试失败步骤
生成中：原提交记录与任务状态 → 可写下一轮 → 下方不允许重复生成
失败：原步骤内错误及保留说明 → 修复/重试入口，不用整页错误替换草稿
```

小屏：

```text
+-----------------------------------+
| 方向 / 来源 / 保存状态             |
| Conversation | Canvas             |
| 当前页签内容                      |
| 对话或参考/结果/证据               |
| 引用对象与输入框            Send |
| 模型 / 画幅 / 质量  [生成一张]     |
+-----------------------------------+
```

右侧图像不裁掉内容以填满面板。检查区使用页签按需呈现，主界面不再同时铺开全部证据和全文提示。生成操作栏始终位于输入框外、下方；小屏可在同一区域内换行，不能移回聊天消息或输入框内部。

### 3.2 关键状态

| 状态 | 页面表现 | 用户下一步 |
| --- | --- | --- |
| 空白/附件待发送 | 开始提示、可删除附件；生成缺项说明 | 发送参考与目标 |
| 上传/分析/理解请求中 | 一个更新中的真实步骤状态，不展示内部思考 | 编辑待发送内容、等结果 |
| 待澄清 | 具体问题与相关选项 | 选择或自由回答 |
| 待应用 | 修改前后、保留项和影响范围 | 编辑、应用或放弃 |
| 可生成 | 当前草稿摘要、模型、画幅、质量和一张 | 下方生成 |
| 排队/生成中 | 已提交版本及真实阶段，草稿可继续编辑 | 查看证据、准备下一轮 |
| 结果就绪 | 结果引用与视觉工作区提示 | 比较、调整或保存 |
| 可恢复失败 | 失败步骤、保留内容、明确恢复动作 | 按 §3.3.8 恢复 |
| 来源缺项 | 身份条与缺失清单 | 定位并补齐所需项 |

### 3.3 业务规则

#### 3.3.1 入口与参考

1. 每个创作方向一次使用一张参考图。上传、拖放、粘贴均先形成待发送附件；删除附件不清除输入目标。多文件输入明确说明限制并要求选一张，不能静默丢弃。
2. 输入框内按钮固定为 Send；可仅发送图片，不可发送空消息。发送图片启动上传与分析，不自动生成。首页已明确提交的图片进入后继续处理，不重复要求发送。
3. 无参考且无可复用风格时，文字请求得到添加参考或使用风格记忆的提示，目标文字保留。格式与体积限制沿用产品实际支持范围，出错时给出可纠正说明。
4. 替换已分析参考、结果作为新参考均开启新方向。未保存内容先允许保留为另一方向、明确替换或取消；取消不改变当前方向。正在运行的旧任务保留归属，完成后不得污染新方向。

#### 3.3.2 多轮对话与修改

5. 对话须真实理解当前参考、证据、草稿、选中结果和显式保留约束。可处理同一意图的不同自然语言表述，不能仅把预置按钮文案或关键词当作完整 Agent 能力。
6. 支持解释证据、改变主体/场景、加强/放宽/移除或替换规则、修改生成目标。超出范围的请求明确说明能力边界并给出可用替代，不伪造完成。
7. 参考、结果和证据均可添加为输入引用；引用包含可识别来源/版本。删除引用只改变本条请求的上下文。引用已不可用时先说明并要求重新选择，不猜测对象。
8. 「更像参考」等存在多种有效解释时提出一个具体澄清，提供相关维度选择；已明确的内容不再询问。与显式保留约束冲突时让用户选择保留原约束或替换约束。
9. 修改先呈现可编辑的前后差异、保留项及下一轮影响范围；应用才改变草稿，放弃无写入。应用不自动生成。直接字段编辑保存时同样说明影响下一轮。
10. 等待 Agent 时发生新编辑，旧提案不得覆盖新草稿；重新对照最新内容提出修改。撤销仅在未发生后续修改时恢复上次内容；旧撤销显示不可直接执行，可作为新提案恢复。
11. Agent 回复优先简短解释与一个相关下一步。用户消息、观察、提案、提交记录、结果与错误有可辨认身份；不以编造的置信度、坐标、进度、耗时或内部思考增加可信感。

#### 3.3.3 发送与生成操作栏

12. Send 仅发送消息，不因输入为空变成生成按钮。输入框下方常驻模型、画幅、质量选择和 Generate 1 image；高级项展开，生成前可查看当前实际设置与画幅来源。保存草稿保持次级入口。
13. 有未发送文字或附件、待应用提案、必填缺项、执行限制或活动生成任务时，生成按钮不可执行并显示具体原因与处理路径。解释不能只藏在悬停提示里；其他可用编辑不整体禁用。
14. 桌面 Enter 发送、Shift+Enter 换行；中文候选确认不发送。手机 Enter 换行。任务进行中可以编辑下一条消息；同一方向一次仅处理一个会改变草稿的对话请求，发送中的消息不可重复提交。
15. 每次生成固定使用提交时的参考、提示、参数和草稿版本。后续修改只影响下一次，提交记录不可随当前草稿变化。重复点击、重连及恢复旧消息不能重复创建任务。
16. 明确的「按当前设置生成一张」可在当前内容及参数已展示、无歧义和阻塞时授权一次生成，回执与按钮生成一致；隐含修改请求不算生成授权。所有可点击的图像执行入口位于下方操作栏；对话内生成摘要只提供查看/编辑/定位该栏。
17. 快速复刻在附件后可选，展示贴近复刻意图、详细度、画幅策略、模型、质量与一张；最终确认按钮在下方操作栏，显示 Analyze and generate 1 image。完整分析且满足条件后仅提交一次。修改参考/授权设置、失败、退出或历史恢复清除未消费授权；不能声称退出已取消提交的任务。
18. 生成中允许编辑下一轮草稿和浏览已有内容，不再提交第二个图像任务。首版不提供无法兑现的停止图像生成按钮；若可停止对话回复，应说明已提交图像任务仍运行。

#### 3.3.4 证据与专家控制

19. Evidence 展示真实观察、来源及可复用规则，编辑后的规则标为用户修改，原观察不被覆盖。证据只在有真实定位信息时定位图像，有支持关系时标出相关提示表达；缺失时说明不可定位。
20. Draft 先展示内容变量，再展示意图与保留规则；与对话应用结果保持同一份当前草稿。部分分析可用时显示已有证据，允许的操作取决于真实必需项，不虚构完整性评分。
21. Prompt 保留 Concise / Balanced / Detailed、全文编辑、结构化查看、负向提示与复制。手写全文遇到 Agent 修改必须预览拟合并差异；恢复自动派生提示时先显示将替换的内容，取消保留原文。

#### 3.3.5 结果与比较

22. 当前方向展示最近五个成功结果，活动/失败任务独立呈现，更早记录进入 Iteration Memory。每条结果可查看实际提交内容及来源。
23. 新结果完成时，对话提示且不弹模态窗口、不抢输入焦点。未主动查看旧结果时可选择最新；正在查看旧结果/比较时保持选择，提供 View latest result。
24. 选择结果只改变观看对象；显示观看版本与编辑版本。Continue from this result 显式恢复为新草稿，保护未保存更改且保留所有既有结果；恢复参数以原提交为准，不可用项明确要求替换。
25. Compare 支持参考与所选结果，以及两轮结果之间比较；无第二对象时说明缺项。保持完整画幅，窄屏上下排列。用户选择偏差维度后连接相关证据和修改提案，不推断自动风格总分。
26. 结果支持比较、继续编辑、首选、下载、保存风格记忆；更多操作包含作为新参考和进入 Iteration Memory。首选只表示当前方向偏好，不表示用户验证。下载失败保留结果并只重试下载。

#### 3.3.6 保存与恢复

27. 当前方向包含真实消息、草稿、来源、任务及结果引用；同一浏览器刷新或重新打开可恢复当前方向。较长对话可分段加载，不能永久只保留最近几条。离开后仍能从对应方向恢复；不新增独立聊天列表。
28. 保存状态对应真实结果：仅在本机保留时显示 Local draft，不暗示跨设备同步。保存失败保留可复制/导出的内容并说明；重新打开只恢复记录与状态，绝不重放执行。
29. 历史/风格记忆进入先展示真实来源及缺项，保护当前未保存内容；缺少过去对话时显示恢复摘要，不编造对话历史。来源图片失效仍保留可用提示和参数，是否生成由实际必需条件决定。
30. 保存风格记忆采用内联命名与可展开高级信息，名称预填方向名或风格名。草稿无代表图时待验证；保存为用户已验证风格须展示具体代表图、来源并明确获得用户确认。首选、点赞、Agent 判断均不等于验证。
31. 有来源风格记忆时明确新建副本或更新代表结果的目标，保留既有确认语义。保存失败保留表单，写入已成功但刷新失败只重试读取，不再提交保存。

#### 3.3.7 布局、语言与可访问操作

32. 保留 Workspace、Iteration Memory、Style Memory 导航及主题/登录入口。标题可修改，顶部显示来源与真实保存状态。整体继承项目字体、冷中性色、功能蓝及浅/深主题。
33. 桌面为双栏，给图像更多空间；中屏优先收窄导航，无法同时容纳可读对话和画布时改页签。小于 768px 使用 Conversation / Canvas，切换保持选中对象、输入和草稿；输入区及下方生成操作栏在两页签均可到达，适应软键盘，不能被遮挡。
34. 点击证据引用可切换画布并提供返回对话；普通完成通知不强制切页。所有关键操作可键盘到达，有可见焦点；折叠/返回恢复到合理触发位置，加载或成功不夺取编辑焦点。
35. 状态变化提供可读说明和辅助阅读播报，不仅依赖颜色；减少动态效果时仍能理解状态。可点击文字不只在悬停时出现。Workspace 固定界面用英文，用户及模型内容保留原语言。

#### 3.3.8 失败与恢复

36. 上传失败保留目标与附件，重试上传；分析失败保留成功上传的参考，重试分析；对话失败标明未应用修改，重试该消息或直接编辑。不连带重做已完成步骤。
37. 提交结果未知先核对是否已有任务；未确认前禁重复生成。明确任务失败后，区分 Retry original 与 Generate current draft，展示将使用的原内容或现草稿，再从下方操作栏执行。
38. 成功任务预览失败只重载图片，不重新生成；历史详情失败不恢复不完整内容，当前草稿保留。登录/服务限制说明受影响操作与可用操作；恢复后由用户主动继续，不能自动重放生成授权。

## 4. 验收标准

各编号为本期稳定验收契约；后续文档须沿用，不能以原型已演示代替产品交付。

| 编号 | 前置 | 动作 | 可观察结果 |
| --- | --- | --- | --- |
| AC-01 | 空白方向 | 上传/拖放/粘贴单图并发送，另以无图文字、多文件和无效图片尝试 | 正常启动分析；其余保留目标并明确缺项/限制，无静默忽略或自动生成 |
| AC-02 | 首页已提交参考或历史/风格记忆入口 | 进入 Workspace | 前者不重复发送；后者显示真实来源、可恢复内容与缺项，无虚构过去对话 |
| AC-03 | 已有参考和草稿 | 用不同表述要求替换主体、解释证据、调整规则，并发出超范围请求 | 按实际上下文回答/提案，显示真实依据；超范围明确说明，无预置回应冒充完成 |
| AC-04 | 已有保留约束或对象引用 | 提交含糊目标、冲突修改或失效引用 | 明确澄清维度/约束/对象，在确定前不改变草稿 |
| AC-05 | 可应用提案 | 编辑提案后应用、放弃或撤销 | 应用更新相应内容并保留其余项；放弃零修改；撤销恢复匹配版本且不生成 |
| AC-06 | Agent 处理期间草稿已更新 | 应用旧提案或执行旧撤销 | 不覆盖新内容，要求按最新草稿重新对照或形成新提案 |
| AC-07 | 任意页面状态 | 查看输入区及操作栏，发送文字和空消息 | Send 始终在输入框内且不切为生成；生成在下方模型/画幅/质量区，空消息不能发送 |
| AC-08 | 未发送内容、待应用提案、缺项或执行限制 | 尝试生成并修复阻塞 | 显示具体原因与修复路径，修复后可生成；允许的编辑保持可用 |
| AC-09 | 当前草稿就绪 | 点击生成并重复点击，随后修改草稿和参数 | 只提交一次，显示固定原提交记录；后续编辑只影响下一轮 |
| AC-10 | 当前内容及参数已展示 | 明确用自然语言授权生成；另发送仅修改的请求 | 前者无歧义且就绪时执行一次，后者仅提案；对话内不新增图像执行按钮 |
| AC-11 | 待分析参考 | 核对快速复刻并从下方操作栏确认；另测试退出/改设置/失败/恢复 | 正常完整分析后最多自动一张，其他分支清除未消费授权，不声称取消已提交任务 |
| AC-12 | 已有证据和手写提示 | 查看证据、直接改变量、调整详细度、修改全文并接受/取消合并 | 来源与用户修改区分；草稿一致；手写内容未经预览同意不被替换，缺定位信息不虚构 |
| AC-13 | 已有旧结果且正查看/比较 | 新一轮完成，再选择旧结果和显式继续编辑 | 完成不抢选择/焦点；仅查看不恢复草稿；继续才恢复原内容与参数为新草稿 |
| AC-14 | 多轮结果 | 切换两种比较，引用偏差，查看较早记录、下载、设首选及作为新参考 | 比较对象明确、图像完整；偏差进入修改；较早记录可达；首选不验证；换参考保护原方向 |
| AC-15 | 当前对话含较早消息和活动任务 | 刷新、关闭后重新打开、返回原方向 | 对话/草稿/来源/真实任务状态恢复，较早消息可读，不重新执行历史动作 |
| AC-16 | 未保存更改或失效来源 | 新建/替换/恢复，分别取消与确认 | 取消保留原内容；保留或替换选择明确；旧任务归属不变；缺项不被伪造补齐 |
| AC-17 | 草稿或选定结果 | 保存风格记忆、新建副本或更新代表结果 | 目标与名称明确；无代表草稿待验证，有代表仅经用户确认才验证 |
| AC-18 | 保存失败或已保存但刷新失败 | 重试 | 前者保留表单可提交；后者明确已保存且只刷新；本机保存不称已同步 |
| AC-19 | 上传、分析或对话分别失败 | 重试失败步骤 | 输入及已完成上下文保留，只重试对应步骤，未应用修改不显示成功 |
| AC-20 | 提交结果未知或生成明确失败 | 核对/重试原提交/按现草稿生成 | 未知先核对不重复提交；失败恢复区分内容与参数，执行仍位于下方操作栏 |
| AC-21 | 图片预览/下载/历史加载失败，或登录/服务限制 | 恢复可用操作并重试 | 不连带重新生成，不覆盖当前草稿；登录或服务恢复不自动重放任务 |
| AC-22 | 桌面、中屏、手机及浅/深主题 | 切页签、编辑、键盘操作、中文候选确认、软键盘输入 | 无水平溢出/遮挡；对象与输入保留；生成栏在输入框外下方；候选确认不发送；焦点和状态可理解 |
