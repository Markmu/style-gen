# 03-0 需求设计：视觉设计改造

## 0. 文档说明

本文件是 03 期需求总文档，用于统一需求、竞品、用户、体验和验收标准，作为后续架构文档、原型和开发的基础。

**产品核心目标**：

将 Visoryn 从"功能性暗色调界面"升级为"具有 Luminescent Darkroom 美学认同的专业视觉创作工具"，让用户在上传参考图的第一秒就感受到产品的专业性和品牌独特性。

**本需求定位**：

01 期"参考图风格再创作"核心功能上线后，验证了用户对 AI 风格提取的需求真实存在。当前产品功能链路完整，但视觉呈现停留在"能工作"阶段，缺乏品牌认同感和细节打磨。本期（03）聚焦视觉体验升级，以 Stitch Obsidian Core 设计体系为参考，打造与产品定位匹配的品牌视觉。

---

## 1. 需求分析与确认

> 视角：产品经理

### 1.1 项目背景

**产品当前状态和核心能力**

Visoryn 核心链路：用户上传参考图 → Gemini 视觉分析 → 结构化 Visual Recipe → Prompt 编辑 → fal.ai 图像生成。全链路已跑通，登录态已打通，数据存储已就绪。

**存在的具体问题**

1. **品牌认同缺失**：当前暗色调界面缺乏独特性，用户无法从视觉上区分 Visoryn 与其他 AI 工具——"看起来像所有其他 AI 产品"
2. **Hero 区转化率低**：缺少清晰的价值主张传达和行动引导，用户进入页面后无法快速理解"这是什么、对我有什么用"
3. **功能区信息密度失衡**：功能卡片罗列特征但无视觉记忆点，数值展示平淡无法建立信任感
4. **Workspace 交互细节粗糙**：Recipe Card 字段展示不够专业、生成面板比例选择不够直观、结果展示缺乏仪式感
5. **技术标签体系缺失**：Recipe Card 中的字段标签（Subject、Style 等）与其他文字混排，缺乏专业工具感

**本期目标**

用户从 Landing Page 进入 Workspace 的过程中，通过视觉一致性感受到"这是一款经过设计的产品"，在上传参考图前就建立对产品专业度的信任。

### 1.2 核心问题定义

| 问题 | 影响 |
|------|------|
| 视觉无品牌识别度 | 用户无法将 Visoryn 与"专业视觉工具"建立关联，首因效应差 |
| Hero 区缺少转化引导 | 用户到达首页后无法快速判断"我要不要试试"，跳出率高 |
| 功能区缺乏视觉记忆 | 功能描述文字用户记不住，没有视觉锚点强化产品能力认知 |
| Workspace 专业感不足 | 用户在核心工作区感受到的是"凑合能用的工具"而非"专业创作台" |

**如果不做，用户会怎样**

- Landing Page 跳出率维持高位，流量无法有效转化为注册用户
- 用户将 Visoryn 归类为"又一个 AI 图片工具"，无法形成品牌溢价
- 竞品（MIDJOURNEY、STABLE DIFFUSION）以更强品牌力持续吸走目标用户

**如果做，我们能获得什么**

- 品牌认同带来的用户留存提升（用户因为"这产品看起来专业"而持续使用）
- 视觉信任带来的付费转化提升（专业感降低用户付费决策摩擦）
- 设计资产积累，为后续功能扩展提供一致的品牌基础

### 1.3 竞品分析

#### 1.3.1 市场格局

| 类型 | 竞品 | 视觉风格 | 品牌定位 |
|------|------|---------|---------|
| 专业 AI 图像工具 | Midjourney | 暗色调 + 高对比 | 艺术创作、精英感 |
| 专业 AI 图像工具 | Stable Diffusion WebUI | 工具感强、功能堆砌 | 极客、技术流 |
| 设计参考工具 | Muzli / Behance | 浅色、画廊感 | 设计师社区 |
| 风格迁移工具 | Leonardo.ai | 暗紫色 + 霓虹 | 创作者友好 |
| **参考设计** | Stitch Obsidian Core | 纯暗灰 + 极简边界 | 精密工具感 |

#### 1.3.2 重点竞品对比

| 维度 | Midjourney | Leonardo.ai | Visoryn（当前） |
|------|-----------|-------------|----------------|
| Landing Hero | 强视觉冲击、Prompt 展示 | 功能截图、色彩丰富 | 纯文字、无视觉锚点 |
| 品牌色 | 紫色系、高饱和 | 青色/紫色渐变 | 蓝紫色、偏暗 |
| 功能区展示 | 社区作品轮播 | 功能标签 + 参数面板 | 文字列表 |
| 信任建立 | 展示生成效果 | 展示生成效果 | 无信任建立元素 |
| 与本产品关系 | 视觉标杆 | 色彩参考 | 定位类似，但当前差距大 |

#### 1.3.3 竞品分析结论

**已被验证的实践**

- 暗色调 + 冷光主色（紫/青）是专业视觉工具的共识选择，Visoryn 保留蓝紫色调方向正确
- Hero 区必须有强视觉锚点（图片/截图/动态演示），纯文字无法建立第一秒信任
- 功能区用视觉装饰（图标、色块、标签）强化记忆，比纯文字描述更有效

**本产品差异化方向**

不追求 Midjourney 的"艺术感"，而是聚焦 Leonardo.ai 和 Stitch 的"精密工具感"——让用户感受到这是一个经过工程化设计的专业系统，而非"AI 生成代码随手搭的界面"。

### 1.4 方案比较与取舍

#### 决策维度一：Landing Page Hero 视觉风格

| 方案 | 优点 | 缺点 | 判断 |
|------|------|------|------|
| 全屏背景视频/动图 | 视觉冲击最强、第一印象深 | 加载慢、维护成本高、可能喧宾夺主 | 不选：性能代价大 |
| 静态产品截图 + 渐变叠加 | 直观展示产品、建立正确预期 | 需要先有可展示的截图 | 暂缓：作为 P2 |
| Radial Gradient + 卡片式截图 | 轻量、不干扰内容、品牌氛围强 | 需要精心设计 gradient 参数 | **选用**：Stitch 验证过的方案 |

#### 决策维度二：功能卡片底部装饰形式

| 方案 | 优点 | 缺点 | 判断 |
|------|------|------|------|
| 无装饰、纯文字 | 最简单 | 与当前无差异，无记忆点 | 不选 |
| AI 生成图展示 | 最直观展示能力 | 需要准备素材、有版权风险 | 暂缓 |
| 技术标签组 + 色块网格 | 符合精密工具定位、与品牌调性一致 | 需要设计标签内容 | **选用**：与 Stitch 设计语言统一 |

#### 决策维度三：导航栏固定方式

| 方案 | 优点 | 缺点 | 判断 |
|------|------|------|------|
| 固定顶部（absolute） | 始终可见、Stitch 风格 | 可能遮挡内容 | 不选：内容区需要留 padding |
| Sticky + 玻璃态 | 滚动时保护、内容不被遮挡 | 实现稍复杂 | **选用**：backdrop-blur 效果现代感强 |

**关键决策汇总**

1. **保留 Luminescent Darkroom 配色体系**：蓝紫色调是品牌差异化基础，不跟随 Stitch 的纯灰方案
2. **采用 Stitch 的布局模式和交互模式**：间距、圆角、边框透明度等技术细节采用 Stitch 规范
3. **品牌化 Hero 区**：Gradient 背景 + 徽章标签 + 双 CTA + 展示图区域
4. **技术标签体系**：统一 Mono 字体 + uppercase + tracking-widest 的专业标签风格

### 1.5 产品范围

**本期必须交付（P0）**

- Landing Page Hero 重构：Gradient 背景、徽章标签、强调色关键词、双 CTA 按钮
- 功能卡片视觉增强：卡片间距增大、底部装饰区域、hover 效果
- 技术标签样式统一：Recipe Card 和 Generate Panel 的所有字段标签
- Ghost Border 应用：全站边框透明度统一调整为 10%-15%

**建议尽快补充（P1）**

- 数据统计区域重构：左右布局（文案 + 数据卡片）
- 底部 CTA 区域重构：深底浅字反转按钮
- 导航栏增强：添加功能链接和 Material Symbols 图标按钮
- Aspect Ratio 可视化选择器

**后续扩展（P2）**

- Hero 展示图区域（需产品截图素材）
- Landing Page Footer 组件
- Workspace 固定底部 Footer
- 卡片 hover 缩放动画
- 进度条脉冲动画

**明确不做**

- 侧边栏导航（当前产品功能单一，空侧边栏降低有效内容面积）
- 全站重新配色（保留现有 Luminescent Darkroom 体系）
- 响应式布局大幅调整（仅做必要适配，不做移动端优先重构）

## 2. 用户旅程和用户故事

> 视角：用户同理心

### 2.1 核心用户类型

**类型一：独立创作者**
- **诉求**：快速将脑海中的视觉风格落地，不需要懂 Prompt 工程
- **典型场景**：插画师想保持自己作品集的风格一致性

**类型二：设计师/艺术家**
- **诉求**：提取参考图的视觉参数，用于团队协作或资产库建设
- **典型场景**：设计团队需要建立视觉风格指南

**类型三：AI 爱好者**
- **诉求**：探索不同视觉风格的 AI 生成可能性
- **典型场景**：玩 Midjourney 的用户想试试其他工具

**类型四：新用户（首次访问）**
- **诉求**：快速判断"这个产品值不值得我花时间注册"
- **典型场景**：从社交媒体/搜索引擎引流来的用户，注意力只有几秒

### 2.2 核心用户旅程

```
[新用户到达 Landing Page]
        ↓
    第1秒：品牌感知
    眼睛扫过导航栏和 Hero 区
    问自己："这是什么？" 或 "这能帮我做什么？"
        ↓
    第3秒：价值确认
    Hero 标题 + 副标题传达核心价值
    问自己："我想要这个"
        ↓
    第5秒：行动冲动
    看到 CTA 按钮
    问自己："我该怎么开始？"
        ↓
    [点击"开始创作"]
        ↓
    [跳转至 Workspace 或 登录页]
        ↓
    [上传参考图]
        ↓
    [查看 AI 分析结果]
        ↓
    [编辑 Prompt]
        ↓
    [生成新图]
        ↓
    [下载结果 / 重新生成]
```

**次旅程：用户跳过 Landing 直接进入 Workspace**

```
[用户从收藏夹/直接链接进入 Workspace]
        ↓
    看到空状态的 Workspace
    "上传参考图开始创作" 提示
        ↓
    [直接进入核心链路]
```

**次旅程：用户离开后重新回来**

```
[用户通过邮件/社交媒体再次访问]
        ↓
    视觉记忆唤醒
    "我记得这个工具" → 直接进入 Workspace
```

### 2.3 异常与边界矩阵

| 场景 | 触发条件 | 系统处理 | 用户可继续动作 |
|------|---------|---------|--------------|
| 上传了非图片文件 | 用户拖拽/选择非图片 | 显示错误提示："请上传 JPG、PNG 或 WebP 格式图片，最大 10MB"，不清空当前状态 | 选择正确格式重新上传 |
| 上传超过 10MB 的图片 | 文件体积超过限制 | 显示错误提示，文件不进入上传队列 | 压缩后重新上传 |
| 分析失败 | AI 视觉分析返回错误 | 显示错误卡片，包含"重试"按钮；参考图保留在上传区 | 点击重试或更换参考图 |
| 生成失败 | fal.ai 生成失败 | 显示错误卡片，包含"重试"按钮；Prompt 保留在编辑器 | 点击重试 |
| 网络中断（分析/生成中） | 客户端网络断开 | 显示"网络连接中断，正在等待恢复"；任务状态保持；恢复后自动继续 | 等待恢复或刷新页面 |
| 生成结果不符合预期 | 用户看到生成的图不满意 | Prompt 编辑器保留上次输入 | 修改 Prompt 重新生成 |

**状态恢复原则**

1. 用户上传的参考图在分析失败后保留，用户可重试无需重新上传
2. 分析和生成过程中的 Prompt 在失败后保留，用户可修改重试
3. 任何失败状态都提供明确的"重试"操作，不让用户陷入空白
4. 网络中断时系统保持当前状态，恢复后自动继续，不丢失用户已完成的工作
5. 页面刷新后，如果存在未完成的分析/生成任务，显示进度而非空白状态

### 2.4 用户故事

**P0 用户故事（核心链路）**

- 作为**新用户**，我希望**在 Landing Page 第一屏快速理解产品价值**，以便**判断是否值得注册使用**
- 作为**新用户**，我希望**一键开始创作**，以便**尽快体验产品核心能力而不是研究如何使用**
- 作为**创作者**，我希望**上传参考图后看到专业的分析结果展示**，以便**相信这个工具真的理解了我的图**
- 作为**创作者**，我希望**在生成结果区有明确的下载和重新生成选项**，以便**高效完成工作流不中断**

**P1 用户故事（体验增强）**

- 作为**设计师**，我希望**功能卡片有视觉装饰和标签**，以便**快速扫描产品能力而不必逐字阅读**
- 作为**设计师**，我希望**Recipe Card 的字段标签是专业的技术样式**，以便**感受到这是一个精密工具而非玩具**
- 作为**AI 爱好者**，我希望**数据统计区有具体数字**，以便**在试用前建立对产品能力的信任**
- 作为**返回用户**，我希望**Workspace 有统一的页面头部和操作区**，以便**快速找到重置/保存等操作**

**P2 用户故事（锦上添花）**

- 作为**新用户**，我希望**Hero 区有产品截图或动态展示**，以便**更直观地了解产品界面**
- 作为**创作者**，我希望**生成过程中有动画进度指示**，以便**知道系统还在工作而不是卡死了**
- 作为**专业用户**，我希望**底部有 Footer 显示版权和链接**，以便**找到文档和支持渠道**

## 3. UX/UE 设计

> 视角：设计师

### 3.1 设计目标

1. **品牌识别**：用户在看到界面的第一秒就能识别 Visoryn，区别于其他 AI 工具
2. **专业信任**：视觉细节（技术标签、Mono 字体、Ghost Border）传达"精密工具"而非"玩具"
3. **清晰引导**：每个页面的视觉重心和用户注意力流动路径清晰可见
4. **流畅体验**：核心链路每一步的视觉状态让用户始终知道"我在哪、下一步是什么"

**设计原则**

- **克制但不简陋**：视觉元素服务于信息传达，不添加无意义的装饰
- **一致性优先**：全站统一的设计语言（Luminescent Darkroom + Stitch 技术细节），每个改动都与现有体系兼容
- **状态可预期**：加载、等待、成功、失败、错误——每种状态都有明确的视觉表达

### 3.4 业务规则

**输入规则**

- 参考图支持 JPG、PNG、WebP 格式，单文件最大 10MB
- 参考图上传后显示预览缩略图，用户可随时替换
- Prompt 文本框支持手动编辑，最大 2000 字符
- Aspect Ratio 选择默认 1:1，用户可切换为 16:9 或 9:16
- Quality 选项默认"高清"，用户可切换为"标准"

**状态流转规则**

- 上传参考图后自动触发分析，无需额外确认操作
- 分析完成后 Prompt Editor 自动获得焦点，用户可直接编辑
- 点击"生成图片"后，Prompt Editor 和生成按钮临时禁用，防止重复提交
- 生成完成后自动展示结果图，并显示"下载"和"生成新图"操作选项

**数据关联规则**

- 每张参考图对应唯一的 Analysis Task 和 Visual Recipe
- 每个 Visual Recipe 包含多个可编辑字段（Subject、Style、Lighting、Composition 等）
- 每个 Generation Task 引用一个 Visual Recipe 和对应的 Prompt
- Recipe Card 字段值变更后，Prompt Editor 内容同步更新

**视觉规则**

- Ghost Border 透明度：默认 15%，强调时 20%，微妙时 10%
- 技术标签样式：text-[10px] font-bold uppercase tracking-widest font-mono
- 卡片 hover 效果：border-primary/30，持续 300ms ease
- 导航栏背景：bg-base/80 backdrop-blur-xl，固定在顶部

## 4. 数据指标与验收标准

> 视角：数据分析师

### 4.1 核心验收指标

| 指标 | 定义 | 目标 |
|------|------|------|
| Hero CTA 点击率 | 点击"开始创作"按钮的用户数 / Landing Page 独立访客数 | 上线后 30 天内从基准值提升 ≥15% |
| 注册转化率 | 完成注册的用户数 / 点击 CTA 的用户数 | ≥60%（需登录的用户中） |
| Workspace 进入率 | 进入 Workspace 页面的用户数 / 注册用户数 | ≥75% 的新注册用户在首周进入 Workspace |
| 核心链路完成率 | 完成"上传→分析→生成"全链路的用户数 / 进入 Workspace 的用户数 | ≥50% |

### 4.2 过程观察指标

| 指标 | 定义 | 观察目的 |
|------|------|---------|
| Hero 区域停留时间 | 用户在 Hero 区域的平均停留时长（秒） | 判断价值主张是否快速传达 |
| 功能卡片悬停率 | 悬停在功能卡片上的用户数 / 总访客数 | 判断视觉装饰是否引起注意 |
| Prompt 编辑率 | 对 Prompt 进行过手动编辑的用户数 / 分析完成用户数 | 判断自动生成 Prompt 的可用性 |
| 重复生成率 | 重新生成超过 2 次的用户比例 | 判断生成质量是否满足预期 |

### 4.3 通过标准

基于核心验收指标，本期改造通过需满足以下所有条件：

1. **Hero CTA 点击率**：上线 30 天后，Hero CTA 点击率较改造前提升 ≥15%
2. **类型检查通过**：`pnpm type-check` 无类型错误
3. **代码规范通过**：`pnpm lint` 无新增 error（warning 数量不超过改造前基准）
4. **单元测试通过**：`pnpm test` 全部通过，现有测试覆盖的功能未出现回归
5. **手动验收完成**：Landing Page 和 Workspace 的所有关键路径在浏览器中验证正常

### 4.4 暂停放量条件

如出现以下任一情况，暂停放量并进行修复：

1. **功能链路阻断**：上传参考图后无法完成分析，或分析后无法生成图片，阻断核心链路
2. **严重视觉问题**：关键区域（Hero、功能卡片、Recipe Card）在主流分辨率（1920x1080、1366x768）下出现布局错乱
3. **性能回退**：页面 Lighthouse Performance 评分低于改造前基准 10 分以上
4. **测试回归失败**：测试通过率低于 95%（现有测试出现大范围失败）

## 5. 风险与兜底方案

> 视角：风险管理者

### 5.1 风险清单

| 风险类别 | 具体风险 | 影响 |
|---------|---------|------|
| 用户理解 | 新用户看到改造后的 Hero，无法快速理解产品是什么 | Landing Page 跳出率上升 |
| 用户理解 | 功能卡片的视觉装饰被误认为是产品截图，用户期望与实际不符 | 用户进入 Workspace 后感到被骗 |
| 体验 | 改造后 Hero Gradient 在低对比度屏幕上显示不清 | 文字可读性下降 |
| 体验 | Ghost Border 透明度 15% 在某些屏幕上看不见边框（设计失效） | 容器边界感消失 |
| 体验 | 技术标签样式（mono + uppercase）在小屏幕上溢出 | 布局错乱 |
| 技术 | 改造涉及 20+ 个组件文件，修改范围大导致回归风险高 | 现有功能出现 bug |
| 技术 | Tailwind CSS 4 配置改动影响全局样式 | 样式冲突或覆盖 |
| 数据 | 无数据风险（纯前端视觉改造，不涉及数据层） | — |
| 合规 | 无新增合规风险（不涉及用户数据采集变更） | — |
| 安全 | 无新增安全风险（纯样式和布局调整） | — |

### 5.2 降级策略

| 场景 | 降级时的系统行为 | 用户可继续的动作 |
|------|----------------|---------------|
| Hero Gradient 在低对比度屏幕显示异常 | CSS 自动降级为纯 bg-base 背景，Gradient 特效隐藏 | 访问 Landing Page 和使用全部功能，不受影响 |
| Ghost Border 完全不可见 | 边框自动恢复为不透明状态（opacity-30），设计细节丢失但功能正常 | 所有操作正常进行 |
| 技术标签在小屏溢出 | 标签文字自动换行，tracking-widest 降级为 tracking-wide | 正常阅读标签内容 |

### 5.3 回滚方案

如改造上线后出现严重问题，可通过以下方式快速回滚：

1. **Git 回滚**：`git revert [commit-hash]` 撤销全部视觉改造代码，预计耗时 5 分钟
2. **分支隔离**：如问题仅影响部分组件，可选择性回滚 `src/components/landing/` 或 `src/components/workspace/` 目录
3. **CSS 回滚**：`src/app/globals.css` 的改动可独立回滚，不影响组件逻辑
4. **部署暂停**：如需进一步诊断，可暂停 CI/CD 流水线部署，防止问题扩散

### 5.4 合规底线

1. **不可降低可访问性**：改造后的颜色对比度必须满足 WCAG AA 标准（4.5:1 文本对比），不得因追求"暗色美学"而牺牲可读性
2. **不可添加未经用户同意的追踪**：视觉改造不涉及新的用户行为数据采集
3. **不可破坏已有功能**：任何组件的改造不得移除或禁用已有功能
4. **不可添加外部依赖**：视觉改造不引入新的 npm 包依赖
5. **不可修改数据模型**：样式改造不影响 `VisualRecipe`、`AnalysisTask`、`GenerationTask` 的数据结构和 API 契约

## 6. 结论与决策记录

> 视角：决策者

### 6.1 推进结论

**结论：建议推进**

**推进理由**

1. **品牌建设窗口期**：当前产品功能完整但视觉空白，是建立品牌认知的最佳时机。竞品 Leonardo.ai 已通过视觉体系建立了一定的品牌壁垒，晚做不如早做
2. **ROI 可控**：纯前端视觉改造，不涉及后端、数据迁移或基础设施变更，风险边界清晰
3. **竞品验证的设计方向**：Stitch Obsidian Core 设计体系经过市场验证（精密工具感 + Ghost Border + 技术标签），不是闭门造车
4. **渐进式改造策略**：P0/P1/P2 分批交付，第一批改造（小改）上线后可快速验证效果，不满意可及时调整

**首版定位**

将 Visoryn 从"功能性暗色调界面"升级为"具有 Luminescent Darkroom 美学认同的专业视觉创作工具"，首版聚焦 Landing Page Hero 重构和核心组件（P0）的技术标签样式统一。

### 6.2 进入下一阶段的前置条件

1. **设计资产就绪**：技术标签样式定义、Mono 字体配置、Ghost Border 的 CSS 变量已在 globals.css 中定义完毕
2. **参考设计确认**：Stitch Obsidian Core 的布局模式和 Luminescent Darkroom 配色体系的融合方案已通过设计评审
3. **组件清单确认**：所有涉及改造的组件已清点完毕，且每个组件的改造优先级（P0/P1/P2）已与开发团队对齐
4. **测试基线建立**：现有测试通过率已记录，确保改造后不出现回归
5. **灰度策略确定**：如采用渐进式发布，灰度比例和观察周期已确定
