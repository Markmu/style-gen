# 03-1 架构文档：视觉设计改造

> **前置文档**：[03-0 需求设计：视觉设计改造](docs/03-0-需求设计-视觉设计改造.md)
> **模式**：精简默认（MVP/V1）

---

## 1. 系统摘要

Visoryn 视觉品牌升级项目，通过 Luminescent Darkroom 配色体系 + Stitch Obsidian Core 布局规范，对 Landing Page 和 Workspace 进行全栈视觉改造，强化"精密专业工具"品牌认知。

**核心闭环**：Design Tokens → 组件样式 → 页面视觉 → 品牌感知

**边界**：纯前端样式改造，不涉及后端逻辑、数据模型或 API 契约变更。

## 2. 范围、非目标与成功标准

### 2.1 本期范围（P0 + P1）

**P0（必须交付）**
- Landing Page Hero 重构：Radial Gradient 背景、徽章标签、双 CTA
- 功能卡片视觉增强：底部装饰区、hover 效果
- 技术标签样式统一：Recipe Card 和 Generate Panel 字段标签
- Ghost Border 全站统一：边框透明度统一调整为 10%-15%（默认 15%，强调时 20%，微妙时 10%），参见 §7.1 token 定义

**P1（快速补充）**
- 数据统计区重构：左右布局（文案 + 数据卡）
- 底部 CTA 区域：深底浅字反转按钮
- 导航栏增强：功能链接 + Material Symbols 图标

### 2.2 非目标

- 不引入侧边栏导航（产品功能单一，空侧边栏降低有效内容面积）
- 不重新设计全站配色（Luminescent Darkroom 体系保留）
- 不做移动端优先的响应式重构（仅做必要适配）
- 不引入新的 npm 依赖包
- 不修改 `VisualRecipe`、`AnalysisTask`、`GenerationTask` 数据结构

### 2.3 成功标准

| 类型检查 | `pnpm type-check` 无错误 |
| 代码规范 | `pnpm lint` 无新增 error |
| 单元测试 | `pnpm test` 全部通过，无回归 |
| 可访问性 | WCAG AA（文本对比度 4.5:1） |

## 3. 关键架构决策（ADR）

### ADR-1：设计令牌作为样式唯一真实源
- **选择**：所有视觉改造的设计令牌（颜色、字体、间距、圆角）集中定义在 `src/app/globals.css` 的 CSS 变量中，组件通过引用 token 而非硬编码值实现样式复用
- **理由**：Tailwind CSS 4 的 `@theme` 指令支持 CSS 变量驱动，组件使用 `bg-[var(--surface-low)]` 或直接使用 Tailwind 的语义化类名，确保设计体系一致性；避免分散在各组件中的硬编码值导致改一处漏多处
- **演进余地**：后续可提取为独立 `tokens.css` 供 design system 包使用

### ADR-2：Ghost Border 统一为 CSS 变量驱动的 border 透明度
- **选择**：全站边框使用 `border-[var(--border)]` 配合不同透明度（默认 /15，强调时 /20，微妙时 /10），不再使用 `border-slate-800` 等具体颜色值
- **理由**：PRD 明确要求 Ghost Border 透明度统一，CSS 变量比每次手写 opacity 值更可控；Tailwind 的任意值语法 `border-color/opacity` 支持 `/{ratio}` 写法；与 PRD §3.4 视觉规则保持一致（默认 15%，强调时 20%，微妙时 10%）；token 定义见 §7.1
- **演进余地**：未来可通过 CSS 变量覆盖实现主题切换

### ADR-3：技术标签样式作为 `.label-tech` 工具类
- **选择**：在 `globals.css` 中定义 `.label-tech` 工具类（`text-[10px] font-bold uppercase tracking-widest font-mono`），所有 Recipe Card 和 Generate Panel 的字段标签复用此类
- **理由**：PRD 要求统一 Mono 字体 + uppercase + tracking-widest 的专业标签风格，集中定义避免散落在各组件中重复；Tailwind 的 `@apply` 或直接写 arbitrary values 均可行，工具类更语义化
- **演进余地**：后续可扩展为 `[data-variant="tech"]` 等变体体系

### ADR-4：Hero Radial Gradient 使用 Tailwind arbitrary value + CSS 变量
- **选择**：Hero 背景使用 `bg-[radial-gradient(ellipse_at_top,_var(--gradient-primary)_0%,_var(--bg-base)_70%)]` 写法，gradient 参数通过 CSS 变量配置
- **理由**：Tailwind arbitrary value 支持内联 gradient 语法；CSS 变量让 gradient 参数可配置，方便后续微调；比在 JS 中计算样式更简洁
- **演进余地**：未来可扩展为多段 gradient 或动画 gradient

### ADR-5：组件改造采用增量修改而非重写
- **选择**：对现有组件（`hero.tsx`、`value-section.tsx` 等）进行增量样式修改，不整体重写
- **理由**：改造涉及 20+ 组件文件，完整重写回归风险高；增量修改保留现有逻辑，只调整 JSX className
- **演进余地**：P2 阶段若组件复杂度上升，可评估拆分或重写

### ADR-6：仅使用现有 npm 依赖完成全部视觉改造
- **选择**：不引入新的 UI 库、动画库或 icon 库；使用 `@tabler/icons-react`（已配置）或内联 SVG 实现图标需求
- **理由**：PRD 合规底线明确"不添加外部依赖"；现有 `@tabler/icons-react` 覆盖所有图标场景；内联 SVG 零依赖且 bundle size 可控
- **演进余地**：若未来图标需求超出覆盖范围，评估替代方案

## 4. 用户流程与状态

### 4.1 用户主流程

```
[新用户到达 Landing Page]
  → 第 1 秒：品牌感知（Hero 区域 radial-gradient + 徽章建立第一印象）
  → 第 3 秒：价值确认（标题 + 副标题传达核心价值）
  → 第 5 秒：行动冲动（双 CTA 按钮引导）
  → [点击"开始创作"] → 跳转 Workspace
  → [上传参考图] → 自动分析
  → [查看 Recipe Card（技术标签样式）] → 信任感建立
  → [编辑 Prompt]
  → [生成图片]
  → [下载结果 / 重新生成]
```

### 4.2 关键状态

| 页面 | 状态 | 视觉表现 |
|------|------|---------|
| Landing | 初始加载 | Hero + 功能区 + 统计区 + CTA 完整展示 |
| Landing | 导航悬停 | 链接文字 secondary → primary |
| Landing | 功能卡片悬停 | border → primary/30（300ms ease） |
| Workspace | 空状态 | 上传区占主体，Recipe Card 显示空状态提示 |
| Workspace | 分析进行中 | 上传区进度动画 + 等待文案 |
| Workspace | 分析完成 | Recipe Card 展示字段（技术标签 + 数据） |
| Workspace | 分析失败 | 上传区错误提示 + 重试按钮 |
| Workspace | 生成进行中 | 生成面板进度条动画 |
| Workspace | 生成完成 | 结果图展示 + 下载/重新生成按钮 |
| Workspace | 生成失败 | 生成面板错误提示 + 重试按钮 |

### 4.3 状态恢复原则

1. 参考图在分析失败后保留，用户可重试无需重新上传
2. Prompt 在失败后保留，用户可修改重试
3. 任何失败状态都提供明确的"重试"操作
4. 网络中断时系统保持状态，恢复后自动继续——此为上游 TanStack Query polling 机制已有能力，本期样式改造不涉及

## 5. 系统上下文与模块职责

### 5.1 模块职责

| 模块 | 职责 | 上游输入 | 下游输出 |
|------|------|---------|---------|
| `globals.css` | 全站设计令牌（颜色、字体、边框、gradient、.label-tech） | PRD 设计令牌定义 | 被所有组件引用 |
| `hero.tsx` | Landing Hero 区域：radial-gradient 背景、徽章、双 CTA | globals.css token | JSX + Tailwind className |
| `value-section.tsx` | 功能卡片网格：底部装饰区、hover 效果 | globals.css token | JSX + Tailwind className |
| `stats-section.tsx`（新建或改造） | 数据统计区：左右布局（文案 + 数据卡） | globals.css token | JSX + Tailwind className |
| `bottom-cta.tsx`（新建） | 底部 CTA：深底浅字反转按钮 | globals.css token | JSX + Tailwind className |
| `footer.tsx`（新建） | Footer 组件：版权和链接 | globals.css token | JSX + Tailwind className |
| `auth-header.tsx` | 导航栏：sticky + backdrop-blur + 功能链接 + 图标 | globals.css token | JSX + Tailwind className |
| `recipe-card.tsx` | Recipe Card：技术标签样式（.label-tech）、字段图标 | globals.css token + 数据 | JSX + Tailwind className |
| `generate-panel.tsx` | 生成面板：Aspect Ratio 可视化、生成按钮 | globals.css token + 用户输入 | JSX + Tailwind className |
| `upload-zone.tsx` | 上传区：宽屏比例、hover 边框效果 | globals.css token | JSX + Tailwind className |

### 5.2 数据流（不变）

```
参考图上传 → API presign → R2 存储
  → Analysis Task 创建 → Gemini 视觉分析
  → Visual Recipe 结构化 → Recipe Card 展示
  → Prompt 编辑 → Generation Task 创建
  → fal.ai 生成 → 结果图展示
```

**关键约束**：视觉改造不影响以上任意数据流和 API 契约。

### 5.3 刻意避免的过度设计

- 不引入 CSS-in-JS 方案（现有 Tailwind CSS 4 满足需求）
- 不建立独立 design system 包（本期只需 tokens + globals.css）
- 不做组件库的抽象层（直接修改现有组件，避免过度分层）
- 不做主题切换功能（单 Luminescent Darkroom 主题）
- 不做组件级别的 storybook 文档（本期范围外）

## 6. 运行链路

### 6.1 主链路：视觉改造部署

1. **开发环境**：开发者在本地 `src/app/globals.css` 中更新设计令牌，组件同步引用
2. **构建验证**：`pnpm build` 验证样式正确性和 bundle size
3. **类型检查**：`pnpm type-check` 确保无类型错误
4. **测试验证**：`pnpm test` 确保无回归
5. **手动验收**：浏览器验证 Landing Page 和 Workspace 关键路径
6. **灰度/全量发布**：通过 CI/CD 流水线部署至 Vercel

**实现原则**：样式变更通过 Tailwind 类名实现，className 变更通过组件文件修改实现，两者均通过 Git 管理版本。

### 6.2 主链路：用户首次访问（视觉体验路径）

1. 用户访问 Landing Page，浏览器加载 `globals.css`（包含 design tokens）
2. Hero 区域应用 radial-gradient 背景，建立品牌第一印象
3. 用户浏览功能卡片，感受 hover 效果和底部装饰区
4. 用户点击 CTA，跳转 Workspace
5. Workspace 的 Recipe Card 以技术标签样式展示分析结果，建立专业工具认知
6. 用户完成"上传→分析→生成"全链路

## 7. 领域对象与关键契约

### 7.1 设计令牌（Design Tokens）

```typescript
// src/app/globals.css 中定义
// 页面背景
--surface-base: #060e20;
--surface-low: #091328;
--surface-mid: #0f1930;
--surface-bright: #1f2b49;

// 主色和次色（品牌色）
--accent-primary: #ba9eff;
--accent-secondary: #53ddfc;

// 文本色
--text-primary: #dee5ff;
--text-secondary: #8b9cc8;

// Ghost Border（透明度通过 border/{ratio} 调整，参见 ADR-2）
--border: #40485d; // 默认 15%（border-[var(--border)]/15）
// 微妙时 10%：border-[var(--border)]/10，强调时 20%：border-[var(--border)]/20

// 技术标签
.label-tech {
  font-size: 10px;
  font-weight: 700;
  text-transform: uppercase;
  letter-spacing: 0.2em; /* tracking-widest */
  font-family: ui-monospace, monospace;
}

// Hero Gradient
--gradient-primary: rgba(186, 158, 255, 0.15); // brand purple, rgba format for gradient
```

### 7.2 术语映射规则

| 旧术语 | 新术语 | 使用位置 |
|--------|--------|---------|
| border-slate-700 等硬编码色 | `border-[var(--border)]/{ratio}` | 全站组件 |
| 普通文本标签 | `.label-tech` 工具类 | Recipe Card、Generate Panel |
| 无 Hero 背景 | radial-gradient（CSS 变量） | hero.tsx |
| 纯文字 CTA | 双 CTA + 反转色 | hero.tsx、bottom-cta.tsx |

### 7.3 状态枚举（不变，仅作参考）

```
Analysis Task: pending → processing → completed | failed
Generation Task: pending → processing → completed | failed
```

以上状态枚举和数据模型在本期视觉改造中**不变更**。

## 8. 非功能需求、风险与运行策略

### 8.1 性能预期

| 指标 | 目标 |
|------|------|
| Lighthouse Performance | 不低于改造前基准 10 分 |
| Bundle Size | 不因样式改造增加超过 5KB（gzipped） |
| First Contentful Paint | 不增加超过 200ms |

**实现原则**：样式改造通过 Tailwind CSS 4 的 JIT 模式实现，只打包实际使用的类名；新增 `.label-tech` 工具类为单一 CSS 规则，体积可忽略。

### 8.2 回归风险缓解

| 风险 | 缓解措施 |
|------|---------|
| 20+ 组件修改范围大导致回归 | 每个改造组件单独提交（commit），便于针对性回滚 |
| Tailwind CSS 4 配置改动影响全局 | `globals.css` 改动与组件改动分开 review |
| 现有测试出现大范围失败 | 改造前记录测试基线，改造后 `pnpm test` 必须全部通过 |

### 8.3 降级策略

| 场景 | 系统行为 | 用户影响 |
|------|---------|---------|
| Hero Gradient 低对比度屏幕异常 | CSS 自动降级为纯 `bg-surface-base` | 无感知，正常使用 |
| Ghost Border 不可见 | 边框自动恢复为 `opacity-30` 不透明 | 功能正常，细节丢失 |
| 技术标签小屏溢出 | 文字自动换行，`tracking-widest` 降级为 `tracking-wide` | 可读，内容正常 |

### 8.4 回滚方案

1. **Git 回滚**：`git revert [commit-hash]` 撤销全部视觉改造，预计耗时 5 分钟
2. **文件级回滚**：可选择性回滚 `src/components/landing/` 或 `src/components/workspace/` 目录
3. **CSS 独立回滚**：`globals.css` 改动可单独回滚，不影响组件逻辑
4. **部署暂停**：CI/CD 流水线可暂停，防止问题扩散

### 8.5 合规底线

1. **可访问性**：所有文本对比度满足 WCAG AA（4.5:1），暗色美学不牺牲可读性
2. **无新追踪**：视觉改造不引入新的用户行为数据采集
3. **功能完整**：任何组件改造不得移除或禁用已有功能
4. **无新依赖**：不引入新的 npm 包
5. **数据模型不变更**：样式改造不影响 `VisualRecipe`、`AnalysisTask`、`GenerationTask` 的数据结构和 API 契约

## 10. 架构结论

**视觉设计改造是纯前端样式工程，不涉及架构层面的本质变更。**

本期架构核心决策：
1. **设计令牌集中管理**：所有视觉常量收敛在 `globals.css`，组件零硬编码
2. **增量改造优先**：不重写组件，只修改 Tailwind 类名，回归风险可控
3. **ADR 覆盖设计细节**：Ghost Border、技术标签、Hero Gradient、依赖管控——5 条 ADR 锁定关键实现选择
4. **降级与回滚完备**：CSS 降级链 + Git 回滚策略，确保问题可快速恢复

**架构稳定性评估**：本期改造对现有系统架构无侵入，部署后对用户和后端系统零影响，可安全推进。
